## 基础服务端：监听、接收请求、记录日志

双击 **`启动基础服务端.command`**，或执行 `python3 game_server.py --probe`，即可独立启动基础接收端，无需先启动模拟器。默认监听 `127.0.0.1:18770`；终端显示连接和请求，日志保存到 `.runtime/server/sessions/`。支持 HTTP 健康检查、服务器列表响应、TLS/TCP 到达记录，以及连接编号、关闭原因和读写字节统计。按 Ctrl+C 停止。

要接入原游戏客户端，使用下面的本地重定向启动器，它已经包含同一个接收端。两种启动方式共用默认端口，不要同时启动；需要并行检查时，独立服务可运行 `python3 game_server.py --port 18771 --probe`。完整使用、curl 验证和日志说明见 [基础服务端](docs/基础服务端.md)。

## 启动与停止

遇到 `get access failed`、登录页卡住或后台反复 `timeout was reached` 时，双击 **`自动修复登录.command`**（等价于 `python3 start_game.py --repair`）。它会停止旧游戏进程和登录服务，清理失效的项目专用 Frida 注入，重建本地连接并执行 DNS、Java／native HTTPS 自检；不会卸载游戏或清空存档。看到“本地服务已就绪”后连接画面，点击“进入游戏”。这是手动触发的一键自动修复，不是后台持续自愈。

2026-10-24 再次排查确认：Android Zygote 重启后旧 Frida 进程仍存在，但新游戏进程注入持续超时；`redirect_game.py status` 的 `running: true` 只表示控制进程存活，不能证明登录可用。新增修复入口已在该故障现场通过自检及 LS→BS 登录，进入“本地行者”主界面，15 项启动／修复测试通过。Android 系统重启的底层原因尚未完全定位，不能保证故障不再发生。若一键修复失败，保留终端错误和 `.runtime/redirect/controller.log`，再用 `停止游戏.command`、`自动修复登录.command` 完整重启环境；不要删除 `.runtime/avd/` 或 `.runtime/offline/`。

双击 `启动游戏.command`（与 `启动本地离线游戏.command` 使用相同流程）。脚本会启动本目录的独立模拟器，等待 Android 启动，首次安装游戏，启动本地登录服务并完成连接自检，随后打开 <http://127.0.0.1:8768>。在网页中连接画面，再点击游戏内“进入游戏”。首次冷启动和安装可能需要几分钟，请保留终端窗口等待完成。

双击 `停止游戏.command` 关闭本项目的模拟器和网页服务。关闭浏览器不会停止模拟器。后续启动保留应用数据，不重复安装。

也可以在本目录运行：

```sh
python3 start_game.py
# 仅调试原客户端、不启动本地登录服务
python3 start_game.py --client-only
python3 android_emulator/run.py --config game.json doctor
python3 android_emulator/run.py --config game.json stop
```
