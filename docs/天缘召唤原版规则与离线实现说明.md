# 天缘召唤原版规则与离线实现说明

更新日期：2026-10-26。离线配置版本：`offline-convert-1`。

【A】表示3.87原包客户端字节码、界面图片或CSV能够直接证明的规则；【B】表示缺失官方服务端代码、配置或结算日志后采用的本地推测。原表中存在的数值不等于已取得官方服务端算法，本文将两者分开说明。

本次对应「活动／试炼 → 天缘召唤」（`cortCallUI`、`fight_type=10`），包括选择来源神仙、缘神仙预览、挑战、免费／道具支付、月卡及VIP次数、战报、五张牌手动／自动翻牌、魂魄入库、合成、成就和持久化。

## 1. 游玩方法与本次修复

达到16级并拥有原表列出的五星神仙后，进入天缘召唤，选择左侧来源神仙，右侧显示对应缘神仙。每天第一次挑战免费；后续挑战需要剩余次数及1颗魂缘丹（1024）。道具不足时可通过购买入口进入集市；有效月卡增加1次总额度。

挑战获胜后显示**五张奖励牌**，点击任意一张或等待10秒自动翻牌。奖励可能是来源魂魄、缘神仙魂魄或2颗魂缘丹；一次挑战只发所选牌展示的那份奖励。收集40个五星魂魄后，可以通过已有魂魄合成功能获得尚未拥有的目标神仙。

本次修正：

- 奖励事件70从错误的 `{prize_list=..., attach_list=...}` 改为原版直接读取的数组，修复胜利后没有翻牌页面。
- 奖励牌从旧实现的3张改为原版要求的5张，修复10秒自动翻牌随机落到第4／5位置时的越界。
- 战斗使用原包天缘守卫占位机制，客户端显示对应的缘神仙，不再使用通用活动对手。
- 魂魄奖励采用原版 `object_type=10`；旧实现的7实际为 `calc`。背包、魂魄列表和实际结算同步。
- 原表42组关系、每组7项产出全部接入，保留地藏王菩萨这一组的特殊权重。
- 增加来源所有权、目标参数、上阵状态、道具可用性和时钟回退校验；接入成就106「仙缘难寻」。

服务端改动在**下次启动本地离线游戏**时加载；本次不需要修改APK或增加Lua补丁。使用项目根目录的 `启动本地离线游戏.command`，保留原账号及存档。

## 2. 【A】原版客户端规则

| 项目 | 原版依据与结论 |
|---|---|
| 等级 | 魂缘丹使用入口 `packageUI` L1913—1921检查16级；原文案 `canNotUseHyd` 也明确16级 |
| 来源选择 | `cortCallUI` L293—331仅列品质≥5的已有神仙，按天缘目标、等级、类型排序；没有关系的神仙提示「该神仙无召唤天缘」 |
| 所有权与上阵 | 列表来自已有神仙总表，不要求所选来源神仙本身上阵；战斗使用普通阵容 |
| 对应目标 | `data.getCortCallById` 根据 `convert_output.csv` 的来源类型查目标类型；可点击右侧头像查看资料 |
| 挑战请求 | `1026`，`fight_type=10`，`des_type=0`、`des_id=0`，`des_value=来源神仙类型`，不是实例ID或目标类型 |
| 免费与道具 | `convert_fight_count=0`走免费分支；大于0时检查1024库存，文案显示「魂缘丹X1」；不足时打开购买入口 |
| 剩余次数 | `convert_fight_limit - convert_fight_count`；仅当 `month_card_time > 当前时间` 时加1，恰好到期不加 |
| 战斗目标外观 | `event_mgr` L448—450及L592—594将6001—6009占位敌人的外观、名称、转生显示替换为右侧缘神仙；原包实际保留6001—6003基础表 |
| 获奖条件 | 原界面图片 `v2/cortCall/txt1.png` 写明「召唤并挑战五星缘神仙，战胜即有机会获得其魂魄」 |
| 奖励协议 | `callbackOutput` L768—777直接把参数存为 `g_self.output`；`show`通过 `#output > 0`判断是否创建翻牌页 |

| 奖励与陪衬牌 | `getRewardsInfos` L904—928读取数组第一项作为实际奖励；`getUnrewardsInfos` L933—959依次读取第二项起的其他牌。玩家点击的位置改变展示位置，不会提交另一个领奖请求 |

| 上次选择 | 活动状态事件48的 `last_convert_type`恢复选择；原入口也按挑战时间判断跨日显示 |
| 商店 | 原 `item_buy_config.csv`：编号15特惠魂缘丹1颗、标价100；编号16常驻魂缘丹1颗、标价200 |
| 合成 | 原 `cortege_quality.csv` 五星 `spirit_compose_count=40`；沿用现有1083合成处理与重复拥有校验 |
| 成就 | 原 `achievements_config.csv`：106「仙缘难寻」，条件「天缘召唤参与一次」，目标1、奖励5A |

## 4. 【B】缺失服务端规则的完整补全

### 次数、支付与跨日

- 普通账号每天总次数1，首战免费。
- VIP1—10原文案中的「道具次数」按额外次数解释，总次数为道具次数+1；有效月卡再加1。这一解释沿用现有VIP模块，原服总次数配置没有取得。
- 每天UTC+8零点重置已用次数；保留上次来源、挑战时间、累计参与数和最近结算记录。现有存档可直接继续使用。
- 免费只指当天第一场；月卡增加的是总额度，不新增免费次数。
- 胜利、失败及战斗安全上限内未分胜负，都占用1次；非首战消耗1颗可用魂缘丹。失败与未分胜负不发奖。
- 来源神仙只用于确定天缘关系，**不会被献祭或消耗**；不要求其上阵，但普通阵容至少有一名已上阵神仙。
- 不额外消耗体力、精力、银两或元宝；不另发角色经验、神仙经验及银两。
- 集市币种与特惠每日1次沿用现有集市推测配置；因此离线售价为特惠100元宝、常驻200元宝。天缘请求本身不会自动替玩家购买道具。

### 守卫与战斗

`server_config/convert_rules.json` 明确标注 `mode=inferred`，当前选用原包6001模板单人守阵，固定16级、初始法术1级。模板的基础攻防血法与成长来自原表；模板选择、等级与单人阵容是推测。保留原客户端的6001外观替换，实际显示为所选缘神仙。

守卫不会随玩家即时战力等比例变化。需要调整离线难度时，可在配置内选择原包6001／6002／6003，调整守卫等级和法术等级；五张牌是原客户端约束，不能改为其他数量。配置启动时校验。

胜负使用现有公共战斗引擎，支持普通上阵神仙和已接入的养成效果。服务端生成1028阵容、1027逐步战报及事件44；不接受客户端上报胜负或奖励。公共引擎本身的缺失服务端公式仍属【B】，本次没有冒称还原官方战斗难度。

### 奖励、展示与结算

胜利时按原表抽取一项实际奖励，另独立抽取四项展示牌；允许重复。后四项的生成方式为【B】，数量五张、第一项是实际奖励的排列语义为【A】。

实际奖励先与次数、道具消耗一起保存，再下发翻牌展示；翻第1或第5位置均显示同一项已结算奖励。后四项不入库。魂魄分别进入来源或目标的魂魄库存，返回的魂缘丹可用于剩余挑战。

失败也下发空事件70，清除客户端可能残留的上一场奖励；返回正常挑战界面，不创建奖励页。胜利后断线、关闭翻牌或重启，不会丢失已入库奖励，也不能靠翻牌重复领取。重连恢复库存和选择；不额外恢复一个待领取弹窗。

### 校验、持久化与成就

- 服务器检查16级门槛、来源在原表且由玩家持有、目标参数为原协议值、有效上阵阵容、VIP／月卡额度、魂缘丹库存与锁定／装备状态。
- 检测日期或天缘最近操作时间回退；拒绝时不扣资源，不允许将来时间的额度回到过去重复使用。
- 最近结算保存在 `role.activity.convert_last_result`，包含战斗ID、来源、目标、胜负、五张牌、实际奖励、时间与配置版本；`convert_total`记录累计参与。
- 成就106根据累计参与的实际增量触发，胜负都算参与；查询、拒绝、翻牌以及相同请求的重放不增加成就。
- 业务在独立角色副本上结算，编码完成后保存；协议编码失败不会提交扣费、奖励或结算记录。
- 同一服务会话的相同序号及内容返回缓存，旧序号或相同序号不同内容拒绝。库存和结算记录持久化，但通用请求缓存不跨服务重启持久化；不宣称旧报文跨进程重放具备严格幂等性。

## 5. 调试与验证

验证使用临时数据库、隔离账号和拦截发包的原版Cocos探针，没有消耗正式角色的魂缘丹或修改正式角色养成。

- **12项天缘后端专项测试通过**：包括42组关系的全部权重区间起止边界、7类具体产出、真实胜利与真实失败、只发第一项、免费与付费、购买后继续、VIP0—10及月卡到期、无神仙／无阵容／道具锁定／等级不足拒绝、跨日、重启、时钟回退、成就、40魂合成和编码失败回滚。
- **181项相关回归通过**：活动、成就、VIP、集市、阵容与公共战斗引擎。
- **9步原协议流程通过**：免费获得目标魂魄→合成→无丹拒绝→集市购买→返还魂缘丹→来源魂魄→次数耗尽→重启恢复→次日免费。战斗使用真实引擎；测试账号等级和前三场抽奖分支为明确控制的测试条件。
- **18项原版客户端探针通过**：入口、目标详情、五星选择、原请求结构、未选择拒绝、无丹购买分支、道具挑战、次数与月卡、旧格式问题复现、三类奖励、五个自动翻牌位置、真实后端战报的敌人外观替换与奖励衔接、失败返回。

客户端探针将倒计时起点提前，并为五个自动翻牌位置固定随机输入。它验证真实原版回调和界面节点，不等同于正式账号逐帧播放整场战斗或人工点击全过程；不以一次随机自动翻牌成功代替五个位置覆盖。购买分支使用替代购买窗口检查入口，实际购买扣款及入库由原协议后端测试验证。
