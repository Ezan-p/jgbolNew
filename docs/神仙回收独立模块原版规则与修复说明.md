# 神仙回收独立模块原版规则与修复说明

日期：2026-10-26；客户端：本仓库金箍棒3.87。

【A】表示原包Lua字节码、CSV或协议可以直接证实；【B】表示原服务端缺失时采用的本地推测策略。原服务端源码和概率配置未取得，不能把【B】视为官方规则。

## 模块范围与入口

- 【A】功能菜单中的神仙回收对应 `activityID.cortegeRecycle=24`；`funUI.pressMenu` → `activityUI.show(24)` → `showCortegeRecycle` → `cortegeRecycleUI.show`。活动入口要求角色15级（`activityUI:1512–1513`）。界面标题为“天道轮回”，有“神仙轮回”“装备轮回”两个入口，见[实机入口截图](../analysis/evidence/recycle/entry.png)。
- 【A】装备回收另要求25级，取原包 `equip_transfer_config.csv`；15级开放模块不等于15级可以回收装备。
- 本次接通此前未处理的1086协议，使原版入口后的神仙选择、确认、消耗、奖励、返回和重进形成完整流程。保留原版界面和等级限制，不替换APK，不赠送测试资源。
- 独立模块与阵容内1084飞升回收、神石祈福、魂魄回收不是同一业务，本次不改变它们。

## 【A】神仙回收规则

| 项目 | 原版规则与证据 |
| --- | --- |
| 可选神仙 | `cortegeRecycleUI:1058–1063` 仅收录四星、`order<=0`、`cheer_order<=0`的神仙，即未上阵、未助威 |
| 数量 | 必须选满5名；不足5名有提示，不能发送；选择器有排序、仙缘标识和选择数量限制 |
| 高价值确认 | 已培养等级较高的神仙会触发原版确认框；界面并非只允许1级神仙 |
| 请求 | 1086：`serial_num,flag,c1,c2,c3,c4,c5`；`flag=0`，五个字段均为神仙实例ID，不是类型ID（887–915行） |
| 奖励预览 | `fillInHeadBtns:947,997,1014,1035`：已选数量+1本，满5名即6本；等级 `角色等级−角色等级%15`。原字节码数值池已核对，模数是15 |
| 仙缘识别 | `getCharFateTable:803–835`、`checkHasFate:838–883`：读取 `fate_config.csv` 的神仙目标仙缘，目标数量小于5，选中发起神仙及所有目标神仙才算完整仙缘；不是任意两名同种族即生效 |
| 仙缘提示 | 完整组合提示“有机会获得高级密卷”；未给出概率、是否逐本抽取等服务端规则 |
| 普通/高级密卷 | 原包物品1041–1080，显示等级5–100、每5级一档；奇数为普通密卷，后一偶数为同档高级密卷。高级增加经验值，不等于提高显示等级 |
| 响应 | 2998/event 64，`roll_list={{type_id,level,count}}`；1360–1407行播放动画，约3秒后清除选择并弹出奖励 |
| 密卷使用 | 原版1059/flag=1，按物品类型计数提交；经验取 `item_base.csv.experience_plus`。返回event 65，沿用既有等级上限和超等级经验衰减实现 |

例如角色60级，无仙缘时预览60级密卷；本地结算普通1063×6，满足仙缘并命中高级时1064×6。二者每本经验分别640000、2560000，直接来自原包CSV。物品实例的 `level=1`，显示“60级”来自该物品类型的 `show_level=60`，不能把1041的实例level设成60来代替1063。

继续使用 `equipment_crafting.py` 的1074/flag=1处理器。原版提交 `num=1,des_type=1,count,id_list`；event 116含 `result=1,flag=1,transform_list,compensate_list`，先同步库存，再播放轮回动画和奖励。

| --- | --- |
| 四星武器、防具 | 1313四星灵器×5 |
| 四星法宝 | 1313四星灵器×15、1322远古水晶×5 |
| 五星武器、防具 | 1314五星灵器×10、1322远古水晶×8 |
| 五星法宝 | 1314五星灵器×5、1322远古水晶×4 |

以上物品编号、数量及25级门槛直接来自 `equip_transfer_config.csv`。原表 `exchange_rate=0.8`；本地按该比例返还历史强化银币及升阶、铸星材料，各项向下取整。具体归还哪些历史投入、取整顺序属于既有【B】服务端补全，见装备系统说明。

【A】选择界面最多6件，同批选择同品质；一键选择优先四星，最多6件。五星或法宝会弹出高价值确认。1074同时供其他界面使用，服务端保留该协议已有批量上限，不把独立界面的便捷选择上限误设为所有调用方的限制。

【B】服务端拒绝已装备、已锁定、已升星/转生等不合法装备；镶嵌宝石返还，避免悬空引用。失败不扣材料。此次复用原有实现并验证三部位、两品质及养成返还，不重复建立第二套装备结算。

## 【B】缺失服务端的实现策略

配置：[cortege_recycle_rules.json](../server_config/cortege_recycle_rules.json)，`mode=inferred`，版本 `2026-10-26-recycle-1`。

| 项目 | 本地规则及理由 |
| --- | --- |
| 高级概率 | 完整仙缘组合时25%，否则0%；每批判定一次，6本均同类型。原版只证实“有机会”，25%及整批判定均为推测 |
| 超出原包等级 | 角色等级向下取15倍数后，最多100级密卷；原包没有更高档，不生成不存在的类型 |
| 额外收费/次数 | 不额外扣银币、元宝、道具，不设置日限次；客户端没有对应收费或次数提示，不凭空添加 |
| 养成消耗 | 神仙及其等级、培养、飞升等投入随回收消失，不再另外返经验、魂魄、培养材料。原版只有密卷奖励合同，没有完整养成返还表；高价值确认仍保留 |
| 所属物品 | 删除被回收神仙的专属天生法术；铭刻精魄等非天生所属物品解除绑定，保留等级、进度和锁定。避免无主物品丢失，也不复制物品 |
| 魂魄与图鉴 | 未使用的魂魄按神仙类型保留；历史图鉴、已完成收集记录保留，不因回收熄灭或退还激活材料 |
| 防误操作 | 服务器独立校验5个不同实例、归属、四星、未上阵、未助威；锁定或培养结果待确认者拒绝，防止绕过客户端提交 |
| 原子性 | 在独立角色副本上处理，响应成功编码后才保存；任一目标无效时整批不变 |
| 重放 | 沿用阵容会话序号缓存，同序号同请求返回原响应，不再次消耗/随机；过期或冲突序号拒绝。重登后旧神仙ID已不存在，不会重复奖励；不是跨会话交易ID系统 |
| 配置校验 | 启动及结算检查配置来源、概率0–100及固定策略名称，非法配置拒绝而非静默回退 |

## 修复文件与验证

- [cortege_recycle.py](../network_redirect/cortege_recycle.py)：独立神仙回收结算、仙缘判定、原包密卷类型选择、所属物品处理。
- [formation.py](../network_redirect/formation.py)：1086路由、启动配置检查；复用库存、图鉴、战力同步和持久化事务。
- [test_cortege_recycle.py](../tests/test_cortege_recycle.py)：概率分支、等级边界、非法请求整批回滚、上阵/助威/品质/锁定/待培养保护、精魄返还、重复请求、重登、密卷实际使用。
- [audit_recycle_rules.py](../analysis/tools/audit_recycle_rules.py)：逐值核对原包CSV与提取表，记录资源SHA-256和Lua预览常量，输出 [audit.json](../analysis/evidence/recycle/audit.json)。
- [build_recycle_client_fixture.py](../analysis/tools/build_recycle_client_fixture.py)：生成临时后端协议响应，在原版模拟器中测试入口、分页、五选仙缘预览、1086发送、奖励动画、消耗后重选、装备选择与1074确认、装备奖励、返回及重开。关闭真实发包，结束恢复客户端表；不修改实际存档。

复现命令：

```sh
.runtime/venv/bin/python analysis/tools/audit_recycle_rules.py
.runtime/venv/bin/python -m unittest tests.test_cortege_recycle tests.test_equipment_crafting -q
.runtime/venv/bin/python analysis/tools/build_recycle_client_fixture.py
```

第三条仅生成 `.runtime/recycle-fixture.lua`，需在项目模拟器Lua线程执行并读取 `recycle_fixture_finished`、`recycle_fixture_results`。UI测试使用真实原版函数和临时协议响应，不能冒充实际账号全流程网络消费验证。
