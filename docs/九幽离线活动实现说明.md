# 九幽离线活动实现说明

更新日期：2026-10-26。适用原版 3.87 客户端与本项目 Python 离线服务端。

【A】表示原包 CSV、协议、客户端字节码可核实的规则；【B】表示缺少原服结算逻辑后采用的本地规则。本文说明完整活动；伤害、精魄和战报细节另见[九幽战斗系统解析](九幽战斗系统解析.md)和[战斗机制重建V2](战斗机制重建V2.md)。已有战斗解析中的早期实现描述不覆盖此次离线经济与榜单修复。

## 1. 玩家可用流程

70 级后进入“活动→九幽”：选择已开放层数挂机，领取临时背包，处理随机事件；通过药神殿学习配方、购买材料、制造药品，给冥仙用药后挑战。击败冥仙开放下一层，直至第 81 层。魂晶可直接兑换九幽商店商品，宝图可在背包打开或批量使用，通幽榜展示本地 NPC 与玩家的进度。

【A】每天最多挑战冥仙 5 次，失败也消耗次数的本地解释属于【B】。通关后继续挂机、领取、事件、炼药、宝图和商店操作；【B】不再允许挑战最终冥仙或继续给其用药，避免重复终层奖励和无意义消耗。

| 环节 | 当前实现 | 依据 |
|---|---|---|
| 开启与层数 | 70 级，九狱各九层，共 81 层 | 【A】总说明、挂机表、冥仙表 |
| 挂机 | 不依赖真人在线，重登按本地服务端时间补算 | 持续挂机【A】；频率、上限、结算方式【B】 |
| 冥仙 | 原表 81 层阵容、奖励、普通药和精魄；服务端计算战斗 | 表与回放协议【A】；具体模拟规则【B】 |
| 随机事件 | 猜数字、祈福、遇魂仙、妙手空空、火眼金睛 | 类型和操作【A】；概率和奖池【B】 |
| 药神殿 | 学配方→买材料→炼药→用药／炼化；药灵丹升级 | 配方、材料价格、经验表【A】；产出品质、制造熟练度【B】 |
| 风云录 | 资料库 NPC 通幽榜前 20 名，显示本人实际排名 | 层数榜和前 20 名【A】；NPC 进度【B】 |
| 榜奖 | 原表通幽榜前五名附件，通过本地系统邮件领取 | 奖励物品【A】；每日结算与邮件方式【B】 |
| 宝图 | 1431—1440，12 格奖盘、移除、继续寻宝、放弃、月卡快速和批量使用 | 原版操作【A】；缺失奖池和价格【B】 |

## 3. 在线内容的离线处理【B】

### NPC 通幽榜

数据源限定为 [analysis/npc_design/players/catalog.json](../analysis/npc_design/players/catalog.json)，复用 `npc_players`。当前有 **510 名等级≥70的 NPC** 参加；不把低于开启等级的角色放入榜单，也不生成虚构的占位玩家。姓名、玩家 ID、头像和等级直接来自资料库。按这些 ID 走现有玩家阵容查询，可查看其对应 V1/V2 阵容。

首次进入活动保存 `npc_epoch_day`。令参加 NPC 的配置战力对数最小值为 lo、最大值为 hi：

```text
初始通关层数 = 1 + floor(71 × (log(战力) - lo) / (hi - lo))
当前通关层数 = min(80, 初始层数 + floor(距首次进入的本地日数 / 3))
排序 = 通关层数降序，再按玩家 ID 升序
```

这是按配置实力分配离线探索进度，并非声称这些 NPC 已经逐层模拟打败原版冥仙。它不随玩家查询重掷、不随重启归零，也不按玩家当前层数追赶。NPC 最高 80 层，玩家完成 81 层可获得第一名。榜单只返回前 20 人，本人信息另返回实际总排名；本人不在前 20 时不会挤占 NPC 的位置。

原版可见九幽操作不包含真人组队、邀请、交易或对战请求；保留冥仙与魂仙作为原版怪物，不将它们误替换成玩家 NPC。消息栏改由本地挂机收益、随机事件和本人通关记录填充。记录最多 20 条，轮询仅发送尚未推送的记录；重进页面仍可查看历史。`top_type=2` 保留原版奖励页回调，不虚构第二套声望竞赛。

### 榜奖

本地时间按 `activity_rules.timezone_offset_hours`，当前为 UTC+8。下次操作九幽时结算**上一个实际活跃日**的最终通关层数和 NPC 进度，符合前五名则发放 `specter_top_prize` 的 type 1 附件。邮件批次为 `abyss-rank-日号`，永久有效、只能领取一次。

连续离开多天只结算上次活跃日，不为未参与的日期制造奖励；查询、重登、重复领取不重复发奖。没有原服周期证据，因此每日、活跃日范围、永久邮件均明确属于【B】，不是原版已证实的周奖。

## 4. 挂机、背包与魂晶【A／B】

【A】魂晶是九幽货币；其他掉落先进入临时背包。此次修复了两个实际断点：

1. 原掉落表重复列名曾被 `DictReader` 覆盖，只留下最后一组。现在专门按列读取，四组全部参与抽取，宝图、药灵丹及精魄材料等可正常产出。
2. 原冥仙奖励中的 1441 魂晶曾进入普通背包，与兑换余额脱节。现在活动奖励统一入九幽魂晶余额；旧存档里的 1441 堆叠首次操作九幽时转换并删除原堆叠，同一存档不会再次转换。普通背包的锁定标记不阻止货币迁移，数量不损失。

【B】具体数值保持现有离线配置：

| 项目 | 规则 |
|---|---|
| 挂机周期 | 每 300 秒一个完整结算点 |
| 离线上限 | 最近 48 小时内的完整结算点，最多 576 次；超出的旧时段舍弃 |
| 魂晶 | 每次 `max(1, 当前角色战力 // 100)`；历史离线时段用恢复时的角色战力估算 |
| 掉落 | 先按四组外层权重选组，再按组内权重选物品；每次产生一个物品记录；外层权重按相对权重解释，非独立百分比 |
| 双倍 | 每小时 10 元宝，最多续至未来 48 小时；只有整个 300 秒周期被双倍窗口覆盖才翻倍；续费前先结算历史，不追溯放大之前收益 |
| 背包 | 初始 30 格，20 元宝扩 1 格，最多 60 格；一条掉落记录一格；满包后仍得魂晶，额外道具不保留 |
| 每日统计 | 按各个结算点所属本地日期归属，只展示当日挂机战斗次数、魂晶和道具数；不会把前两日补算全计为今天 |

领取后清空临时背包；换层先结算原层，之后按新层掉落。重复同一时刻查询不能重复产出。魂晶在事件被偷、商店扣费与冥仙领奖后使用同一余额。

## 5. 冥仙、药神殿与随机事件【A／B】

【A】保留 81 层原始冥仙、原药品与精魄配表。请求不接收客户端声称的胜负、伤害或奖励。日挑战次数、已开放层、消耗、阵容是否存在均由本地服务端检查。

【B】沿用现有统一战斗引擎；有精魄的冥仙使用配置 `abyss_boss_max_actions=80`，其余使用通用上限。80 是本地选择而非原版协议硬上限。普通药削减总属性再按敌方基础属性分摊，每名单位每项属性最低为 1；替换药槽重新计算，失败保留药效，胜利清空。两格精魄药按实际可削减效果校验，无效果不消耗。

【A】普通药品质连续编号，四类精魄药品质相隔 20；此次修复了原来“药品编号＋品质”会制造出其他家族药甚至普通药的问题。现在 4 家族×4 品质都有对应原表产物。

【B】制造品质仍使用确定性等级档：`min(3, max(0, 药师等级-配方最低等级) // drug_quality_level_step)`，0—3 分别下、中、上、极品。原版说明是随炼药等级提高而增加高品质概率，但概率表未恢复，因此确定性档位属于离线替代。现有制造熟练度统一取 `drug_craft_exp=10`；原版称不同药品熟练度不同，但数值未恢复。所有配方可达到原表最低等级后花原表元宝学习，未恢复的掉落／兑换配方限制采用这一【B】替代路径，避免配方不可获得。

五类事件均可处理或放弃，队列上限 5 个；【B】每小时产生一个随机类型，满队列期间不积压额外事件。答案、魂仙剩余血量、尝试次数均存档。魂仙按真实战报累计伤害，免费 3 次后优先扣 1023 道具，否则每次 20 元宝。猜数字区间、四次机会和神仙猜测保留原版操作。奖池与祈福消耗使用现有 `activity_rules`，不接受客户端传入的奖励。

此次还将魂仙战斗中的通用沙弥替换为原包 `cortege_base_0` 中标注 `jiuyousuiji` 的 7221、7222、7223 三种怪物【A】。随机选择、事件生成时按挂机层设置等级、HP 至少 50,000 并结合原表成长取较大值，属于【B】；选定身份、等级和初始血上限存档，战报与事件预览一致。旧事件缺少身份时使用 7221，不重新抽取或恢复已损失血量。

## 6. 宝图与商店【A／B】

宝图首抽消耗一张宝图，后续最多 3 次，每次 20 元宝；允许首抽前屏蔽最多 2 格，已屏蔽和已抽中格不再抽取。奖盘、抽取次数和快速标记持久化。批量最多 99 张，每张可选择 1—4 抽，一次性校验并扣图／元宝。上述次数与奖池属于【B】，沿用现有离线数值。

【A】快速标记需要有效月卡；此次补齐重新打开宝图时检查到期状态，过期后不会继承旧的快速标记。普通寻宝仍可使用。

九幽商店的商品、魂晶价格和每日次数采用 `activity_rules.abyss_shop` 的现有【B】配置。药材商店材料与银币价格来自配方表【A】。客户端重复 serial 回放、改包拒绝、失败原子回滚沿用后端统一机制；九幽零序号 `id15` 轮询不干扰写请求重放缓存。
