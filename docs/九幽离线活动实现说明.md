更新日期：2026-10-28。适用原版 3.87 客户端与本项目 Python 离线服务端。

【A】表示原包 CSV、协议、客户端字节码可核实的规则；【B】表示缺少原服结算逻辑后采用的本地规则。本文说明完整活动；伤害、精魄和战报细节另见[九幽战斗系统解析](九幽战斗系统解析.md)和[战斗机制重建V2](战斗机制重建V2.md)。本次九狱逐层核查、修复方案与验证结果见[九幽九狱玩法与数值核查](九幽九狱玩法与数值核查.md)。当前战斗规则以[战斗机制完整说明与本次修复](战斗机制完整说明与本次修复.md)为准。

## 1. 玩家可用流程

70级后进入“活动→九幽”，首次获得药灵丹40颗、银币100,000、元宝50，使用药灵丹达到4级后可制造初阶极品药。随后：选择已开放层数挂机，领取临时背包，处理随机事件；通过药神殿学习配方、购买材料、制造药品，给冥仙用药后挑战。击败冥仙开放下一层，直至第 81 层。魂晶可直接兑换九幽商店商品，宝图可在背包打开或批量使用，通幽榜展示本地 NPC 与玩家的进度。

【A】每天最多挑战冥仙 5 次，失败也消耗次数的本地解释属于【B】。通关后继续挂机、领取、事件、炼药、宝图和商店操作；【B】不再允许挑战最终冥仙或继续给其用药，避免重复终层奖励和无意义消耗。

| 环节 | 当前实现 | 依据 |
|---|---|---|

## 3. 在线内容的离线处理【B】

### NPC 通幽榜

数据源限定为 [analysis/npc_design/players/catalog.json](../analysis/npc_design/players/catalog.json)，复用 `npc_players`。当前有 **510 名等级≥70的 NPC** 参加；不把低于开启等级的角色放入榜单，也不生成虚构的占位玩家。姓名、玩家 ID、头像和等级直接来自资料库。按这些 ID 走现有玩家阵容查询，可查看其对应 V1/V2 阵容。

首次进入活动保存 `npc_epoch_day`。令参加 NPC 的配置战力对数最小值为 lo、最大值为 hi：

```text
初始通关层数 = 1 + floor(71 × (log(战力) - lo) / (hi - lo))
当前通关层数 = min(80, 初始层数 + floor(距首次进入的本地日数 / 3))
排序 = 通关层数降序，再按玩家 ID 升序
```

这是按配置实力分配离线探索进度，并非声称这些 NPC 已经逐层模拟打败原版冥仙。它不随玩家查询重掷、不随重启归零，也不按玩家当前层数追赶。NPC 最高 80 层，玩家完成 81 层可获得第一名。榜单只返回前 20 人，本人信息另返回实际总排名；本人不在前 20 时不会挤占 NPC 的位置。

原版可见九幽操作不包含真人组队、邀请、交易或对战请求；保留冥仙与魂仙作为原版怪物，不将它们误替换成玩家 NPC。消息栏改由本地挂机收益、随机事件和本人通关记录填充。记录最多 20 条，轮询仅发送尚未推送的记录；重进页面仍可查看历史。`top_type=2` 保留原版奖励页回调，不虚构第二套声望竞赛。

### 榜奖

本地时间按 `activity_rules.timezone_offset_hours`，当前为 UTC+8。下次操作九幽时结算**上一个实际活跃日**的最终通关层数和 NPC 进度，符合前五名则发放 `specter_top_prize` 的 type 1 附件。邮件批次为 `abyss-rank-日号`，永久有效、只能领取一次。

连续离开多天只结算上次活跃日，不为未参与的日期制造奖励；查询、重登、重复领取不重复发奖。没有原服周期证据，因此每日、活跃日范围、永久邮件均明确属于【B】，不是原版已证实的周奖。

## 4. 挂机、背包与魂晶【A／B】

【A】魂晶是九幽货币；其他掉落先进入临时背包。此次修复了两个实际断点：

1. 原掉落表重复列名曾被 `DictReader` 覆盖，只留下最后一组。现在专门按列读取，四组全部参与抽取，宝图、药灵丹及精魄材料等可正常产出。
2. 原冥仙奖励中的 1441 魂晶曾进入普通背包，与兑换余额脱节。现在活动奖励统一入九幽魂晶余额；旧存档里的 1441 堆叠首次操作九幽时转换并删除原堆叠，同一存档不会再次转换。普通背包的锁定标记不阻止货币迁移，数量不损失。

【B】2026-10-28修复后的挂机经济如下，每个完整结算点计入统计中的一场挂机战斗：

| 项目 | 规则 |
|---|---|
| 挂机周期 | 每 300 秒一个完整结算点；每日统计的 `fight_count` 按完整结算点累计，`now_fight_len` 返回 300 秒，不再固定为 0 |
| 离线上限 | 最近 48 小时内的完整结算点，最多 576 次；超出的旧时段舍弃；服务器时钟回退时不补算负时长 |
| 魂晶 | 每次 `min(所在狱上限, max(1, 当前角色战力 // 1000))`；九狱上限为3—11，双倍再×2；历史离线时段按结算时战力估算 |
| 掉落 | 先按四组外层权重选组，再按组内权重选物品；每次产生一个物品记录；外层权重按相对权重解释，非独立百分比 |
| 双倍 | 每小时 10 元宝，最多续至未来 48 小时；只有整个 300 秒周期被双倍窗口覆盖才翻倍；续费前先结算历史，不追溯放大之前收益 |
| 背包 | 初始 30 格，20 元宝扩 1 格，最多 60 格；同类型／等级道具堆叠一格；旧重复记录自动合并且不丢数量；满格仍可叠加已有品种，仅新种类无空位时丢弃，统计保留生成数 |
| 每日统计 | 按各个结算点所属本地日期归属，只展示当日挂机战斗次数、魂晶和道具数；跨日补算不会全部计入今天；统计数值与实际魂晶余额分开保存 |

领取后清空临时背包；换层先结算原层，之后按新层掉落。重复同一时刻查询不能重复产出。魂晶在事件被偷、商店扣费与冥仙领奖后使用同一余额。

## 5. 冥仙、药神殿与随机事件【A／B】

【A】保留81层冥仙身份、阵容及原药品／精魄参数；【B】基础四维按各狱25/30/35/40/45/50/50/50/50%缩放，灵力封顶为缩放后攻击的2倍，随后计算普通药减益。主冥仙继承原角色可释放的主动法术，否则补101级别1法术；精魄仅挂主冥仙。请求不接收客户端声称的胜负、伤害或奖励。日挑战次数、已开放层、消耗、阵容是否存在均由本地服务端检查。

沿用统一战斗引擎：按既有明确约定，每场最多30个完整回合，到限比较双方当前总气血（含存活替补），相等为平局；可在冥仙仍存活时获胜。`abyss_boss_max_actions=80` 和 `battle.max_actions=240` 不是当前正式战斗上限。伤害公式与普通药分配仍属【B】。普通药削减总属性再按敌方基础属性分摊，每名单位每项属性最低为 1；替换药槽重新计算，失败保留药效，胜利清空。普通药比较替换前后的有效属性，无效或降级替换拒绝且不扣药；两格精魄药同样按实际削弱效果校验。

【A】普通药品质连续编号，四类精魄药品质相隔20。已修复高品质药需要超过36级的问题：40配方、160变体全部在合法等级可产出。

【B】配方要求等级与当前等级相差0/1/2/≥3级时，下／中／上／极品概率分别为60/25/10/5%、35/35/20/10%、10/25/40/25%、0/0/0/100%。相差3级后稳定极品；33级配方在36级可稳定极品。每次制造仍获10熟练度。通过通关获得逐步增加的熟练度，按4级→36级的累计原表经验曲线在前72层分配；通关还免费领悟课程已开放且本人达到要求等级的配方，已学的不退费也不重复授予。自行提前学习仍按原表元宝价。

每层首胜魂晶为原表整数÷100，另发 `100000+20000×层数` 银币供购买药材。其他原表道具奖励保留。已有魂晶／道具／学习记录不清空、不追扣；新账号和旧账号的一次性入门补给均以存档标记防重。

配方标记已按原客户端的**每个字段31位、最低位保留**修复，两个有符号int32覆盖40种配方；全学会时为`(-2,1022)`。每次进入九幽从已学配方ID重建旧标记，不改变已学配方，避免第31／32种配方后封包溢出或界面错位。

五类事件共用上限5个的队列；猜数字、祈福、魂仙和火眼金睛可在查看后处理或放弃，妙手空空在查看时直接结算并出队；【B】每小时产生一个随机类型，满队列期间不积压额外事件。答案、魂仙剩余血量、尝试次数均存档。魂仙按真实战报累计伤害，免费 3 次后优先扣 1023 道具，否则每次 20 元宝。猜数字区间、四次机会和神仙猜测保留原版操作。奖池与祈福消耗使用现有 `activity_rules`，不接受客户端传入的奖励。

此次还将魂仙战斗中的通用沙弥替换为原包 `cortege_base_0` 中标注 `jiuyousuiji` 的 7221、7222、7223 三种怪物【A】。随机选择、事件生成时按挂机层设置等级、HP 至少 50,000 并结合原表成长取较大值，属于【B】；选定身份、等级和初始血上限存档，战报与事件预览一致。旧事件缺少身份时使用7221，不重新抽取或恢复已损失血量。客户端补丁还修复了妙手空空复用事件窗口时新按钮表为空的问题；需要重绘时重建该事件子层。

### 2026-10-27 冥仙挑战按钮修复

原客户端 `abyssUI` 的第1887—1890行先计算 `剩余 = max_fight_count - fight_boss_times`，却以 `剩余 >= max_fight_count` 提示次数已满。因此首次进入或每日刷新后的 **5/5** 被拦截，请求没有到达服务端；仅修改后端次数无法修复此问题。第2320—2322行的次数显示公式本身正确，`fight_boss_times` 仍表示已使用次数。

新增 `network_redirect/abyss_client.lua`，由 `summon.py` 的现有客户端补丁通道加载，只替换冥仙面板的挑战按钮回调，保留原版面板、阵容准备和战报流程。挑战发送 `1329/id6`，由服务端按当前日期核验每日5次额度；旧页面显示0/5时也允许请求到达服务端，从而正常完成跨日重置。通关后显示独立的八十一层完成提示，不再与次数已满混用。此离线入口采用服务端既有70级、已开放挑战层、已上阵神仙和日额度检查；不再沿用旧按钮中额外的客户端转生拦截。

每场有效战斗消耗一次，失败／平局保留当前层与已用药，胜利发放该层奖励、开放下一层并清空药槽。第81层胜利标记完成，之后不能重复挑战领奖。拒绝请求不扣次数、不发奖；同日重启保留额度，每日0点恢复5次。服务端分别提示“次数已用尽，每日0点恢复5次”与“八十一层已全部通关”。

## 6. 宝图与商店【A／B】

宝图首抽消耗一张宝图，后续最多 3 次，每次 20 元宝；允许首抽前屏蔽最多 2 格，已屏蔽和已抽中格不再抽取。奖盘、抽取次数和快速标记持久化。批量最多 99 张，每张可选择 1—4 抽，一次性校验并扣图／元宝。上述次数与奖池属于【B】，沿用现有离线数值。

【A】快速标记需要有效月卡；此次补齐重新打开宝图时检查到期状态，过期后不会继承旧的快速标记。普通寻宝仍可使用。

九幽商店使用 `activity_rules.abyss_shop` 作为完整候选池。当前池包含 30 种原九幽商店中出现的道具（普通蟠桃、伏心转生石、各类普通属性下品药及四种精魄下品药），每日按角色和本地日期从池中无放回选出 6 种，保存到角色副本；当天重复查询、重登和进程重启都沿用同一批商品。每日换日时重置限购次数并重新选取 6 种，配置版本变化也会触发一次迁移刷新。

价格和限购已按新的挂机产出重新压低：蟠桃 1001×10 为 120 魂晶、每日限 3 次；伏心转生石 1330×5 为 80 魂晶、每日限 3 次；普通药为 500—1600 魂晶、每日限 2 次，精魄药为 1800 魂晶、每日限 1 次。兑换按商品奖励身份记录次数，不会因每日商品排序变化而串用旧次数。查询回包带 `shop_day`、`shop_revision` 和下一次刷新时间；客户端带回这两个字段时，服务器会拒绝过期页面的兑换请求。

药材商店材料与银币价格来自配方表【A】。客户端重复 serial 回放、改包拒绝、失败原子回滚沿用后端统一机制；九幽零序号 `id15` 轮询不干扰写请求重放缓存。
