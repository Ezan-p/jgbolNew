# 通天塔离线活动实现说明

更新日期：2026-10-26。适用原版 3.87 客户端与本项目 Python 离线服务端。

【A】表示原包道具说明、CSV、协议和客户端字节码能够核实的规则；【B】表示没有原服逻辑后采用的离线实现。原版客户端不是完整服务器：地图生成、敌方属性、掉落概率和周奖数量均未恢复，不能把这些实现称为原版数值。

## 1. 可游玩流程

36 级后从“活动→通天塔”进入，逐格探索，收集锤子／道符、挑战钥匙守卫、开启对应宝箱，击败本层守塔者后进入下一层。仙力不足可使用仙露或等待自然恢复；生命不足可等待次日或花 200 元宝恢复。通天币用于六格商店兑换。

【B】当前完整开放 1—60 层，依据已恢复的奖励表封顶。60 层击败守塔者后踏入楼梯，领取一次终点奖励、显示通关提示，楼梯变为普通地面。之后可继续探索剩余格、传送回已到达层、兑换与查看榜单，不会因“已经顶层”回滚最后一步，也不会重复发放终点奖励。

【A】周一 0 点重置进度并按排名发奖，钥匙与道具保留。【B】使用 30 名本地 NPC 构成周榜，奖励通过系统邮件领取；离线期间的恢复和跨周结算在下次登录／活动准备时补算，不要求真人在线。

## 3. 地图、消耗和奖励【A／B】

【A】金／银／铜箱 20007／20008／20009 分别消耗一把 20010／20011／20012 钥匙；石块 20003 消耗锤子 20005，篝火 20004 消耗道符 20006。

【B】每层使用可连通的 5×8 固定布局，从 `(1,1)` 开始；移动只允许上下左右相邻格，探索揭示周围 3×3 格。每次成功移动消耗 1 点仙力，挑战失败也消耗 1 点；非法坐标、缺钥匙／工具、生命不足开战等拒绝请求不扣资源。

| 格子 | 坐标（行，列） | 本地行为【B】 |
|---|---|---|
| 锤子／道符 | (1,2)／(1,5) | 拾取对应道具 1 件 |
| 石块／篝火 | (2,2)／(2,5) | 消耗工具，清除障碍 |
| 铜／银／金钥匙守卫 | (1,3)／(2,3)／(3,2) | 胜利给对应钥匙 1 把，并给格子奖励 |
| 铜／银／金箱 | (1,4)／(2,4)／(3,3) | 消耗钥匙，给格子奖励 |
| 铜／银／金守关者 | (3,4)／(4,2)／(4,3) | 可选战斗，给格子奖励 |
| 本层守塔者 | (4,7) | 胜利给格子奖励；必须击败才能使用楼梯 |
| 楼梯 | (5,8) | 进入下一层；60 层结算一次终点奖励 |

每个宝箱／战胜的守卫／最终终点：按当前楼层原表 `daoju` 条目等概率抽取 1 项，并给 50 通天币。**物品及其单项数量属于【A】，触发位置、概率与 50 通天币属于【B】**。表中重复条目保留重复权重；不会自行合并成唯一物品等概率。胜利后的格子被清空，失败则保留敌人和原位置。

通天币统一为背包道具 20000，掉落、邮件领取和商店扣费使用同一库存。奖励弹窗包含实际入账的通天币。旧存档如果只有 `coin_count`，迁移时只补足库存差额，并保存迁移标记，避免重复补币。

【B】`reset` 只回到第一层起点，不重建地图、不恢复资源；传送允许前往本周已到达的任意层，花 20 元宝回到该层起点。客户端目前提供分段传送入口，服务端允许的范围更宽。已经拾取、清除或战胜的内容在同一周回访／重启后不会刷新。新周才重新生成地图。

## 4. 生命和仙力【A／B】

| 项目 | 实现 | 分类 |
|---|---|---|
| 初始生命／仙力 | 各 100，上限各 100 | 【B】 |
| 生命自然恢复 | 本地每日 0 点恢复至上限 | 恢复时间【A】；恢复至满值的解释【B】 |
| 仙力自然恢复 | 每半小时 1 点，最多恢复至 100 | 半小时周期【A】；每次 1 点、按整点／半点结算【B】 |
| 四种仙露 | 10／25／80／200 点，可突破 100 上限 | 【A】 |
| 元宝恢复生命 | 200 元宝恢复到上限；满血拒绝扣费 | 【A】 |
| 生命为零 | 不能挑战敌人，仍可探索空格、拾取、开箱和传送 | 原文只限制战斗【A】；具体允许范围【B】 |

自然恢复不会把仙露带来的超上限仙力压回 100，也不会积攒满仙力时段供日后使用。跨日不再无条件重置仙力；多天离线按完整半小时补算。时钟倒退时保持此前观察到的时间，避免重算日刷新和自然恢复。

【B】生命是活动消耗池，不是直接替换每名上阵神仙的 HP。每场战斗使用当前真实阵容满血参与，生命扣除为：

```text
损失HP = max(0, 我方开战总最大HP - 我方战后总剩余HP)
生命消耗 = max(1, ceil(100 × 损失HP / 我方开战总最大HP))
失败／平局至少消耗20生命；生命最低为0
```

治疗和复活后的剩余 HP 计入结果。玩家可以通过养成和减少战损提高探索效率；失败后可以恢复再挑战，敌方不会因重新查询而变弱或换队。

## 5. NPC 阵容与难度【B】

只使用 [players/catalog.json](../analysis/npc_design/players/catalog.json) 绑定的 V1／V2 阵容，不修改这些资料文件。候选角色等级 24—90，排除资料中已标记 `replay_limit_observed` 的阵容。候选等级可低于活动开启等级，用于设计低层容易战胜的守卫；参加离线周榜的 NPC 则必须达到 36 级。

第 `f` 层的基础目标战力：

```text
P(f) = 8000 × (600000 / 8000)^((f - 1) / 59)
```

| 敌人 | 目标战力倍率 |
|---|---:|
| 铜钥匙守卫 | 0.65 |
| 银钥匙守卫／铜守关者 | 0.80 |
| 金钥匙守卫／银守关者 | 1.00 |
| 金守关者 | 1.15 |
| 本层守塔者 | 1.25 |

在候选池中选对数战力距离最近的阵容，相同距离以 NPC ID 排序。目标区间约为第一层守塔者 1 万至第六十层 75 万；实际数值取资料库离散阵容，**不强行缩放属性**。选定身份按楼层／格子存档，不按玩家战力动态追赶。

保留资料库阵位、前后排、装备计算后的属性、携带法术、精魄和九转战斗特性，走现有统一战斗引擎。战报敌方姓名显示“守塔·资料库姓名”。胜负、消耗和奖励均由服务端决定，不接受客户端声称的伤害／胜利。

## 6. 离线榜单与周奖【A／B】

【A】层数越高排名越前，同层按到达时间先后，周一结算。【B】从候选池中选出 30 名等级至少 36 的 NPC，按战力从低到高等间距采样。它们每周目标层数为 `5 + floor(i×54/29)`，`i=0…29`，即 5—59 层。

设本周已过秒数为 `elapsed`，某 NPC 的目标为 `goal`：

```text
interval = floor(604800 / goal)
当前层 = min(goal, 1 + floor(elapsed / interval))
到达时间 = 周一0点 + (当前层 - 1) × interval
```

这是确定性的离线进度模拟，不声称 NPC 已真实逐场战斗。玩家按本周最高到达层与首次到达该层时间参与排名，返回 31 人完整榜、本人的独立信息与上次结算榜。排序最后用角色 ID 消除完全相同时间的歧义。NPC 最高 59 层，玩家到达 60 层可取得第一名。榜上姓名与 ID 来自资料库。

【B】榜奖数量未恢复，采用以下通天币档位；榜单展示与邮件发放共用一个计算函数：

| 排名 | 通天币 |
|---|---:|
| 1 | 2000 |
| 2—3 | 1500 |
| 4—10 | 1000 |
| 11—30 | 500 |
| 31 | 200 |

发生过有效移动或战斗才视为本周参与，单纯打开界面不产生榜奖。新周结算上一个保存过参与记录的周，发放键为 `babel-rank-周号` 的永久系统邮件，随后重置层数、地图、敌人记录和通关标记。钥匙、工具、仙露、通天币及超上限仙力均保留。连续离开多周只结算上次参与周，不为期间未参与的周制造奖励。邮件重复查询／领取不重复发放。

客户端适配保留原版地图和排行控件，补上原 UI 缺失的 `rankData[页码].my_top_data`；没有上期数据时不绘制该行，避免空排名比较报错。榜单提示标明离线 NPC 和系统邮件领奖，最终通关会显示通知。适配支持重复安装和恢复，随本项目现有离线 Lua 注入加载，不修改 APK。
