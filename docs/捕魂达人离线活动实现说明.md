## 缺失服务端规则的补全【B】

集中配置：[hunt_rules.json](../server_config/hunt_rules.json)，要求 `mode=inferred`、版本号及有效数值，启动时校验。基础原版表直接读取，不把【A】数值复制成可随意调整的推测配置。

### 开放、地图与弹射

- 本地常驻开放，时间统一使用活动配置UTC+8。原版真实运营起止日期未获得。
- 首次参与获得当天400能量；按实际跨过的日期补充400／天并封顶1000。每日发射100次、免费刷新地图3次；次数00:00恢复，能量和未捕获神魂保留。
- 使用原 `ground.png` 的左侧圆弧、上下平边与右侧斜边形状，拟合服务端碰撞多边形。左弧中心 `(-360,280)`、半径275，以10°弦段近似；底／顶边为 `y=5/555`，右侧短边 `x=634,y=235..325`。这些坐标是图形推导，并非原服碰撞配置。
- 炮口从 `(0,-20)` 发射，进入地图时不在底边反弹。墙面镜面反射，最多执行“弹射次数+1”个飞行段；右侧短边设为吸收陷阱，触及后立即结束，保留本发已捕获收益。原文仅确认存在陷阱，位置、数量和作用均无法证实。
- 每色固定数量取 `base_count`，再独立以 `rand_weight/100=30%` 的概率增加 `rand_count=1`，每张图11—16个神魂。随机生成在地图内、离边至少35像素、彼此间隔至少65像素的位置。
- 轨迹与神魂中心的垂距不超过30像素且投影位于飞行段内即捕获；同一发同一个神魂只能计一次。未捕获的点持久化，清空地图后免费自动生成下一张图，刷新次数不减少。
- 基础收益为命中魂值之和；连击收益为 `floor(基础收益 × min(100,10×(命中数−1)) / 100)`。例如白+绿基础60，连击6，总收益66。

轨迹、捕获列表和收益全由服务端计算。客户端仅提交珠子与角度，不能提交中奖数量、积分或余额。示例轨迹按原版每秒500像素播放；服务端传的是原坐标，不是随机编造的动画点。

### 离线排行与结算

- 使用项目NPC资料库29名稳定身份作为本账号的竞争者；没有跨账号共享榜单或原服真人数据。每日NPC终值为400—2400的稳定散列数，当前日分按当天进度增长，周分按本周时间进度增长；同分按角色ID升序。NPC分数独立于玩家战力和分数，不跟随玩家变强。
- `soul`为可消费余额；`day_score/week_score`仅累计本活动实际捕获和连击收益。消费不减少累计分，兑换卡和宝箱不增加累计分。历史日／周榜保存各参与者已观测到的单日／单周最高成绩；这是对原版“历史”页的补全解释。
- 服务端在已参与角色登录、活动访问时惰性结算，不依赖后台定时任务。日榜邮件按参与日幂等保存，不为未参与的中间日期虚构分数或补奖。
- 上周榜正常在原界面领取，每期一次。超过下一次周结算仍未领取，转为永久系统邮件；长时间离线同样只结算有记录的参与周。此邮件兜底是离线便利规则，未发现原服是否补寄的证据。
- 周榜称号在新一周授予，生效窗口固定为该周一00:00至下周一00:00；重查和领奖不续期，超过窗口不补发过期称号。原版只明确持续1周，实际起算点属于【B】。
- 服务器时钟回退时不回退任何计数，捕魂操作拒绝执行；库存刷新和奖励不会因此重置。

请求1226：`serial_num=I,flag=B,count=I,index=I`，通过2998／155返回原版事件。

| 3 | 魂值换能量 | 更新余额和能量 |
| 4 | 刷新神魂 | 更新点列表和次数 |
| 5 | 商店 | `store_data.item_list` |
| 6 | 购买 | `item_index,buy_times,attach_list` |
| 7 | 刷新商店 | 更新库存、余额 |
| 8／9 | 日榜／周榜 | `my_order,top_list` |
| 10 | 上周榜 | `my_order,top_list,had_prize,had_got_prize` |
| 11 | 领取周奖 | `prize_list` |
| 12／13 | 历史日榜／周榜 | `my_order,top_list` |

活动状态1205／事件47下发 `hunt_data`，客户端自然显示入口与周奖提示。1036／1037／1324通过1051／事件21使用。无需注入捕魂界面补丁；客户端原有资源、教程、布局、按钮与回调均继续使用。

状态存储于 `role.activity.hunt`。旧账号没有该字段时独立初始化，不改写其他活动数据。账本、地图、库存、计分、结算记录与称号随账号存档持久化；依赖统一Backend的分离副本、编码后提交与请求序号校验，同包重试不重扣，错误参数或编码异常不保存半完成结算。

实现：[activity_hunt.py](../network_redirect/activity_hunt.py)、[activity_hunt_geometry.py](../network_redirect/activity_hunt_geometry.py)，入口修改位于 `activity.py`、`backend.py`。
