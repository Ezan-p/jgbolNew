# 日常模块规则与调试

更新时间：2026-10-29。配置版本：`daily-local-2026-10-29-daily-reset`。

## 当前规则

日常活跃度按北京时间（UTC+8）每天 00:00 刷新，同时重置任务已得分、总活跃度及五档宝箱领取记录。当天重新达到门槛后可以再次领取对应宝箱，每档每天最多一次。累计签到天数、累计签到奖励领取记录和最近签到时间保留，签到仍每天一次。

这是本次需求明确指定的本地规则，替代原版“活跃值累计周一0点重置”的规则。原包文案仅作为历史证据，当前客户端提示已同步为每日重置。其他模块使用的周一周期（如仙盟、财富榜）不受日常调整影响。

封神榜按服务端 `rank_count` 的实际增加计分；查询榜单、查看战报、购买次数、无效对手、精力不足和重放原包不加分。吃包子按当日 `activity.feed` 新增成功结算时段计分；查询（`feed_count=0`）、关闭时段、非法数量和同一时段重复提交不加分。同日参加第二个时段仍可获得活动本身的奖励，但日常活跃度维持 10 分上限。

## 刷新、迁移与持久化

- 以服务端时间和配置中的 UTC+8 时区划分自然日，与操作系统时区无关。在线跨日由心跳触发刷新；离线跨日由下次登录、查询或有效结算触发。未登录期间无须定时批量改写存档。
- 跨日时清空 `daily.points` 和 `daily.claimed`，总分重算为 0；随后发生的任务结算计入新一天。即使首个请求直接挑战封神榜或提交吃包子，也先按新日期重置再计分。
- 同日重启和重连保留当日分数及领取记录。奖励、积分和领取记录在同一角色事务中保存；发奖或回复编码失败时不提交整笔变更。
- 客户端不能通过上传积分、次数、时间或奖励内容修改服务端结果。相同原包返回缓存结果，不重复结算；持久化领取记录继续防止新流水重复领取。
- 旧周累计存档按 `daily.day` 迁移：日期已过期则清空积分及领取记录；日期仍为今天则保留当日 `points`，用其合计替换原周累计 `total`，移除旧 `week` 字段。
- 旧领取记录没有单独的领取日期；同日升级保留已有 `claimed`，避免更新时重复发奖。它会在下一次每日刷新时清空。本次不追溯补发已领取档位的差额，也不补算更新前的封神榜和吃包子任务积分。

## 客户端及协议

复用原版日常面板和宝箱交互，没有新增替代界面。客户端适配调整十一行任务间距，使其占用原九行任务区域；宝箱预览与领取布局保持原交互。说明文字在创建标签时替换，可覆盖原字节码提前缓存的 `gethz` 引用。

| 功能 | 请求／回调 |
| --- | --- |
| 打开日常 | 1347，`id=1`；返回事件 198，`id=1` |
| 领取宝箱 | 1347，`id=2, data={prize_id=数组索引}`；返回事件 198，`id=2` |
| 任务行 | `point_data`，每项包含 `desc / cur_point / point_limit` |
| 宝箱 | `point_prize`，每项包含 `point / status / prize_list` |
| 宝箱状态 | 1 未达标、2 可领取、3 已领取 |
| 红点 | 事件 198，`id=3, has_prize` |
| 每日日期 | 查询及红点附加 `local_day`，用于识别跨日的旧面板 |
| 签到查询／签到／累计领奖 | 1206，`checkin_type=1/3/2`；返回事件 54 |

跨日心跳更新红点后，已打开的日常面板检测到 `local_day` 变化会重新查询并渲染；已关闭的面板不主动打开。服务端发奖始终检查新一天的真实分数，即使旧界面尚未刷新也不能使用昨日活跃度领奖。

原版证据保留在 [original_strings.json](../analysis/evidence/daily/original_strings.json) 和 [audit.json](../analysis/evidence/daily/audit.json)。原版协议、枚举与字节码表现标为【A】，本地任务分值、时区、发奖与存档策略标为【B】；本次指定数值是用户定制规则，不代表官方服务器配置。原版只有任务 1–9 的枚举，新增任务 10–11 使用服务端下发的描述行展示。
