# 三星赐福离线活动实现说明

更新：2026-10-26。适用原版3.87客户端和本项目离线服务端。

【A】为原包协议、CSV或客户端字节码可确认的规则；【B】为原服资料缺失后的离线补全。没有官方服务端奖池，不能声称全部奖励和概率已完全还原。

## 玩法与原版依据

入口为“活动→三星赐福”。保留原版福星翻牌、禄星摇骰／揭碗、寿星刮奖以及领奖界面，不新增替代玩法。

- 【A】请求1030，回调事件42。`visit_index` 0查询、1福星、2禄星、3寿星；`op_type` 1抽取、2领奖。入口查询使用0／1，同时兼容旧离线查询0／0。其他组合拒绝。
- 【A】福星返回牌列表，每张有奖励信息和`get_flag`；客户端将中奖牌移到展示位置，最终只领取标记的一张。当前沿用8张牌。
- 【A】禄星用三枚骰子，客户端排序后匹配[luhsing_form_rate.csv](../analysis/configs/luhsing_form_rate.csv)：111为开门红×10、444为发发发×8、666为六六大顺×16；123、234、345、456均为同花顺×3，排列顺序不限。
- 【A】寿星抽取结果里的`object_type`和`attach_type`决定刮开后的图像、说明及奖励名称；法术必须返回`object_type=6`、`attach_type=法术编号`。刮到阈值后由原版客户端发送领奖请求。
- 【A】成就322对应福星获得装备；323／324／325／326依次对应六六大顺／同花顺／发发发／开门红。

证据：[loginGameUI字节码](../analysis/evidence/lua_named/lua/ui/loginGameUI.lua.txt)，原源码行123—195为回包分发，896—984为骰子展示及组合读取，1047—1248为刮奖，1450—1523为寿星领奖；[activityUI字节码](../analysis/evidence/lua_named/lua/ui/activityUI.lua.txt)原行1796—1812为入口请求；[成就原表](../analysis/configs/achievements_config.csv)。

原包`item_name.csv`还将4014—4021法宝和6005五星被动碎片标为“寿星玩法”产出。这证明存在历史产出文案，不能单凭文案确认当前实际奖池、概率或版本分支。本次没有据此制造官方奖池；在随机奖池缺失部分，按用户参考采用法术奖励。

## 离线补全与概率【B】

全部奖池配置在[visit_rules.json](../server_config/visit_rules.json)，`mode=inferred`。旧`activity_rules.json`中的固定福禄寿奖励与福星占位池已移除，避免两份配置互相覆盖。

| 项目 | 当前规则 |
|---|---|
| 次数 | 三位仙人各每日免费一次；按活动时区UTC+8的自然日重置 |
| 福星 | 每张牌先抽类别：蟠桃1001×5、银币10000、包子1022×1、精力丹1023×1、装备，各20%；装备从原表武器／防具／法宝中按品质抽取，数量1、等级1 |
| 禄星 | 三枚独立均匀骰子；基础银币10000，乘以原版组合倍率；非特殊组合×1 |
| 寿星 | 从原表54种可获得法术中抽取一本，等级1；主动和被动法术都可获得；排除1—10号内部战斗动作／占位技能 |
| 品质分布 | 装备和寿星法术均先按品质抽取：二星60%、三星30%、四星9%、五星1%；再在该品质内等概率选择 |

品质概率是**整个品质档的总概率**，不随该档法术数量变大。法术数量为二星2种、三星11种、四星21种、五星20种。新抽取的寿星只会给法术，不再固定给包子。

原版客户端有`can_visit`及未来可拜提示，但缺少服务端开放日历；每日三位均可拜沿用离线策略。福星具体奖池与装备比例、禄星基础银币和骰子分布、普通组合倍率、寿星法术范围和品质权重均属于补全值，不能当作官方概率。

## 图标兼容修复

原版[data.lua字节码](../analysis/evidence/lua_named/lua/data.lua.txt)原行705—714的`getBigSkillSprite`，在`skill/<法术编号>.jpg`缺失时返回字符串`skill/107.jpg`，而非精灵。原版刮奖把该结果直接传入`CCMenuItemSprite:create`，会报“string; CCNode expected”；实测五星法术21触发。

[visit_client.lua](../network_redirect/visit_client.lua)保留存在的大图；缺图时改取**同一法术编号**的背包图集图标，按原大图尺寸显示。仅在原版`gameShou`创建期间替换图像读取，结束或抛错都会恢复公共读取函数；不拿其他法术的图片充当奖励图。补丁通过现有登录配置注入，重启本地服务并重新登录后生效。

## 结算、存档与关联

- 抽取时固定奖励快照；重复抽取、查询、同日重新登录或重启不会重掷。
- 领奖才加入背包／银币，并记录已领取。法术按独立附件保存，能进入现有穿戴与升级流程。
- 成就322—326在真实领奖时记录；仅抽到、查询和重复包不增加次数。日常任务8沿用现有成功领奖计分。
- 同序列重放复用原响应；新序列重复领奖、未抽先领、非法参数拒绝。编码失败时不提交扣发和领奖状态。
- 旧存档中已抽出的福星／禄星结果不变；旧寿星只有`prize_info`时按已展示信息领取一次，即使旧结果是包子也不强制换成新法术；下一次新抽奖使用新规则。
- 沿用原离线日切：午夜清除当天未领奖结果，不自动补发；服务器时钟回拨不恢复次数。此日切处理属于【B】。

实现：[activity_visit.py](../network_redirect/activity_visit.py)负责配置、奖池和两阶段结算；[activity.py](../network_redirect/activity.py)保留入口分发、日切和活动状态；[achievements.py](../network_redirect/achievements.py)接入领奖增量。
