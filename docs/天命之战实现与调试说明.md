# 天命之战实现与调试说明

更新日期：2026-10-26。适用原版 3.87 客户端与本项目本地服务端。

## 1. 本次范围与还原边界

按本次确认的范围：**各关敌阵、掉落、强度保留原有离线配置，暂不重新设计**。本次补齐外围流程、后续关卡推进、战魂结算、祝福／祭魂、领奖、重开、两种半程继续、持久化、跨日、排行、榜奖、称号和成就联动。

已取消原有第30关封顶，31关以及40、60、80、100关之后均沿用同一套完整流程。这里的“后续关卡”指流程能够继续，并不表示已经取得或复刻了这些关卡的原服敌阵。

原包能证明的规则标为【A】；现有离线数值和缺失原服算法的本地策略标为【B】。旧攻略只作历史佐证，单独标明。**本实现不能称为原服数值的完整复刻**：原服关卡表、祝福公式、祭魂随机池与消耗表尚未取得。

该历史记录还描述过3%／15%／30%的随机祭魂效果，但原包未提供其抽取概率、费用及3.87对应表，因此此次没有凭此新造随机池。

## 3. 游玩与状态流转

1. 从活动／异事进入天命，查询只展示当前状态。
2. 开始新挑战扣一次每日额度，选择初始祝福，再选择一／二／三星难度。
3. 服务端独立计算战斗结果；客户端不能提交胜负、伤害或奖励。每场重新生成战斗用属性，临时祝福不会写回永久神仙属性。
4. 胜利累计战魂并进入下一关。每过3关进入领奖，领取后选择一次祭魂效果，再继续战斗。
5. 失败或战斗在引擎安全边界内未分出胜负，结束本轮。还有次数且有可恢复快照时显示半程选择；次数耗尽则显示结束入口。
6. 次日重置3次额度，保留昨日最好成绩和半程快照，提供从头或半程开始的选择。

| 存档阶段 | 查询结果码 | 允许的后续操作 |
|---|---:|---|
| 无挑战 | 2 | 开始；有昨日快照时返回12等待选择 |
| `initial` | 1 | 选一次初始祝福 |
| `fight` | 3 | 挑战 `cur_round+1` |
| `prize` | 6 | 领取当前待领银币 |
| `exchange` | 5 | 消耗战魂选择保存的祭魂选项 |
| `finished` | 11 | 从头或半程重开；没有剩余次数时返回7 |

战斗过程中结果8供原版胜利回调使用；败退使用11进入半程面板，不能继续时使用9进入原版结束页。战斗数据包和活动数据先到达，事件44最后触发原版播放／结束处理。

## 4. 保留的数值与半程策略

以下是【B】旧离线基线，不是新增的原服关卡设计：

| 配置 | 当前值 |
|---|---|
| `battle_npc / battle_level` | 1001／1，继续与原活动配置共用 |
| 守卫四维 | 原基础属性 × 当前关号 × 难度；沿用旧公式 |
| `duty_silver_per_round` | 1000；每过3关领取3000银币 |
| `duty_initial_bonus` | 10%，从旧硬编码提取为配置 |
| `duty_exchange_cost` | 3战魂 |
| `duty_exchange_bonus` | 10%；四维任选一项，保留旧配置 |
| 额外元宝、乾坤袋等关卡掉落 | 保留原先未配置的状态，本次未新设掉落 |

初始祝福数值仍为旧配置10%；虽然原版文字指出它与昨日最好成绩相关，但具体公式尚缺，**没有声称已经恢复动态九梵祝福公式**。祭魂暂保留旧四选一配置，接口已经按服务端选项数组执行，后续有原表时可接入不同费用／属性／效果。

半程起点保留旧取整基线 `max(1, floor(已通关数 / 2))`，解释为下一次挑战的关号；取该点或更早可用的真实快照。例如新实现从头打完15关，会从第7关继续。原服具体取整算法尚无证据，该数值策略仍为【B】。

与旧实现不同，半程恢复会取回该点实际保存的战魂、已花战魂、初始祝福和祭魂加成，不再用个人历史关数配一组零加成。跳过部分不再次发银币；重打部分仍按新一次挑战结算。本轮半程只用本轮快照；昨日半程只用紧邻上一自然日的最好单次成绩快照。

从头重开清空本轮战魂和加成，不清除当天最好成绩；两种半程继续也各扣一次每日额度。重开必须在本轮结束后，昨日选择仅能在当天第一轮之前执行。

## 5. 本地排行、榜奖与联动

榜单只纳入当前数据库中真实本地账号的实际天命成绩，**不生成 NPC 成绩**。仅一个账号参加时，榜上也只有这个账号。它不连接旧官方服务器，不是官方全服或跨服榜。

【B】本地排行政策：每人每日取最高单次战魂成绩；同战魂比较该次关数，再按内部账号键稳定排序。分组使用该轮开局时的阵容容量，避免临时下阵改变分组。预估名次实时计算；未参加时为0。每日最好关数和战魂来自同一次成绩，历史最高通关数另存，供通关成就使用。

旧账号的游戏角色ID可能都为1，因此榜单查看阵容使用稳定的只读查询别名，避免点其他人却打开自己的阵容。别名不修改实际角色ID。界面只展示角色名；内部账号键不下发。角色查看包含当前上阵神仙、装备、法术和助阵信息。

次日首次成功活动请求或登录时，按上一日真实榜单结算奖励，金额直接来自原版 `duty_topprize_config.csv`：

| 分组 | 第一名元宝 | 最后一档有奖名次／元宝 |
|---|---:|---:|
| 4人 | 250 | 20／50 |
| 5人 | 300 | 20／60 |
| 6人 | 350 | 20／80 |
| 7人 | 450 | 20／100 |
| 8人 | 700 | 50／50 |

全部中间名次数值也直接读原表。原界面没有单独的天命日榜领取请求，所以本地采用自动入包【B】，并保存结算日、名次与金额；查询、重连、重复包均不能再次获得。长时间离线只补结已有参战记录的日期，不为未参战日生成奖励，不修改其他账号的余额或存档。

联动如下：

- 一轮结束触发天命日常活跃任务及成就104；查询、领奖、祭魂不计完成轮次。
- 实际打过20／40／60／80／100关，触发426—430。
- 日结有奖上榜／第一触发216／217；连续有奖上榜触发431—439，中断日期会中断连榜计数。
- 日结前10名按原表授予110—113称号。有效期按结榜日计算24小时，延迟登录不会重新延长称号。

## 6. 存档、安全与兼容

主要状态：

- `role.activity.duty`：当前轮、下一关 `round`、战魂、已用战魂、两类加成、阶段、待领银币、祭魂选项、检查点、开局分组。
- `role.activity.duty_meta`：版本、日期、单调时钟、每日最好单次成绩、昨日快照、逐日榜奖结算记录、连续上榜记录。
- `role.activity.duty_best`：历史最高实际通关数，兼容原成就读取。
- `role.activity.duty_runs`：当天已用挑战次数；对客户端返回的是剩余次数。

每天北京时间00:00切换。先保存昨日成绩、处理已经赚到但未点领取的银币，再清空当前挑战和次数；旧待领银币只处理一次。日期或服务端时间倒退不能重置天命次数或领取记录，天命操作会明确拒绝，恢复时钟后可继续。

旧存档保留现有战魂、已用战魂、加成、进度与待领奖励；不会把旧星数按新倍率追溯增发。旧存档没有的历史半程快照不编造，无法安全还原时可从头重新挑战。旧30关版本已标记结束的轮次也不凭空推断胜负历史。

沿用后端“角色副本上执行→编码成功→保存”的事务边界。无效阶段、越关、伪造目标、无效难度、重复祝福、星数不足、重复领奖、额度不足和编码失败均不提交结算；原请求序号重放返回缓存。战斗模拟的超时结果不算胜利。

没有新增玩法关数上限，但协议整数和战报大小仍有技术边界；极端数值导致编码失败时会回滚，不能据此承诺数学意义上的无限关数。
