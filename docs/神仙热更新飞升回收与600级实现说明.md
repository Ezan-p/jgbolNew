## 3. 飞升1～499

### 3.1 消耗、潜力与上限（A）

`cortege_evolution.csv.level`表示**本次完成后的飞升次数**。因此299→300查第300行；498→499查第499行。消耗对应神仙自身魂魄，每次成功立即增加相应潜力；500档不存在。

| 目标飞升次数 | 单次魂魄 | 单次新增潜力 | 覆盖 |
|---|---:|---:|---|
| 300～399 | 1,000 | 320 | 一星至五星 |
| 400～499 | 1,200 | 400 | 一星至五星 |

300～499共200次，合计消耗 **220,000魂魄**、增加 **72,000潜力**。从0完成到499次合计消耗 **390,910魂魄**、增加 **127,180飞升潜力**；这里不包含升级潜力与转生返还。

注意：原潜力CSV有2～5星各一条`level=0`数据。因此文件2499行不等于2499个可飞升档位，累计只能取`1..499`，不能直接把同品质整列相加。实际每品质有效飞升档位499条，1～499累计潜力相同。

### 3.2 直接属性（公式A，完整乘区B）

原飞升界面逐项计算：

```text
单次直接成长 = floor(该神仙对应原始成长 × 3)
累计直接成长 = 单次直接成长 × 当前飞升次数
```

生命、攻击、防御、法力分别计算。先取整再乘次数，不改为最后统一取整。潜力另行保存，不自动作为已培养属性。`combat_power.py`每次按当前`evolve_level`重算，回收后直接飞升成长自然消失。

公式和显示增量属A；飞升与装备、转生、仙缘等完整乘区顺序沿用既有本地属性模型，属B。详见[养成原版数值核对](神仙养成原版数值核对与修复.md)。

### 3.3 请求与失败处理

使用原协议`1084 / flag=0`，成功仍返回event 50及神仙状态。魂魄不足、已到499、存在待确认培养结果均拒绝。失败不保存变更，同一会话内相同请求重放不会再次扣魂魄（事务与重放策略属B）。

### 4.2 潜力与培养回退（B）

沿用现有离线回收策略：

```text
总潜力预算 = 未使用潜力 + 四项已培养加点之和
飞升潜力 = 原潜力表从1累计到当前飞升次数
回收后未使用潜力 = max(0, 总潜力预算 - 飞升潜力)
四项已培养加点 = 0
飞升次数 = 0
```

此策略允许回收已经培养过的高飞升神仙，并防止再次飞升重复获取同一批潜力。它会把保留下来的普通升级／转生等潜力还原为未使用潜力，**不会保持原培养属性分配，也不额外返还培养消耗**。原表只证明材料和界魂数，不能证明这一服务端回退算法；因此明确标B。

例：499次飞升，有127,103未使用潜力、100已培养属性时，总预算127,203；回收扣除127,180，留下23未使用潜力，培养加点清零。已不足以覆盖飞升潜力的异常旧数据按0截断，不产生负潜力或额外补发。

## 5. 神仙等级最高600

### 5.1 当前等级上限（A）

原`expbookUI.getMaxLimitLevel`以200为基础，读取主建筑`coretege_limit_plus`；五品质经验表独立限制最高支持等级。

```text
主角等级 ≥ 80：min(经验表最高等级600, 200 + 主殿上限加成)
主角等级 < 80：再与 主角等级 × 3 取最小值
```

| 主殿等级 | 上限加成 | 主角≥80时神仙上限 |
|---|---:|---:|
| 0 | 0 | 200 |
| 20 | 100 | 300 |
| 21 | 110 | 310 |
| 30 | 200 | 400 |
| 40 | 300 | 500 |
| 50 | 400 | 600 |

主殿1～20级每级加5，21～50级每级加10。主角79级即使主殿50级仍最多237级；主角80级且主殿50级才能达到600。

后端优先从存档中主殿等级读取加成，不依赖玩家重新进入洞府刷新缓存。旧测试／无洞府状态角色仍兼容既有`cortege_limit_plus`字段；一旦存在洞府存档，以建筑事实为准。
