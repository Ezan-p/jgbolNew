# 猎魂之地离线活动实现说明

更新：2026-11-10。

2026-11-10最新调整【B】：保留铁脊塔、天风塔守卫；地元塔由T2大幅降至T4，千魂塔由T3大幅降至T5。两座低阶塔在四张地图的最强新候选，均低于对应调整前最弱候选的40%。同日未占领旧塔在下次活动访问时更新守卫，正在占领的塔在结束占领后更新；资源与计息不重置。

2026-11-09调整【B】：普通／冥界首领在2026-10-30版本基础上均增强约2倍；翻牌新增精魄石×10／×20，未达上限时合计概率35%，普通最多2张、冥界最多1张；每周一UTC+8零点重置双塔与地图进度并邮件结算周榜；占塔、游历分档，守塔NPC改用更高等级的完整阵容。

猎魂之地对应原版 `landUI`、1302／事件149；仓库旧代码与文档称它为“逐鹿”。它与 `soulHuntUI`、1226 的“捕魂达人”是两个活动。本次完善猎魂之地，保留原版界面、游历、占塔、组队、普通／冥界首领、翻牌、符咒、扫荡与榜单流程。

**【A】**：原包 CSV、协议或客户端字节码能够证实的规则。**【B】**：服务端缺失后的推测、已有离线规则及本次离线适配。NPC 资料、模拟进度、匹配与协作行为统一归入【B】，不另设“C”或冒充原服规则。

## 进入与完整玩法

更新后重启本地游戏服务，继续使用 [启动本地离线游戏.command](../启动本地离线游戏.command)，无需重建 APK 或重新创建账号。保留已有38级入口门槛【B】。

1. 每天 UTC+8 的00:00—18:00游历，每天30轮【B】。原版界面固定4个头像位【A】；本地每轮显示2—4位候选【B】，选择一名本地 NPC 挑战，或撤退结束；重复查看同一轮不扣次数。
2. 胜利按地图获得100／200／350／500魂力和随机属性的5%符咒【B】。一键游历一次最多5轮，逐场用真实引擎计算，只有胜利才给奖励；没有选择战斗或撤退前，不允许另开批量游历。
3. 使用魂力挑战普通首领，首胜后翻牌、领取奖励并进入下一层。普通5张、冥界3张牌【A】；已有离线费用依次为0／20／50／100／200元宝【B】。每个位置只能领取一次，满翻附加奖励；再次挑战已通关层只更新更好的成绩，不再生成首胜牌。
4. 按原表解锁阵位、地图和符咒槽【A】。装上符咒降低战斗难度；减少参战人数、减少装备符咒可获得更高的首领挑战积分。
5. 普通／冥界（正塔／逆塔）各64层【B】。正塔完成翻牌结算、进入下一层后，对应逆塔层免费自动开启；未达到正塔条件时，可消耗100魂力提前开启当前逆塔层，逆塔仍需逐层挑战【B】。冥界每层每天3次挑战；普通与冥界战斗均消耗“层数×10”魂力【B】。普通已通关层每天可扫荡一次。
6. 18:00—24:00占塔，每天共5次攻打／进入机会【B】。铁脊塔保留组队入口，天风塔、地元塔进行单人战斗，千魂塔保留直接进入及自动占塔的离线流程。
7. 占塔按千魂／地元／天风／铁脊塔分别每分钟10／20／40／80魂力，每塔600／1200／2400／4800魂力，每次最多一小时【B】。离线补算截至塔到期、资源耗尽或当天午夜，不会重复计息。没有在线玩家抢走资源。
8. 查看普通榜、冥界榜、周魂力榜及最近30条活动日志。周一UTC+8零点换周；登录、重连、心跳或活动请求触发旧周结算与双塔／地图重置，奖励发入系统邮件。

首领、翻牌、符咒和查询不受日间游历／晚间占塔时段限制。千魂塔为无需战斗的魂力来源；低战力玩家也可逐日积累资源。自动占塔只在本地访问触发，不模拟长期离线时连续多日自动入塔。

## players NPC 与离线交互【B】

入口为 [players/catalog.json](../analysis/npc_design/players/catalog.json)，通过统一 [npc_players.py](../network_redirect/npc_players.py) 解析资料及其引用的原始阵容。**不再直接将 v1 目录作为活动候选库**。

当前资料库共有1725人，覆盖 v1／v2；排除16个已有 `replay_limit_observed` 标记的模板，1709人可参与活动匹配。`not_sampled` 仅表示原设计未逐个做战斗抽检，不能理解为全部复杂组合均已验证。所有 NPC 使用保存的姓名、角色ID、神仙、装备、法术、精魄和命星；先按正式角色结算器重算战力，不额外缩放四维。守塔战力通过地图等级、模板T档与完整阵容分档，11月10日地元／千魂降为T4／T5。资料库保持只读。

### 游历与守塔

游历依据已开阵位的双方战力，循环寻找玩家战力55%／80%／105%附近的模板，候选等级不超过玩家等级。初期可遇到低等级 NPC，提供弱队的起步选择。每个候选排除本轮已选角色，同轮没有重复人物；相邻轮交替选择最近的两个候选，当前轮名单存档，重启不重抽。百分比是匹配目标，不是精确战力或胜率承诺。

四张地图的守塔者改为50／70／90／99级模板；铁脊／天风／地元／千魂塔分别采用T1高段／T1低段／T4／T5档。守卫使用完整阵容（最多8位），不再随玩家已开阵位截断。按日期在对应池内轮换；同一地图所有候选的战力区间严格分档，高档最弱者也强于下一档最强者。千魂塔仍直接进入，NPC仅展示；铁脊塔仍需组队。本次仅将未占领的地元／千魂旧守卫更新到新池；铁脊／天风已有守卫保持原样。玩家正在占领时先保留，结束占领后更新NPC。剩余资源、收益率、计息时钟、次数与地图进度均不因换守卫而重置。详见下方守塔明细。

为了兼容原界面与旧请求，游历使用942001—942004、队友使用940001—940003、塔主使用940100＋塔ID这些**场景编号**；同时保存 `npc_id` 与资料库真实角色ID。阵容详情返回同一人的资料与实际阵容，不读取其他账号。榜单直接使用资料库角色ID。

**头像点击修复【A】**：`landUI` L1767将数组序号作为头像菜单 `tag`，L1807原样送入1302／4的 `des_id`。服务器现在优先将1—4解析为当前轮的目标序号，同时兼容旧场景编号；不能使用其他轮、越界序号、布尔值或小数目标。L1783“查看阵容”读取 `enemy.role_id`，响应已补上该字段，指向对应场景编号，并保留真实身份 `npc_player_id`。塔详情和队伍成员也补齐这个关联字段。

旧存档已有游历再次打开时保留前4名可见目标、既有次数和身份，不额外扣次数；不再生成第5—8名隐藏候选。

### 组队与战斗

首次进入保存三位不重复的候选队友；玩家升级、跨日和重启不会换人。原版1303／事件145支持创建、申请、接受／拒绝、清空申请、列表／详情、离队、解散、踢人、换位、锁定／解锁。队伍最多3人【A】，玩家自己占一席。

NPC 立即申请或接受邀请；申请 NPC 队伍后将指挥权交给当前玩家，不等待真人响应，不允许把指挥权交给 NPC 后造成无法操作。占塔时不能调整队伍。队员和申请列表的战力随当前已开阵位重新展示，但身份不变。

铁脊塔协作战斗使用每名队员的前 `min(已开阵位, floor(8/队伍人数))` 名神仙，按成员顺序组成最多8个单位，实际参与同一场战斗。保留队员自身装备、法术、精魄和命星；共享玩家本场猎魂符咒加成，以及本地引擎对己方队伍施加的修炼／仙阵战斗效果。收益归当前账号。这是【B】协作规则，并非原服多场接力复原。

NPC 队员进入战斗时采用独立内部神仙编号，避免资料快照中的神仙ID与玩家ID重合后，被引擎覆盖为玩家的精魄／命星效果。这个编号不写回资料库，也不改变 NPC 的角色ID。

塔详情在玩家占领后展示玩家／实际队伍、对应人数、头像和参战部分基础战力，不再展示原守塔者的战力。符咒和引擎内临时效果不计入该基础战力。

## 首领积分与显示修正

原版 `landUI.calcFightScore` 的最高层分默认3000，按照参战人数和装备符咒数量扣分【A】：

```text
人数扣分（1—8人） = 0, 150, 300, 420, 480, 600, 750, 900
各类符咒扣分 = floor((数量 + 数量^1.2) × 0.5 × 系数)
攻击／防御／生命／法伤系数 = 20／25／15／30
本次得分 = max(0, 3000 - 人数扣分 - 四类符咒扣分之和)
```

仅统计已解锁、已开启且装备该属性的槽，扣分取决于数量而非符咒百分比。证据为原版字节码L117—123、L2047—2076及对应数字常量池；服务端现在按该公式结算，返回 `max_level_score=3000`，与客户端预览一致。

同层保存最高分及取得该最高分时的人数【B】。低分重打不覆盖最佳人数、不重复累加总分；普通／冥界历史分别保存。客户端上报的胜负、积分不作为结算依据。

## 镇妖塔64层首领补全

原版提取配置中只找到猎魂的地图、符咒、阵位及周奖表，未发现逐层首领映射；`data`加载器也未读取这种表。`landUI`首领展示使用服务端 `type_id`，缺省外观为5001阎罗王【A】，这不能证明所有层本来都是阎罗王。因此按用户要求采用以下缺失逻辑补全【B】，不宣称复原了原服名单。

- [land_boss_rules.json](../server_config/land_boss_rules.json) 明确保存64层名单，64位首领名称和神仙类型均不同。从小妖、天兵等低阶对手，逐步推进到妖王、神将和佛祖，第64层为如来佛祖。普通和冥界采用同一组身份，冥界强度更高。2026-11-09在原有基线完成递推后，将正塔全部单位四维乘4、逆塔全部单位四维乘8，再重新计算战力；相对2026-10-30的2／4倍率，双方都再增强约2倍，主怪和护卫均只乘一次。
- 类型、形象、中文名、基础四维、成长系数及初始技能使用原版神仙表【A】；名单、顺序、等级及以下成长处理为【B】。普通首领等级为 `3＋6×(层数−1)`，冥界为 `4＋8×(层数−1)`；初始技能保持1级。相较2026-10-27版，首层等级仍为3／4，逐层等级增量由3／4翻倍至6／8。
- 先通过 `journey.fighters` 按原神仙模板计算四维并结算初始被动，再对每项四维乘115%向下取整。第二层起，每项四维再取该结果与“上一层首领对应值×103%向上取整”的较大值；普通／冥界分别递推。原来仅保证比前层＋1，现在保证生命、攻击、防御和法伤各项至少增长3%，避免换模板后某项属性长时间停滞。
- 阵容人数为 `min(8, 1+floor((层数−1)/8))`，每8层增加一位护卫；首领在1号位，护卫依次采用前几层首领的身份、属性和技能。例如第64层为如来佛祖，加上第63—57层首领。不会在同一队中复制8个同名神仙。
- 整队基础战力逐层严格递增，同层冥界高于普通。不同技能有不同克制关系，因此基础属性更强不意味着对所有玩家阵容都有完全相同的胜率变化。
- 逆塔开启支持正塔进度自动开启和魂力提前开启。原版 `landUI` L2410读取 `unlock` 决定是否显示付费解锁按钮，`is_open` 表示是否已经开启；原包文案 `land58` 提示“镇魂塔正塔通关%d层时自动开启”，`land_tip5` 则提示“需通关第%d层镇魂塔”【A】。服务端补齐 `unlock` 字段，并按已有离线规则将 `unlock_layer` 设为同层、提前开启费设为100魂力【B】；付费提前开启无需先通过正塔，但不能跳过逆塔前置层。重复解锁、魂力不足和无效层数不会扣费。
- 同一周内，旧存档进入活动时按正塔已通关层数免费补齐逆塔开启状态，保留已有付费开启层、逆塔通关进度和历史记录；跨周则统一重置。每层每日3次挑战限制不变，重启和周内跨日不会重新锁定；跨周重置开启状态。

### 当前正塔、逆塔战力与计算口径【B，2026-11-09】

配置版本：`land-tower-power-2026-11-09-v5`。原版未提供逐层首领属性、等级及两塔倍率表，以下为离线设定，不代表原服数值。普通与冥界同层身份相同，冥界更强。界面预览、历史查看与实战都读取 `activity_land_encounters.py` 的同一份配置。

```text
普通等级 L = 3 + 6 × (层数 - 1)    # 3 → 381
冥界等级 L = 4 + 8 × (层数 - 1)    # 4 → 508
模板四维 = max(1, floor(原表基础属性 + 原表成长系数 × (L - 1)))
T = journey.fighters 结算模板及原始初始技能被动后的四维
首层基线属性 = floor(T × 115 / 100)
后层基线属性 = max(floor(T × 115 / 100), ceil(上一层对应基线属性 × 103 / 100))
敌方人数 = min(8, 1 + floor((层数 - 1) / 8))
护卫 = 前面相邻若干层首领，沿用各自原层基线属性
正塔最终四维 = 各单位基线四维 × 4
逆塔最终四维 = 各单位基线四维 × 8
倍率仅用于最终阵容，不带入逐层递推；护卫不重复乘倍率
单个单位战力 = floor(生命×0.2 + 攻击×3 + 防御×2.5 + 法伤×1.5)
整队战力 = 各单位战力之和
```

相对上一版正塔×2／逆塔×4的最终属性，本次两塔所有首领和护卫四维均精确翻倍；显示战力逐单位取整，因此可能比“旧显示战力×2”多几个点。等级、身份、法术和人数不变。

### 魂力收支口径

- **收入**：胜利游历与占塔计息，均计入当周累计获得魂力；余额可跨周保留。
- **支出**：普通／冥界每次首领战消耗层数×10魂力，1—64层各打一次分别20800，双塔共41600；失败仍扣战斗费，重打另计。正塔推进后同层冥界免费开启；提前开启每层100魂力，64层全部提前开启最多6400。
- **成长**：第3—8阵位依次花费300／500／800／1100／1400／1800，合计5900；已开阵位跨周保留，不重复收费。符咒槽的开启、提前解锁与合成转换依原表；卸换已装备符咒每次10魂力。所有消费不扣周榜累计成绩。
- **其他奖励**：翻牌产出精魄、碎片、精魄石；满翻附加蟠桃×20；普通扫荡每个已通关层蟠桃×10＋精魄石×5。它们均不增加魂力或周魂力分数。周榜邮件也不包含魂力。

## 排行、周奖与称号

### 固定本地榜单【B】

首次进入，从等级至少38级的候选中按“等级、完整阵容战力、NPC ID”排序，等距选取60人并存档。玩家与60名固定 NPC 排名；最多展示前50名，同时返回玩家真实名次。玩家是否在榜单前50名不影响周奖计算。

- NPC 普通进度：`min(64, max(1, floor(等级/2)+(5−T档数字)×7))`；冥界进度为普通进度减12，最低0。
- NPC 普通／冥界分数：对应层数×2100。普通／冥界榜按层数降序、积分降序、角色ID升序。
- NPC 日魂力：`100 + 等级×5 + (5−T档数字)×100`；周内按已过去秒数线性累加，周末按完整7天计算。
- 周榜按本周累计**获得**的魂力降序、角色ID升序。花掉魂力不降低成绩，也不能通过预置高余额直接进入周榜。

### 每周刷新与周奖

以服务端活动时区UTC+8为准，每周一00:00换周。在线由跨周心跳触发，离线在下次登录／重连／活动访问时补执行，不依赖打开猎魂界面，不运行离线后台定时任务。

执行顺序：①将旧占塔收益补算到塔到期、资源耗尽或旧日午夜；②按旧周累计魂力计算名次并投递邮件；③将周成绩归零，重置双塔和地图；④恢复新一天次数。长时间离线只结算保存的最后一个参与周，不为缺席周生成奖励。

| 状态 | 换周处理 |
|---|---|
| 普通／冥界通关层数、历史积分、总积分 | 全部归零，重新从第1层挑战 |
| 当前地图与地图解锁门槛 | 返回凡俗之地；按本周普通通关16／32／48层重新开放其他地图 |
| 冥界开启状态（含付费提前开启） | 清空；新周重新按条件开启 |
| 普通／冥界待翻牌及已翻牌位置 | 清空；未翻牌不自动发奖、不退款，须在周一零点前领取 |
| 占塔归属、资源池、未结束游历 | 清空；新塔按新地图／新日重新生成 |
| 游历／攻塔／冥界次数、扫荡标记 | 按新一天重置；须重新通关才可扫荡 |
| 魂力余额、背包物品、已开阵位、符咒槽与装备、符咒库存 | 保留，已开成长无需再次解锁 |
| 固定队友、队伍、NPC榜单名单、自动占塔设置、邮件、称号达成记录 | 保留；普通成就称号不因每周重打而续期 |

## 持久化、兼容与资源边界

所有活动数据保存在当前账号：魂力、已开地图／阵位、符咒库存及装备、两套首领历史、待翻牌奖池、已领取位置、队伍、NPC名单、占塔时钟、周成绩与奖励状态。

- 待翻牌奖池在胜利时生成，同周跨日和重启不重抽；同一位置、同一周内同一首胜、满翻额外奖励均不能重复领取。跨周清空待翻牌，重新开启首胜。
- 周内跨日重置游历／攻塔／冥界挑战次数和每日扫荡；保留成长、队伍和待翻牌奖励。跨周另按上表重置镇妖塔与地图。
- 时间早于活动已记录时间时拒绝活动／组队请求，不倒拨日期刷新次数。本地文件可自行编辑，因此不将此机制描述成防修改存档系统。
- 旧 v1 游历、队员、申请及塔主保留其 `npc_id`、场景编号与当前状态，更新为 players 资料；不重置消耗、背包、周魂力或待领奖励。
- 旧积分曾使用“层数×100＋人数奖励”，与原版公式不同。一次性迁移保留 `legacy_score` 供核对；新分取“旧分与该人数无符咒最高分的较小值”，重新合计总分【B】。旧战斗未记录当时符咒，不能准确倒推；迁移不增加旧分，之后可重打提高成绩。
- 沿用 Backend 离线副本、编码成功后保存机制。资源不足、非法目标、越界请求、重复领奖及编码失败均回滚；同会话相同序号请求返回已缓存响应。
- 战报保留原版嵌套 `final_result_list`、战斗类型21、额外战斗事件。最多80动作、额外事件预算4000字节（全局配置更低时取更低值）；容量耗尽时保留未决结果，不冒充胜利。
