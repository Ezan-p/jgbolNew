## 独立 Lua 虚拟机集成验证

执行：

```sh
.runtime/venv/bin/python -m observability.tests.live_lua_smoke
```

这是**可选的主动集成测试**：需要游戏与 Frida 服务端正在运行。它在目标进程中新建一个独立 `lua_State`，运行测试字符串后销毁，不使用游戏业务虚拟机，不加载业务资源或访问服务器。

通过会话：`.runtime/observations/20261023T142031Z-b584d1cc/`。

实际捕获：

```text
lua_load: @observer-smoke.lua
lua_print: JGBOL_OBSERVER_SMOKE\t42\ttrue\tnil
lua_pcall_error: observer-smoke.lua:1: expected observer smoke error
lua_load: @observer-invalid.lua
lua_load_error: observer-invalid.lua:1: '<name>' expected near '='
smoke_passed: 独立 Lua state 实测通过
```

同时验证：初始化栈顶为 0，合法 chunk 加载返回 0；预期运行错误返回 2、栈顶为 1；预期语法错误返回 3、栈顶为 1。输出参数与 chunk 名必须精确匹配，因此也覆盖原生字符串边界读取。

首次测试暴露了按固定长度读取 C 字符串会越过终止符的问题；实现已改为 C 字符串扫描到 NUL、Lua 字符串读取 API 返回的真实字节长度，再应用大小上限。失败时生成的测试日志已删除，修复后的集成测试通过。
