# 太虚幻境：历劫与血战离线实现说明

更新日期：2026-10-27。规则版本：`offline-taixu-3`。

本次范围为「活动 → 太虚幻境」中的历劫关卡及同入口的独立血战。关卡保留原版九大关、每关九小关及固定守卫；血战中的真实玩家、跨服匹配、排行榜和交互改为本地 NPC。没有依赖官方服务器，也不修改 NPC 资料库中的原始养成数据。

## 1. 如何游玩

原版外层入口与商店**12级**开放，历劫地图与战斗**50级**开放。本次等级审计已修正此前将整个入口统一挡在50级的实现：1349操作3／5按12级检查，其余历劫操作按50级检查。血战当前仍采用既有离线方案的50级起四组，原版门槛来自服务器分组参数，不能称为原包固定50级。旧存档保留。依据与完整等级表见[游戏玩法等级开放说明](游戏玩法等级开放说明.md)。

### 历劫

1. 进入地图，先完成第一大关的「挑战」九小关。
2. 点击左上角切换「历劫」，长按下方神仙头像，拖入九宫格布阵。
3. 在同一大关内依次完成历劫九小关，再开启下一大关挑战。
4. 神仙历劫每日最多上场4次，需要轮换阵容；每日零点恢复次数，同时把**当前大关**的小关进度重置到第一小关。
5. 已完成的历劫大关每天可以领取一次仙晶，支持地图上的单关领取和一键领取。
6. 在仙晶商店兑换物品，商店限购每天零点重置。地图新增「刷新历劫进度」入口，跨日或长时间停留后可主动刷新。

挑战每天10次、每次消耗2体力；限时历劫不消耗体力。胜负都消耗本次挑战额度或神仙上场次数。历劫当前大关从首次实际出战开始计时72小时，失败停留当前小关；超时退回前一大关第一小关。多次超时按完整72小时周期继续回退，最低第一大关。普通挑战已经取得的进度保留。

首次进入下一历劫大关时，计时尚未启动，可以先准备阵容。历史通关的每日领奖资格、首次奖励记录永久保留。计时起点、失败不退小关及历史领奖资格的保留是本地补全规则。

### 血战

进入血战后选择自己的等级组。比赛顺序为：

**冲榜 → 练习 → 血战第一阶段 → 血战第二阶段 → 血战第三阶段 → 结算。**

每阶段至少打过一场后，点击右上角按钮推进。可以先用完本阶段免费次数，也可以提前结束阶段。血量耗尽后允许推进，避免被困在无法战斗的阶段。血战布局按用户最终要求恢复到本轮修复之前的版本：继续调用原版冲榜、练习、血战和排行面板，保留原位置、比例、美术及既有顶部离线状态/推进按钮。点击顶部状态文字查看规则，本轮尝试的两套新布局均已撤回。

原版按周三、周五、周六开放并穿插休战期；离线版取消这些现实等待，由玩家推进赛程。兼容时间字段只标记当前阶段开放，后续阶段开始时间处于未来；服务端不因倒计时自动推进或结算。练习赛保留原面板，将原倒计时位置显示为“可直接推进”，不安装其每秒轮询回调，停留练习赛不会循环发包。

每天最多新开一届。尚未结束的比赛跨日保留；本届结束后，若已到开赛日期的次日或更晚，重新进入可开启新一届。提前结束某阶段无法倒退重打或反复领该阶段奖励。

## 2. 原版依据与修正

依据来自本地3.87原包 LuaJIT、CSV 和运行中的原版客户端；没有官方服务端源码或官方结算日志。`analysis/evidence/taixu/official_audit.json` 保存13份原始输入的哈希、CSV一致性校验、函数与字段证据。

| 项目 | 已核实的原版行为与本次处理 |
|---|---|
| 模式名称 | `mode=1`、`map_list.undergo` 实际为普通挑战；`mode=2`、`map_list.challenge` 实际为限时历劫，不能按英文变量名理解 |
| 布阵 | 原版收发 `cortege_list` 是 **神仙ID → 阵位**，已纠正旧后端的反向映射；内部保存仍用阵位→ID |
| 次数与体力 | 挑战10次/日、2体力；历劫0体力、每神仙4次/日。原CSV中的通用 `strenth_consume=1` 与实际界面不一致，此处按客户端专用界面执行 |
| 模式奖励 | 普通挑战使用 `exp`、`money`、`com_win_prize`；限时历劫使用 `_lijie` 列，首次奖励也属于限时历劫 |
| 地图依赖 | 必须先通过整大关挑战，才能开始该大关历劫；必须完成上一大关历劫，才能首次挑战下一大关 |
| 每日重置 | 恢复神仙次数、挑战次数、日奖和商店限购；当前限时大关小关重置，不能每天把整个活动清回第一大关 |
| 72小时 | 已补 `last_challenge_time`、超时退关及 `top_big_id`，首次奖励判定使用实际历史领取记录 |
| 战斗奖励页 | 补齐原客户端消费的 `attach_list` 和 `first_win_prize`，不再只有入包而奖励页缺数据 |
| 最终关 | 909后使用1001作为已通关哨兵，地图仍定位在第九大关；禁止重复挑战限时终关，并保留全部日奖 |
| 九宫格出手 | 按双方最靠前的已占用阵位决定先手，同阵位进攻方先手，然后双方轮流使用各自剩余阵位。空位不占一次出手机会 |

原包还包含旧的 `cross_server/manual.csv` 修行者、护法天梯资料。该旧天梯不等同于本次实际入口中的历劫地图或血战；未把这套不同玩法的养成与排名硬接入。其九宫格顺位说明用于校验共用九宫格战斗规则。

## 4. 血战 NPC 与排名

玩家来源统一为：

- `analysis/npc_design/players/catalog.json`：正式随机玩家ID、姓名、等级、头像、VIP、资料及阵容来源。
- 资料记录的 `source_file`：V1/V2原始战斗阵容快照。
- `network_redirect/npc_players.py`：身份解析、完整只读阵容查看。

NPC姓名、玩家ID和阵容详情保持一致，可在已有“其他玩家”功能中使用相同身份查找。原版血战卡片显示主将神仙头像，个人资料头像仍来自玩家目录。

原版按七组分级【A】；当前按用户要求删除前三个低等级组，仅开放50—59、60—69、70—79、80—99级四组【B】，保留其内部组号4—7，避免改变已有高等级赛程及NPC抽样。旧档浏览低等级组时回到自己的组；早期低等级赛程在角色达到50级后迁至当前等级组，保留对手与赛程进度。本届开赛时锁定玩家组别，赛中升级不换组。每组按绝对战力分段抽取NPC，使用日期和NPC身份作确定性选择；自己的组有19名NPC加自己，共20名参赛者。不会随玩家临时强化而等比例抬高对手。

其他分组允许浏览排行和查看阵容，不能跨组攻击。参赛名单在本届内固定，重启、刷新和跨日都不刷新对手。

- **冲榜：** 按分数排序，10次免费挑战。胜利增加分数，至少超过本次对手1分；同一NPC本届首次击败额外获得20仙晶，重复刷同一目标不重复领。默认20个晋级名额保证离线参赛者能体验后续流程，名次决定初始血量。
- **练习：** 5次免费挑战，不改变血量、分数，也不发重复战斗奖励。
- **正式血战：** 每阶段9行动力，每战3点；胜利得100分，目标血量减少20。前两段进攻失败不扣自己血量，第三段失败扣20；不完整/超时战斗不冒充胜利。
- **初始血量：** `100 + (20 - 冲榜名次) × 5`。正式赛按血量降序、分数降序排名，同分按稳定身份打破平局。
- **可挑战范围：** 沿用客户端当前名次所在五人档及前方对手的范围。服务器核验目标身份、名次、阶段、血量和组别，不能伪造请求挑战不在列表中的对象。
- **付费补战：** 免费次数/行动力不足时，客户端确认后每次20元宝，一届最多5次。尚有免费额度时即使带付费标志也不扣元宝。离线版不开放赌斗。
- **NPC互动：** 推进前两段正式赛时，NPC之间完成一轮配对；依固定阵容战力确定胜负，更新NPC分数与血量。此为离线模拟，不伪装实时在线战斗；不会在玩家未操作时扣玩家血量或资源。

主动挑战使用NPC完整上阵养成快照与现有八人战斗引擎，包含已接入的装备、法术、精魄和觉醒效果；不拿客户端上报的胜负、伤害或奖励作结算依据。

## 8. 2026-10-26 血战界面与奖励修订

### 练习赛持续加载的根因与修复

原包 `arenaUI.showExerFight` 的秒计时回调（原源行882—892）读取 `match_time_list[3].start_time`，正式赛开始时间已到就调用 `refreshGroup`。第一版离线配置把三个阶段同时设成 `now-1` 开始；练习面板刚创建便再次请求分组，返回后重新创建面板，形成持续加载循环。

1. 兼容赛程时间只开放当前阶段，练习期间正式赛开始时间始终晚于查询时间。

## 10. 2026-10-27 冲榜挑战「活动数据无效」修复

实际请求日志记录1350挑战失败原因为 `'<' not supported between instances of 'str' and 'int'`。在当前存档只读副本上复现：战斗计算已完成，但新战报的 `fight_events` 同时含数字索引和字符串 `fight_id`，后续 `formation.prepare` 对整个角色进行 `json.dumps(..., sort_keys=True)` 比较时触发类型错误。没有效果事件时只有 `fight_id`，所以同一阶段可能部分挑战成功、部分失败；刷新界面不能解决。

血战保存战报时现统一将效果事件的顶层键转为字符串，与SQLite JSON读回的格式一致。即时战斗仍发送原版数字索引，历史回放沿用 `replay_packets` 将数字字符串转回数字，不丢弃法术效果，也不修改胜负、次数或奖励规则。旧战报读取方式不变，已有存档无需清理。

新增回归测试先在修复前稳定复现相同提示，修复后覆盖冲榜、练习、三段血战的带效果事件结算，以及每阶段关闭后端、重新读取存档后回放事件完全一致且不再次消耗资源。此前测试未覆盖这一带效果战报的保存路径。本次血战、历劫及战斗引擎相关测试共60项通过。

另使用当前99级角色存档的只读副本，在临时数据库中对本届19名对手逐一执行真实战斗、完整1350响应及保存后回放校验，全部通过，其中11场产生效果事件。正式账号未因验证消耗挑战次数或资源。这是后端真实引擎与协议验证，不等同客户端逐帧动画验收。
