## 必须了解的时间与存档规则

1. 首次建立锚点仍采用未验证的系统日期和已识别旧档时间下限中的较大值。已有未来历史不会自动退回现实日期，也不会因此自动封锁旧角色。
2. 同次设备启动且启动身份可确认时，锁屏、休眠和关闭／重开游戏按连续计时补算。**设备重启或无法确认启动身份时，不补算无法验证的离线间隔；游戏日期可能落后现实日历。** 本版没有联网校时。
3. 零点、周一等边界按游戏时间（通常 UTC+8）计算，由登录、心跳或相应玩法请求触发结算。手机日期修改可能短暂影响客户端倒计时，下一次时间同步纠正；收益由后端决定。
4. 升级会在 `game.sqlite3` 新增 `time_guard` 表，并在同一 save 目录生成 `clock.sqlite3`、`time_guard.key`、`clock_integrity.key`。这些均运行时生成，安装包不携带玩家数据库或校验密钥。
5. 备份请停止游戏后，完整保存同一代的数据库与上述密钥，或保存整个 save 目录；不能只恢复角色数据库或只恢复时钟文件。首次升级前没有这些新文件的旧备份应按完整旧备份保存。部分恢复、外部编辑或数据损坏可能导致限制或停止处理。
6. 升级后出现 `TIME-001` 表示受保护时间记录异常，已接入的相关时间功能受到限制，不删除角色或追回既有资源。最新包同次开机系统时间累计偏差超过5分钟也会触发封锁；调回日期或重启不解封。正常设备重启本身不直接触发处罚；没有自动到期或客户端解封入口。

本机制用于普通离线环境，不能防止修改 APK、Root、读取密钥后重签、整套备份回滚或旧 APK 绕过规则。不要通过降级旧版尝试修复新时钟存档。
