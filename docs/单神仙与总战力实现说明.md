# 单神仙与总战力实现说明

实现日期：2026-10-25。当前评分版本：V1.1（下方第7节为切换前的历史排查记录）。

评分依据：[用户提供的战力评分规则说明 V1.1](战力评分规则说明_V1.1.md)。

## 1. 实现范围与证据边界

本次以[原版游戏战力来源与计算线索](原版游戏战力来源与计算线索.md)、原包 CSV 和现有服务端状态结构为依据，完成常驻属性、单神仙评分、角色当前总战力、历史最高战力和协议刷新链路。

原版已确认的是字段、配表和部分局部公式；完整评分权重、属性叠加顺序和团队汇总规则仍缺原服证据。本实现明确采用 `inferred` 本地规则，不宣称还原了官方公式，也不向客户端伪造配置类别 25。

主要文件：

- `network_redirect/combat_power.py`：独立结算、来源明细、称号、助威、灵兽、洞府修炼和缺失来源接入口。
- `network_redirect/formation.py`：保留兼容入口 `recalculate(role, rules)`，统一委托战力模块。
- `network_redirect/immortal.py`：独立收集奖励重建函数，避免旧缓存和重复累加。
- `network_redirect/backend.py`：登录、增量更新、心跳、存档、历史峰值同步。
- `server_config/formation_rules.json`：权重与新增来源开关。
- `tests/test_combat_power.py`：专门回归测试。

## 2. 计算规则

### 单神仙

```text
单体战力 = clamp(floor(3×攻击 + 2.5×防御 + 1.5×法力 + 0.2×生命 + E))
```

当前权重为攻击3、防御2.5、法力1.5、生命0.2，并加入有效精魄独立分E；不是官方还原权重。`combat_weights` 支持大于0且不超过100的有限数。精魄按V1.1固定表及组合规则计分，主动法术与其他战斗能力不额外计分。

结算按下列顺序执行，每次从原始状态重建：

1. 原模板基础 + 成长 ×（等级 − 1）+ 已分配培养属性，再加 `floor(成长 × 3) × 飞升次数`。飞升直接成长于 2026-10-25 补齐，原版依据和验证见[养成数值核对](神仙养成原版数值核对与修复.md)。
2. 装备强化、注灵和升阶的属性值。
3. 同属性被动法术百分比先相加，再作用于上述小计。
4. 既有转生、经脉、装备转生、铸造、套装和连锁计算。
5. 既有觉醒、星宿五行关系及 `LINEUP` 四维效果。
6. 三类仙缘及装备升阶附加倍率；同属性仙缘百分比加算。
7. 向下取整，加收集、角色固定四维和洞府生命。
8. 当前有效称号、洞府攻击/防御修炼、灵兽、助威。
9. 显式来源通道，生成最终整数四维，再将四维加权分与精魄E相加统一向下取整；不对四维每一项评分单独取整。

这里的阶段顺序属于本地推测规则。装备、法术效果的局部取整沿用原实现；新增阶段使用 `Decimal`，避免二进制浮点边界抖动。

修复了原先“逐件遍历物品，遇到被动法术立即乘倍率”的问题：同一套装备和法术不再因背包中排列先后而产生不同结果。自带法术按神仙 ID 归属，未上阵神仙也拥有自己的被动属性，且不会读到其他人的自带法术。

### 总战力和最高战力

```text
当前总战力 = clamp(Σ 单体战力，范围为 order 在 1～8 的神仙)
最高战力 = max(旧最高战力, 当前总战力)
```

主角若已占一个阵位，按该神仙记录计一次。助威者、背包神仙不直接加总；助威、仙缘等通过受益神仙间接改变总数。没有额外团队固定分，也不把历史最高值加进当前值。

`clamp` 范围为 `0～2147483647`，匹配 `1032` 有符号 32 位属性限制。极端值达到上限时，明细可见取整前数值；当前总战力与单体之和也会因限幅产生差值。未知历史模板保留原记录，不擅自替换模板或删除神仙。

`max_combat_power` 作为历史峰值保存是明确的本地推测。卸装、换将或称号到期可以降低当前战力，但不降低峰值；读取旧存档时会建立缺失字段。

## 3. 新增来源的具体约定

| 来源 | 状态和计算 | 推测边界 |
|---|---|---|
| 称号 | `title_id/title_begintime/title_endtime`，读取 `title_config.csv` 的四维目标和固定值 | 只取当前称号；生效区间为开始时间含、结束时间不含；限时称号无结束时间不生效，不累计全部已获称号 |
| 洞府修炼 | `activity.home.train["1"/"2"].level`，从 `hole_train_config.csv` 取当前等级 `rate|value` | 攻击、防御按 `原值×(1+rate/100)+value`；不累计所有历史等级；法伤和法抗不映射成法力和防御 |
| 灵兽 | `activity.home.pets` 中 `order=1` 的当前宠物，使用已保存的 `grow_values`，顺序为攻、防、命、法 | 按原版宠物界面：成长×等级×属性系数，再按品质开放方向、特殊属性除数、历代培养百分比及星级固定值结算；详见《独立宠物系统规则与修复说明》 |
| 灵兽境界/阶段 | 当前境界 `star_plus` 固定值加一次，随后各属性乘 `1+each_stage_plus×对应train_levels/100` | 阶段比例按表头 percent 解释；无需把原始小数放大为百分之几十 |
| 灵兽位置/转换 | `plus_order` 按神仙阵位传递对应属性；`special_property` 按位置、源属性、目标属性和 rate/100 转换 | 不给全体神仙无条件叠加宠物全部属性；转换为额外传递，不扣宠物原属性 |
| 正向助威 | `cheer_order=1～8` 对应同号主阵位，角色 `cheer_heaven_level` 等八方等级，缺省为1 | 读取配表从1至当前级的累计系数，`0.026` 直接作为比例；底数为助威者阶段6的小计，排除共享加成和其他助威反馈 |
| 助威冲突 | 助威者必须不在主阵；异常同槽多名助威只取 ID 最小者 | 避免重复放大；不修改历史阵容记录 |
| 收集 | 每次从 `immortal_collection` 激活状态重建 | 缓存不是独立奖励，反复登录不会再加一次 |

助威采用两遍计算，先完成所有神仙独立属性，再计算传递，避免循环放大及遍历顺序依赖。助威伙伴仍可满足既有伙伴仙缘规则。

## 4. 缺失服务的接入口

原文档列出了天赋、`fam`、`prey`、灵石、精英、自由阵位等通道，但当前仓库没有完整的状态生产服务。本次提供可运行的统一属性入口，默认无来源即零加成，不按库存数量猜测激活状态。

在角色或神仙记录上使用独立的 `combat_sources` 对象，例如：

```json
{
  "combat_sources": {
    "fam": {"gongji": 5, "hp": 3},
    "goss_equip": {"gongji": 120},
    "cortege": {"magic": 50}
  }
}
```

- 固定值通道：`cortege`、`elite`、`goss_cortege`、`goss_equip`、`goss_skill`、`free_order`、`cheer_skill`。
- 百分比通道：`genius`、`fam`、`prey`、`goss`、`special_attack`；示例 `5` 表示5%。
- 属性键仅允许 `hp/gongji/fangyu/magic`，值须为有限数；未知来源、非数值、NaN、Infinity 都拒绝。
- 先结算角色通道，再结算神仙通道；各范围内部百分比加算，按 `小计×(1+百分比合计/100)+固定值合计` 处理。
- 角色来源覆盖全部神仙；只影响某一神仙的来源应写在该神仙记录上。场景临时加成应留在战斗模块。
- `goss_equip/goss_skill` 等输入须是其生产服务已经依据装备/法术底数算好的固定增量，不将“装备倍率”错误地乘到神仙最终四维上。

输入与派生输出明确分离。不自动读取旧缓存中的 `plus_rate`、`role_collect_*`、`animal_*_plus` 等同名字段，以免重复计算既有收集、灵兽或通用倍率。已自动结算的角色固定值、称号、宠物和洞府生命也不再提供同名二次入口。

这部分完成的是战力结算接入口，并非为这些玩法新建获取、升级、佩戴协议。现有助威客户端开关仍保持关闭；有助威存档时可以正确参与本地推测结算。逆八方、助威法术原始升级服务、灵石自动装配识别及空位触发条件仍需相应玩法服务提供明确来源；可经显式固定值/百分比通道接入。精魄触发、主动法术强度、星宿战斗效果继续由战斗模块处理；精魄独立评分使用V1.1规定的固定表，其余未规定效果不额外计分。

## 5. 配置、调试和协议

`server_config/formation_rules.json` 中的新增配置：

```json
"combat_power": {
  "title": true,
  "pet": true,
  "cheer": true,
  "explicit_channels": true
}
```

这些开关只控制新增结算来源，不代表开放相应客户端玩法。修改后重启本地服务端即可加载；原存档在下次读取/保存时重算，无需清档。

角色上的 `combat_power_breakdown` 是派生明细，记录每名神仙各阶段四维、最终面板和评分、显式输入、汇总成员 ID、总数、峰值及权重。阶段值是累计小计，两个阶段相减才是该阶段增量，不能把所有阶段再次相加。精确小计保存为十进制字符串。

只读解释接口不会改动传入角色或峰值：

```python
from network_redirect import combat_power, formation
report = combat_power.explain(role, formation.load_rules(), now=1792886400)
```

协议沿用原版：

- `1034` 下发单体属性和 `combat_power`。
- `1017` 下发当前 `role_combat_power`。
- `1032/unit_type=4` 更新58号单体战力和61～64号四维。
- `1032/unit_type=1` 更新30号当前战力和39号历史峰值；登录也补发这两个属性。
- 阵容、神仙、转生、活动、旅途、VIP相关结算统一刷新；存档和重连重算。
- 心跳发送单体属性增量以刷新到期称号，保留客户端已引用的神仙对象，不用全量列表替换正在操作的界面对象。
- 既有序列号重放仍复用原响应字节，避免重复操作。

## 8. V1.1 精魄评分实现

本节规则覆盖前文旧版本排查中的等权评分数值。

`server_config/essence_power_v1_1.json` 固化用户文档中的38种、每种5级，共190条**最终评分**。不在运行时再次乘1.6，也不增加品质底分、等级底分或库存分。配置版本及条数、类型集合和整数范围在模块加载时校验。

有效精魄条件：附件类型5、`owner_id` 等于当前神仙、精魄类型在表内、等级1～5、`ext_skill_pos` 在1至已开放槽位（最多4）、实例数量大于0。背包、其他神仙、未开放槽位、无效等级均不计分。同族跨品质/重复实例按基础分从高到低取一枚，同分取ID较小者。异常重复槽位也只取一枚，保证结果不随附件列表顺序变化。

组合参数直接取原包 `ext_skill.csv` 对应类型、等级的 `parameter`：

| 组合 | 参数位置（从1开始） | 修正 |
|---|---|---|
| 幸运＋愈合 | 幸运第1组 | `ROUND_HALF_UP(幸运提升率 × 愈合基础分)` |
| 招架＋强袭 | 招架第2组 | `ROUND_HALF_UP(0.30 × 强袭提升率 × 强袭基础分)` |
| 连击＋斩杀 | 连击第1组 | `-ROUND_HALF_UP(连击概率 × 斩杀基础分)` |

百分数除100，使用十进制精确运算。各组合单独四舍五入（0.5向上），再和基础分合计为E；E与四维加权和统一向下取整。例如一级金色招架150分、强袭1325分，额外分为`R(0.30×0.20×1325)=80`，E=1555；参考神仙攻10000、防5000、法3000、命20000，无精魄得51000。

精魄强壮、战意、祝福等效果不在此模块加到常驻四维。评分代码没有修改战斗触发概率、伤害、治疗、持续时间或上限；不得把这些精魄效果再通过`combat_sources`注入，否则属于来源生产者重复记账。

明细新增每名神仙的 `essence`：有效实例、基础分、三种组合修正及总E；顶层 `scoring_version="1.1"`，明细结构版本升级为2。历史最高战力保持既有不下降语义，切换权重不抹除旧峰值，因此它可能包含旧评分体系的历史记录。

切换时服务端读取存档自动重算，不修改等级、装备、培养或资源。总战力仍只汇总上阵者评分，不直接加助威/背包神仙的精魄分。超过协议范围时沿用int32上限保护，属于兼容性边界。
