- **【A】**：可从本项目原版 3.87 客户端字节码、协议或 CSV 直接复核。
- **【B】**：缺失原服务端时采用的本地实现、配置、结算假设。能运行不等于已证明与历史原服完全一致。

2026-10-28专项复核发现并修复逆八卦前置校验及法术槽掩码偏移；新增一次性旧档迁移。入口、全部数值、A／B区分和最新验证以[逆八卦原版机制与实现说明](逆八卦原版机制与实现说明.md)为准。下文2026-10-25验证记录为历史记录。

## 【A】原版客户端合同

### 位置、开启与目标

1. `cheer_order_index` 定义正八卦 1–8：乾、坤、震、巽、坎、离、艮、兑；逆八卦 9–16 为对应逆位。UI 通过 `index + orientation * 8` 发包（L948–955）。
2. 配置段为 `g_new_config[14]`。字段为 `is_open`、`is_open_ni`、`cheer_level_limit`、`open_cheer_item`、`cost_item_count`、`cost_gold_count`（L490–499）。等级及开位道具按全局位号索引；洗炼两项消耗是**数值**，不是表。
3. `is_open_ni` 参与整数比较；1 表示逆位基础功能，2 才开放进一步培养／法术等（L89–96）。不能发送布尔 `false` 代替整数。
4. 正八卦前两位无论等级字段是否为零都直接进入；第三位起使用开位提示。正位第4位起、逆位第3位起检查前方阵位已经开启（L865–902）。前两位何时由原服务端赋初始等级无法仅凭客户端确定。
5. 开位默认材料为 `1017 × 1`，配置可覆盖（L263–265）。原道具描述说明 1016 为八卦令·震，1017 为八卦令，60级后使用。
6. 助阵候选必须 `order=0` 且 `cheer_order` 为空／0（L638–648）。选择加成目标发神仙 ID；显示时用角色 `cheer_<方向>_effect` 索引**上阵位置**（L686–700、L2789–2799）。并非固定对相同编号阵位生效。
7. 查看阵容 `owner_cheer_info` 使用**数值属性编号**；`cheer_cortege` 按助阵位置索引。查看界面再将其映射为角色属性和助阵神仙（checkLineupUI L52–67、L174–187）。

### 升级、洗炼及属性

- 升级材料 ID 为 **1015**，由 UI 硬编码（L1976）。原 `cortege_cheer_config.csv` 含正八卦每位1–10级，升级读取**下一等级**的 `upgrade_cost`。
- 1→10级依次消耗：25、50、75、108、129、158、194、230、331；共1300个材料。
- CSV 提供 `gongji/fangyu/maxhp/maxmagic` 的 `plus` 和 `recover` 列，但并未提供完整服务端结算公式。不能仅凭列名声称恢复量、累计方式已还原。
- 原界面满10级后切换洗炼流程（L1951–1974）。阵位洗炼有预览、放弃、确认和恢复未确认结果。
- 洗炼回复含 `src_index`、`des_index`、`modify_value`；属性编号为攻击1、防御2、血量3、法力4。`modify_value` 及角色方向属性以1000为倍率传输，界面除以1000（L441–444、L2843–2864）。
- UI 用助阵神仙四维乘以方向对应比例显示加成（L2867–2881）。
- 法术洗炼须主角境界至少4、至少一个法术位开启、当前法术等级低于500（L2255–2276）。它与普通阵位洗炼使用不同的确认／放弃标志。

### 助阵法术

- 每位有两个可装被动法术的位置：`equip_pos=2/3`；位置1保留自带法术。UI 排除已装备、非被动及自带法术（L1030–1047、L1144–1156）。
- 背包装备位置1–8属于主阵，9–24属于16个八卦位，助阵位置为 `equip_order - 8`（packageUI L2122–2132）。不能将八卦法术装到主阵同号位置。
- 开槽状态编码在 `cheer_skill_open`／`cheer_skill_ni_open`，每个方向使用两个二进制位（L957–966）；结合原 `tianShuUI.getBitInGuideIndex` 会移除最低位，实际使用bit1～bit16，bit0保留（2026-10-28修正）。开槽的境界门槛来自转生配置 `rights.open_cheer_skill`；每次使用一个该方向配置的开位道具（L990–1017）。
- `cheer_skill_config.csv` 包含0–500级，`plus_rate=0.5 + level × 0.001`。UI根据当前等级读取消耗表，材料为1206，数量按等级模4循环：600、900、1500、1500。
- 原版1017登录协议：正位法术等级为32位整数；逆位为一个字节。1032角色属性更新则可传32位整数。两种协议宽度不一致是原包事实。

## 【B】补齐的服务端规则

### 开放与材料获取

- 正八卦8位40级、逆八卦8位60级（2026-10-28按需求调整）；前两正位达到门槛自动给予1级，其余位不开启、不免费赠送资源。
- 正第三位用1016×1，其余正位用1017×1；逆位用1017×2。逆位还须全部正位已开启，且先开逆·乾。正位全开是原入口条件【A】，后端强制逆·乾先开为流程补强【B】；等级、数量均为推测配置。
- 主角境界4开放助阵法术槽；配置同时发送给转生界面和服务端校验，避免客户端永远找不到权限。
- 原永久集市CSV未包含这四类材料的可用购买条目，因此补充40级起“全部”页：1015×100售100元宝，1016×1售200元宝，1017×1售200元宝，1206×1售100元宝（每个礼包开启获得1015×100）。索引201–204；沿用原集市购买协议、数量限制及扣款。价格、常驻供应和礼包数量均为【B】，可在八卦配置中修改。没有充值或外部支付行为。

### 数值、目标与战斗

- 正位逐级累计原CSV的 `*_plus`。逆位缺少独立表，暂复用同编号正位。`recover` 列保留原证据，但本地公式不据此生成额外资源或战斗回血。
- 每个助阵位只选一名神仙、一个目标阵位；同名神仙不能同时出现在主阵或其他助阵位。不同助阵位可指向同一目标，正逆加成相加。
- 阵位洗炼固定消耗1015×10、20元宝；均匀随机选择不同来源／目标属性，将来源的5‰转到目标，来源不足时只转移现有值。四维比例总和不变，不产生负值。可重复洗炼覆盖旧预览，每次重新扣费。
- 法术洗炼相同消耗，随机增加1–5级，不超过500；未确认不生效，放弃不退款。有待处理预览时拒绝直接升级法术位，防止先升级后确认越界。
- 助阵属性以本轮计算的神仙基础结算结果为输入，不把上轮缓存战力再次加成。被动法术以目标本轮基础属性 × 法术效果百分比 × 原表 `plus_rate` 计算，结果加到目标；没有独立助阵神仙时不产生增益。
- 目标按阵位绑定；换人后由该阵位新神仙获得加成，目标阵位变空则清除绑定。助阵法术跟随八卦位，助阵神仙自带法术跟随神仙。
- 结算进入统一永久属性与战力计算，旅途／仙盟等战斗沿用同一属性。正逆位均支持500级法术能力。
- 为兼容逆位登录字段，1017只发送不超过255的初始值，紧接着用原1032属性消息发送完整等级；服务器持久化值始终保留0–500。此兼容发送策略为【B】，不是声称原服也这样实现。

### 可靠性

- 失败在独立读取的角色副本中退出，不保存部分扣款、部分穿卸或半次升级。
- 同一连接序列号和同一请求重放原回复，不重复消费；同序列号异包及已过期序列号拒绝。缓存边界沿用现有阵容后端，**不声称跨服务重启具备全局幂等键**。
- 洗炼预览、确认结果、开位、开槽、目标和法术等级均写入账号存档。重连恢复完整属性，查询flag7可恢复未确认选择。
- 锁定材料不可消耗；主阵神仙不能同时助阵；不能把已装备法术、自带法术、主动法术或同名法术重复装入槽位。
- 成功时先同步神仙／背包和角色属性，再发事件95，最后发1106完成通知，供原UI刷新。
- 自己的阵容查询、仙盟阵容查询补齐八卦属性、按位号组织的助阵神仙和法术；离线生成对手没有助阵时发送完整零值。
