# 其他模块与系统邮件调试

本次围绕“其他 → 消息 → 系统邮件”的补偿礼包链路调试，不将其他菜单所有子系统声称为已完整实现。

## 原版证据【A】

- `analysis/evidence/lua_named/lua/ui/other_functionUI.lua.txt`：原源码209行创建消息按钮，451—459行的 `menuMessageCallback` 打开 `d_messageUI.show()`。菜单另有图鉴、成就、公告、聊天、设置、客服、重新登录、兑换码及渠道中心。
- `messageUI.lua.txt`：1754—1783行接收系统邮件编号；1792—1831行自动请求正文；1948—1991行处理标题、正文、附件；1996—2004行发送领取请求；2121—2158行处理领取结果。
- `common/common_def.lua.txt`：服务端事件13/14/15分别是邮件列表、正文和领取结果。`protocol_tables.json` 的1102/1103分别读取正文和领取附件，邮件编号为double。
- 正文读取显式调用 `main_server_send_msg(..., 0)`，允许请求序号0；领取调用未传0，使用正常的请求序号。
- `messageUI.lua.txt` 原源码799—802行，仅在**没有附件且超过30天**时忽略显示；未领取附件的邮件跳过该分支。原包不包含可证明的运营后台发送实现，不能据此推断原运营后台不存在。
- 兑换码入口使用另一条礼包协议1104，并非系统补偿邮件发送入口。客服/渠道外链不等同于本地运营工具；此次未恢复这些外部服务。

## 修复与本地补齐【B】

1. 修复 `Backend.welfares` 将序号0正文读取误判为“福利请求已过期”。读取独立返回事件14，不消耗领奖序号，不重复发送整个背包。
2. 新增 `network_redirect.system_mail` 运营命令：按账号发放任意合法补偿附件；默认只预览，`--send` 才写入；永久有效。
3. 写入使用与控制服务相同的排他锁、SQLite事务、原存档备份及 `system_mail_audit` 审计表，避免在线存档覆盖。
4. 同一批次重复发放保持原邮件编号和领取状态；内容冲突拒绝，已领取邮件不会恢复为可领取。
5. 发送前在副本上验证所有奖励及协议编码，非法附件不能造成部分到账。真实领取仍由原1103链路完成，并保留持久化重复领取保护。
6. 邮件明确保存 `expires_at=null`、`no_expiry=true`，正文说明永久有效。服务端不执行过期删除。原版已领取且无附件的消息可能在30天后不再显示，但不影响未领取礼包的永久领取权。

## 使用

所有命令从项目根目录执行。发放期间短暂停服，执行完恢复，玩家重新进入游戏即可看到邮件。

```sh
# 检查开服礼包；不会增加或领取任何资源
python3 -m network_redirect.system_mail --account ezan --launch-gift
python3 redirect_game.py stop
python3 -m network_redirect.system_mail --account ezan --launch-gift --send
python3 redirect_game.py start --offline --probe
```

自定义补偿文件示例（数量在第三列，等级在第四列）：

```json
{"key":"maintenance-compensation-001","title":"维护补偿","body":"感谢你的耐心等待。","prizes":[[11,0,100,1],[5,1001,20,1]]}
```

```sh
python3 -m network_redirect.system_mail --account ezan --file /tmp/compensation.json
# 停服后加 --send 发放，再恢复服务
```

支持神仙4、物品5、法术6、魂魄10、元宝11、银币12、宠物15。宠物附件第四列是品质，实体初始等级为1。`analysis/tools/send_launch_gift.py` 旧命令已转入相同的锁、备份与去重流程。

## 消息按钮可见性补修

此前实机验证通过调用 `menuMessageCallback` 打开页面，未验证按钮可见性；用户反馈后确认遗漏。原版 `other_functionUI` 157—160行从 `g_new_config[7]` 读取菜单配置，缺省表只有图鉴、公告、设置、客服、重新登录；207—210行仅在 `message=true` 时创建消息按钮。本地启动配置现显式下发第7组，保留原五项并开启消息。新增启动协议回归测试，合计23项通过。补修需通过真实可见按钮点击验证，不以直接调用回调代替。
