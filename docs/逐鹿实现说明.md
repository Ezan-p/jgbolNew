# 逐鹿离线活动实现说明

更新日期：2026-10-25。

逐鹿已接入本地 NPC 游历对手、守塔对手、三人组队、阵容查看、本地榜单、周奖和活动日志，与已有普通／冥界首领、符咒、翻牌、扫荡形成可玩的完整流程。所有活动状态保存在当前账号；不需要在线玩家，不读写其他账号，不修改 NPC 设计库。

## 2. 玩家流程

1. 角色达到 38 级，从活动入口进入逐鹿。
2. 北京时间 00:00～18:00 游历。每日 30 次；每轮按地图原表出现 2～8 个候选目标，选择其中一人挑战，或撤退结束这轮。再次打开尚未结束的游历不重复扣次数。
3. 胜利获得 100 魂力及一枚随机属性的 5% 符咒。批量游历最多 5 次，逐场计算实际胜负；失败或未决不发胜利奖励。
4. 消耗魂力挑战普通首领，胜利后翻牌，再进入下一层。免费首翻，额外翻牌按 20／50／100／200 元宝递增；普通 5 张、冥界 3 张。满翻额外奖励采用现有配置。
5. 按原表开符咒槽、装备／卸下、合成／转换。符咒只增加逐鹿战斗属性。合成失败保留主符咒、消耗辅符咒是本地规则。
6. 普通首领达到 12／20／28／36／44／52 层后，可依次花费魂力开放第 3～8 阵位；通过 16／32／48 层后开放后续地图。初始两个阵位。
7. 已通关的普通层对应解锁冥界层，冥界需逐层推进；每层每天 3 次挑战。普通与冥界各 64 层，已通关普通首领每天可扫荡一次。
8. 18:00～24:00 占塔。每日 5 次攻塔／进入次数；铁脊塔先建队，天风塔、地元塔可单人挑战，千魂塔可直接进入，也可启用自动占塔。
9. 默认每分钟 10 魂力、每塔 600 魂力、单次最长一小时。离线后重新打开逐鹿时补算，截止于到期、魂力耗尽或当日午夜，重复查询不重复获得收益。
10. 可以查看活动日志和本地榜单；周一零点后的首次逐鹿访问结算上一活跃周奖励，奖励进入游戏内系统邮件。

组队和普通／冥界首领入口不额外要求真实玩家在线。当前实现保留上述日间／晚间时段，不把原活动全部改为全天攻塔。更新代码后需重启本地服务端加载 Python 模块；无需重新构建 APK。

## 3. NPC 安排

### 游历

- 对 NPC 快照调用正式 `combat_power.recalculate`，不直接信任历史缓存分数。
- 排除已标记 `replay_limit_observed` 的模板；其余模板参与匹配，仍受正式战报上限保护。
- 按当前逐鹿开放阵位计算双方参战部分的真实战力，候选目标依次取玩家战力约 55%、80%、105% 附近的已保存模板；等级不超过玩家等级。
- 只挑选已有快照，不线性插值、不乘虚构难度属性。快照稀疏时选择最接近的真实模板，因此百分比是匹配目标，不保证精确相等，也不是胜率承诺。
- 相邻游历轮交替选取两个最近候选，保持一定变化；同轮和重启后保留已选择的 NPC ID。
- 名字明确保留“离线”前缀，显示实际神仙头像、等级、人数和战力。

### 守塔

四张地图分别使用 7／24／50／80 级代表模板；前三座塔依次使用 T5／T4／T3 档，流派按日轮换，随地图推进提升固定难度。千魂塔不要求战斗，保留稳定的魂力来源。守塔 NPC 不会读取真实玩家存档，也不会在玩家离线时随机扣除其资源。

新游历对象用 `942001～942008`，队友用 `940001～940003`，塔主用 `940100 + tower_id`。这些是逐鹿独立协议标识；内部另存稳定的 `npc_id`。旧存档中尚未结束的通用守卫游历可以完成，下一轮自动切换至 NPC。

### 阵容查看与战斗

`1039` 对当前游历、队员和塔主返回实际 NPC 神仙、装备和法术。过期或伪造的本地目标拒绝访问。战斗使用已有八位引擎，包含替补、技能、精魄和命星；属性和仙缘沿用角色完整养成的正式结算，再限制本场出战人数。

NPC 模板是静态缓存，战斗单元重新构造；伤害、魂力、背包和队伍修改均不能污染模板。

## 4. 离线组队

接通原版 `1303(id=1)`，保留创建、申请、接受／拒绝、清空申请、离队、解散、踢人、列表／详情、换位、锁定／解锁等操作。最多三个成员，自己占一个位置。

- 自己建队：生成三个 NPC 申请，玩家选择最多两个接受。
- 申请 NPC 队伍：立即接受，并将指挥权交给当前玩家，不等待网络响应。离线队伍始终由当前玩家指挥；不能转交给 NPC 后让玩家失去控制。
- 通过拖动队员调整顺序，服务端校验 ID 唯一且包含全部成员。
- 占塔期间不能改组队伍；组队期间不能切换地图，退出或解散后可以切换。
- 队伍跨日和重启保留，申请操作、人数上限、重复接受、锁定与踢出均由服务端验证。

**协作战斗为 B 规则**：铁脊塔战斗把每名成员的前 `min(已开阵位, floor(8/队伍人数))` 名神仙按队员顺序组成一支至多八位的队伍，实际参加同一场战斗。沿用八位首发／替补规则和玩家逐鹿符咒增益，当前账号获得塔收益。不是只在界面摆放两个不参战头像，也不声称恢复了原服多场接力逻辑。

组队回复通过事件 145 更新窗口；使用原版 `2995(tip_type=2)` 同步 `team_info`，避免发“重新进入地图”事件导致队伍窗口被销毁。

## 5. 榜单、周奖与日志

- 普通榜、周榜、冥界榜加入 NPC，最多展示前 50 条，同时返回自己的真实名次，即使自己不在展示范围。
- NPC 层数、积分和周魂力是稳定模拟进度，不代表在线人口统计。普通／冥界榜按对应层数与积分排序；周榜按本周实际获得魂力排序。
- 消耗魂力不会降低周榜累计量；游历胜利和占塔产出计入 `week_soul`，没有把背包余额当作成绩。
- 每个本地自然周只结算一次。只有存在本周魂力收入时才参与；跨过多个离线周，只结算最后一次有记录的活跃周，不凭空补发每一空白周。
- 使用原表周奖。例如第一名为 1200 个 10000、50 个 1325、12 个 10001 和 500 元宝；奖品以原物品 ID 为准。
- 邮件键为 `land-week-<week>`，永久有效，沿用系统邮件领取路径与幂等检查。重复打开逐鹿或重复领邮件不会重复发资源。
- 日志最多保存最近 30 条，记录挑战结果、魂力收益及周奖投递；读取后清除未读提示。

周奖目前在访问逐鹿时懒结算；不会为了结算在后台开启定时联网任务。

## 6. 保留并修复的关键流程

- 普通／冥界首领真实模拟；不信任客户端传来的胜利结果。
- 首领获胜后保留待翻牌奖池，跨日、退出和重启不重抽；同一位置不能重复翻牌，重复“下一层”不能重复推进。
- 当次参战数量不得超过实际拥有的出战神仙，避免虚构人数参与结算。
- 扫荡回复改成原客户端读取的 `sweep_list[层][奖励]`，修复原来的额外包装层。
- 活动余额、次数、奖池、背包和阵位都随账号事务保存；非法参数或资源不足时整体回滚。
- 日常活跃度沿用已有逐鹿游历次数记录，查看同一轮不重复累加。
- 每场回放仍是事件 149 内的 `final_result_list`，包含 `line_up_msg`、`fight_result_msg` 和对应额外事件；战斗类型 21。

原协议的动作／报文容量有限，仍沿用逐鹿最多 80 动作和嵌套额外事件预算。双方都存活但触及容量边界时返回未决，不伪造成胜利、不发胜利奖励。没有对每一种高阶阵容组合证明无限长回放可播放。
