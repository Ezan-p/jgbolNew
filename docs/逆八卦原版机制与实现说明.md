# 逆八卦原版机制与实现说明（3.87）

核对日期：2026-10-28。范围为阵容中的逆·八卦助阵。活动“八卦炼丹炉”是另一套玩法。

**A＝原版玩法／原包可直接证明的协议、界面条件及表值。B＝原服务端缺失后的本地推测、配置、结算及兼容策略。** 本次依据本项目 3.87 原始资源解析，没有连接历史官方服务器；不能把本地可运行解释为已完整证明历史原服行为。

## 1. 入口与完整游玩流程

入口：**首页 → 阵容 → 神仙阵位界面顶部助阵图标 → 正八卦 → 正／逆切换按钮 → 逆八卦**。

1. 【A】阵位界面通过 `charPositionUI.gotoCheerSquadUI` 进入八卦。自身阵容须满足八卦功能及等级条件；主界面不是独立的逆八卦活动入口。
2. 【B】当前正八卦40级开放，乾、坤自动为1级。震消耗八卦令·震1016×1，其余未开正位消耗八卦令1017×1。
3. 【A】**八个正位全部开启**，且 `is_open_ni≥1`，才显示自身阵容的逆八卦切换入口。不要求八个正位满级，全部1级即可。
4. 【A】首次切换时校验逆·乾等级门槛、显示材料确认框；确认发送 `1087 / flag=8 / order=9 / client_flag=9 / id=0`。这是开启逆·乾，不会一次打开八个逆位。
5. 【B】当前逆位门槛统一60级，每位使用1017×2。先开逆·乾，再开逆·坤、震、巽、坎、离、艮、兑；后端拒绝绕过正位全开及首次开逆·乾的流程。
6. 【A】选择闲置助阵神仙，再选择受益的上阵神仙。目标保存为上阵位置，并非固定给同编号位置加成。
7. 【A】使用乾坤符箓1015升级阵位；达到10级进入洗炼。每位另有两个被动法术槽，独立开槽、装法术，共用该方向的法术能力等级。
8. 【B】材料供应在“集市 → 全部”。重新登录会恢复助阵、目标、法术槽和洗炼预览；逆位法术能力超过255级也能完整恢复。

原版入口证据：`charPositionUI` L396–529、L4213–4228；`cheerSquadUI` L208–256、L315–371。原Lua行号是反汇编中 `[L数字]`，不是文本文件行号。可复核的[原包审计](../analysis/evidence/reverse_cheer/audit.json)及[阵位入口反汇编](../analysis/evidence/reverse_cheer/charPositionUI.txt)。

## 2. A：原版可证明的规则

### 2.1 八个逆位、目标与助阵

| 逆位 | 请求 order | 属性前缀 | 法术背包 equip_order | 两个槽位的掩码值（A） |
|---|---:|---|---:|---|
| 逆·乾 | 9 | unheaven | 17 | 2、4 |
| 逆·坤 | 10 | unearth | 18 | 8、16 |
| 逆·震 | 11 | unshake | 19 | 32、64 |
| 逆·巽 | 12 | unsunda | 20 | 128、256 |
| 逆·坎 | 13 | unwater | 21 | 512、1024 |
| 逆·离 | 14 | unfire | 22 | 2048、4096 |
| 逆·艮 | 15 | unhill | 23 | 8192、16384 |
| 逆·兑 | 16 | unpool | 24 | 32768、65536 |

- `orientation=0/1` 表示正／逆；请求位置＝界面方向编号＋8×orientation。
- 逆位第三位开始，原按钮会检查前一逆位已开启。逆·坤按钮本身没有这项检查，但正常入口先开逆·乾；后端禁止直接跳开逆·坤是对正常入口流程的补强【B】。
- 助阵候选是未上阵、未助阵神仙。加成目标在上阵位置1～8内，包括已开放的替补位。
- 每位法术 `equip_pos=1` 保留神仙自带法术，2、3为可装备被动法术。主动、已装备、自带法术不能作为普通被动法术装入，同一助阵位不能装备两本同名法术。
- `is_open_ni=0` 关闭逆位入口，1开放基础助阵，2开放培养和法术操作。协议字段必须是整数。

### 2.3 两类洗炼

- 阵位满10级后原界面进入洗炼，包含阵位属性／法术能力两类选项。
- 属性洗炼返回来源、目标、改变量。属性编号：攻击1、防御2、生命3、法力4。传输值以1000为倍率，例如5表示0.5个百分点。
- 洗炼支持预览、查询未确认结果、放弃和确认；属性与法术使用不同确认标志。
- 法术洗炼额外要求主角境界≥4、至少一个法术槽开启、法术能力等级<500。
- 洗炼消耗由服务端配置下发，原客户端没有足以证明历史概率、数量的完整表。

### 2.4 法术能力与槽位编码

原 `cheer_skill_config.csv` 共501行，能力等级0～500：

`法术发挥倍率 = 0.5 + 等级 × 0.001`

0／100／250／500级分别发挥50%／60%／75%／100%的法术能力。两个被动槽共享方向等级。普通升级读取**当前等级**消耗，材料ID1206、按等级除以4余数循环600／900／1500／1500；0→500总消耗562500。原道具名1206为“乾坤符箓礼包”，尽管名字是礼包，原法术能力消耗表确实直接指定该ID，本地保留此表值。

槽位编码必须同时核对两个原函数：

- `cheerSquadUI.getSkillBit` L957–966：按方向读取两个相邻位。
- `tianShuUI.getBitInGuideIndex` L647–672：先按最低位优先展开，再删除第一个元素。因此**bit0保留，槽位实际使用bit1～bit16**。

正位保存在 `cheer_skill_open`，逆位保存在 `cheer_skill_ni_open`；各自全部16槽开启时是131070（0x1FFFE），不是65535。开槽境界权限来自服务端转生配置，每槽消耗当前方向开位道具**1个**，不是开阵位的数量。

1017登录协议把逆位法术等级定义为单字节，但1032属性更新支持完整整数；这个协议宽度差异属于原版事实。

## 3. B：缺失服务端的补全规则

### 3.1 当前配置与获取

配置文件：[server_config/cheer_rules.json](../server_config/cheer_rules.json)。以下数值都属于B，可修改后重启本地服务并重登。

| 项目 | 本地规则 B |
|---|---|
| 正／逆门槛 | 正八卦8位40级、逆八卦8位60级（2026-10-28按需求调整） |
| 逆位开位 | 每位1017×2；正位全开，逆·乾先开 |
| 法术开槽 | 主角境界4，每槽1017×1 |
| 属性洗炼 | 每次1015×10＋20元宝 |
| 法术洗炼 | 每次1015×10＋20元宝 |
| 集市201 | 1015×100，100元宝 |
| 集市202 | 1016×1，200元宝 |
| 集市203 | 1017×1，200元宝 |
| 集市204 | 1206×1，100元宝；开启获得1015×100 |

集市四项从正八卦门槛40级起提供。原道具文案列有1015的仙盟宝库、跨服战场、跨服争霸赛、释厄副本来源，1016／1017／1206写活动期间集市出售；这些是原文案【A】，不代表各来源的历史掉率、当前全链路均已证实。上述常驻商品、价格和包数量均为B。

仅逆位部分：八位开齐需要1017×16；再开完16个法术槽需要1017×16，合计32个，不包含正位前置花费。

### 3.2 洗炼概率及预览处理

属性洗炼在四维中均匀选择来源，再从另外三维均匀选择目标，12种有序方向各1/12。固定转移5‰；来源不足5‰只转移剩余值，来源为0则可能产生0转移。确认后四维比例总和不变，不出现负数。

法术洗炼均匀抽取1～5级并裁剪至500级。499级时五种抽取都会变成+1。预览先扣费，确认才生效，放弃不退款；再次预览覆盖旧结果并重新扣费。有待确认结果时不能直接升级法术能力，避免先升级再确认造成越界。

预览按正／逆全局位号独立保存，不能拿另一位的结果确认，也不能混用属性和法术确认请求。同一成功结果只应用一次。

### 3.3 属性、战斗与换人

`目标四维增加量 = 助阵神仙本轮基础结算四维 × 该逆位对应传递比例`

例如未洗炼的10级逆位，助阵神仙基础攻击10000、生命100000，目标增加攻击1750、生命27500。多个正／逆位指向同一个目标时累加，不把上轮结果再次当输入。

被动法术使用目标本轮基础属性×法术效果百分比×法术能力倍率；参悟生命收益沿用已实现的参悟规则并乘相同倍率。神仙、阵位和对应法术槽均须实际有效：未开阵位、未开槽的残留装备不产生额外收益。加成进入统一属性与战力结算，已有战斗模块继续使用这套结果。

一个神仙不能同时上阵和助阵，同名神仙不能重复占主阵／助阵。目标按阵位绑定，换人由新神仙继承，阵位变空则清除目标。法术跟随助阵位，自带法术跟随神仙。清空助阵／目标／被动法术用对应请求的id=0，是本地补全约定。

### 3.4 存档兼容与可靠性

- **本次修复**原本从bit0开始的错误槽位编码。无版本标记的旧本地存档按 `(旧值 & 0xFFFF) << 1` 迁移正／逆掩码，写入 `cheer_skill_mask_version=2`。重复读取、保存和重连不会再次移位，已开槽不重复收费；不会凭空补开其他槽。
- 对来源不明、已经手工写成原版正确掩码的导入存档，应同时标记版本2。无版本旧档默认按此前本项目编码处理，这是B迁移假设。
- 逆位法术等级始终保存0～500。1017暂发不超过255，随后1032同步完整值；此兼容发送顺序属于B。
- 请求失败不保存部分扣料、扣款或装备状态；会话内相同序列号的相同请求重放原回复，不重复消费。不宣称跨服务重启有全局幂等键。
- 已有逆位进度不会因新增开位校验被删除，新增开位执行完整前置条件。本次验证使用临时数据库，未消费正式账号资源。
