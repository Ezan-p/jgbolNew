# 基础游戏服务端

对应图片中的第一步：服务端持续监听，接收客户端发来的请求，并把请求到达的证据记录到日志。入口为 [game_server.py](../game_server.py)，复用项目现有接收器，无需启动模拟器、ADB 或 Frida，只依赖 Python 3 标准库。

## 启动与停止

双击项目根目录的 **`启动基础服务端.command`**，默认监听 `127.0.0.1:18770`，自动进行 HTTP 自检并持续前台运行。终端会显示监听地址和本次日志目录。按 **Ctrl+C** 停止；收到 SIGTERM 也会关闭监听、所有连接并写入结束日志。

也可以在项目根目录运行：

```sh
# 持续监听
python3 game_server.py

# 实际建立本地 TCP 连接，验证健康检查和两个服务器列表端点
python3 game_server.py --probe

# 自检后运行 10 秒并退出
python3 game_server.py --probe --duration 10

# 使用其他端口；终端仅显示启动提示，事件仍写入日志
python3 game_server.py --port 18771 --quiet
```

`--port` 接受 1024—65535；`--duration` 接受有限非负秒数，0 表示不限时。监听端口已被占用时会明确报错并退出，不会停止其他进程。自检失败返回非零退出码。

## 验证客户端请求

保持服务端运行，在另一个终端发送请求：

```sh
curl -i http://127.0.0.1:18770/__redirect_health
curl -i http://127.0.0.1:18770/update/jgb/p360_a/server_list.txt
curl -i http://127.0.0.1:18770/example
```

健康端点返回 `200` 和 `JGBOL_LOCAL_REDIRECT_OK`；服务器列表返回缓存快照；第三条未知路径返回 `501`。服务端终端和会话日志都能看到连接、HTTP 方法、Host、路径、状态和响应字节数。`--probe` 自动验证健康内容和两个列表端点的完整响应字节，并写入 `probe_result`。

## 接收边界

| 流量 | 基础服务端行为 |
|---|---|
| `GET`／`HEAD /__redirect_health` | 返回健康标记 |
| `GET`／`HEAD /update/jgb/p360_a/server_list.txt` | 返回已有服务器列表原始快照 |
| `GET`／`HEAD /update/jgb/p360_na/server_list.txt` | 返回同一份快照 |
| 支持方法下的其他路径 | 返回 `501 Not Implemented` |
| TLS 请求 | 记录到达并关闭；不提供证书或 TLS 握手 |
| 原始 TCP 请求 | 记录字节数，不提供游戏业务应答；空闲超时或达到接收上限后关闭 |

服务器列表来源为 `analysis/server_lists/server_list.raw.txt`，保留原始内容，不自动访问线上获取数据。基础服务不处理 SDK 登录、角色、战斗、存档或资源更新。相关业务属于现有的 [本地离线服务](本地离线服务.md)。

## 游戏接入与已有模式

独立服务只负责接收，客户端必须连接到这个地址才能产生日志。`127.0.0.1` 只对当前主机有效；Android 模拟器内的回环地址属于模拟器自身，不能直接当作 Mac 地址使用。

**实际游戏接入请使用已有的 `启动本地重定向.command`，无需先开独立基础服务。** 该脚本本身已包含同一个本地接收器，同时负责启动模拟器、配置 `adb reverse` 和注入游戏重定向，详见 [本地重定向](本地重定向.md)。它和独立基础服务默认都使用端口 18770，不能同时占用该端口；切换前先在独立服务终端按 Ctrl+C。仅更改独立服务端口不会自动更改游戏目标地址。

`启动本地离线游戏.command` 则显式启用已有离线业务后端。基础服务入口不启用此后端，不修改原游戏或离线模式。三者共享接收器实现，但启动职责不同。

## 日志

每次运行新建 `.runtime/server/sessions/<会话>/`：

- `events.jsonl`：结构化连接、HTTP／TCP／TLS、自检、启动和停止事件。
- `console.log`：对应的可读日志。
- `session.json`：本次端口、模式、服务器列表来源等元数据。
- `summary.json`：正常停止后的事件计数和日志轮转配置。

每种事件日志单文件默认最多 8 MiB，保留 4 个轮转备份。请求日志不包含请求体、URL 查询参数、认证头或原始 TCP 载荷；沿用观测模块的常见凭据脱敏。会话目录长期保留，便于逐次复核。

## 本次验证

2026-10-24 已完成 30 项自动化检查，覆盖独立入口自检、参数校验、端口占用、SIGTERM 清理、分片及并发连接，以及原离线 TLS／登录／存档协议回归。

独立服务在 18771 接收到 Android 模拟器经 `adb reverse` 发送的请求：健康检查返回 200，服务器列表返回完整的 59,531 字节，未知路径返回 501；另外验证了 TCP 和 TLS 到达日志。测试服务和临时映射已清理。

沿用原离线配置重启游戏接入服务后，原游戏进程请求 `jgbupdate02.shangyoo.com/update/jgb/p360_a/server_list.txt`，本地 18770 返回 200，59,531 字节及 SHA-256 均与快照一致；DNS、IPv4／IPv6、Java HTTPS 和 native HTTPS 自检通过。该接入服务在本次验证结束时保持运行。证据见 [basic_server_validation.json](../analysis/evidence/basic_server_validation.json)。

```sh
.runtime/venv/bin/python -m unittest discover -s tests -v
```

同一连接的事件共享 `connection_id`，可将 `local_accept`、请求事件与 `local_close` 对应起来。`local_close` 保存关闭原因、连接时长，以及 `read_bytes`／`written_bytes`：它们统计接收器实际从 socket 读取、向 socket 写入的字节数，并非客户端发送的全部数据。基础 HTTP 接收器不消费请求体，因此未读取的请求体不计入 `read_bytes`。
