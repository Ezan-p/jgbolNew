# 仙佛密卷原版规则与修复说明

日期：2026-10-26；适用版本：本仓库金箍棒3.87离线游戏。

2026-10-28补充：大库存使用卡顿、闪退已修复，原因、界面变化和原生验证见第六节。

用户所称“仙踪密卷／高级仙踪密卷”，在本原包道具表中的正式名称是**仙佛密卷／高级仙佛密卷**。以下按原名说明。同名不同经验是原版的20档、40个独立道具配置，不是重复脏数据，也不应按名称合并或统一经验。

【A】表示原包CSV、Lua字节码或协议能直接证明；【B】表示原服务端缺失时采用的离线结算策略。客户端预览能证明客户端算法，不能据此断言原服务器的全部边界处理。

## 二、【A】原客户端选择、请求与升级预览

依据：[expbookUI原包字节码与数值常量](../analysis/evidence/expbooks/ui_expbookUI.txt)，其中`[L…]`是原Lua源行号。

1. `createExpbookMutilSelectLayer`（L304–419）从背包读取经验大于0且`sub_type=99`的材料，展开各堆叠的数量，保存各自的`type_id`、显示档位、名称和经验。经验丹是另一个页面（`sub_type=100`）。
2. `sendEatExpbookRequest`（L953–986）将选中材料按`type_id`汇总为`{type_id,count}`，发送1059：`first_send=true, flag=1, cortege_id, roll_count, roll_list`。`roll_count`是不同模板的条目数，不是总卷数。返回事件65；`flag=2`是经验丹，`flag=3`是药神殿药灵丹。
3. 例如2卷1041、1卷1043、3卷1042，原始经验为`2×1200+10000+3×2480=19840`；1059中的列表为3项。同名的1041和1043不会合并成一个模板。
4. `getExpResult`（L851–904）按[cortege_experience.csv](../analysis/configs/cortege_experience.csv)中神仙**品质和当前等级**对应的升级消耗逐级计算；跨级后继续使用新等级的效率，而非对整批统一打折。
5. 原初始化L84及`isMorethan80`规定下列效率。令主角等级为R、神仙当前等级为L：

| 条件 | 本级经验效率 |
| --- | ---: |
| R＜80，L＜floor(2.5R) | 100% |
| R＜80，floor(2.5R)≤L＜3R | 20% |
| R＜80，L≥3R | 0% |
| R≥80 | 100%（仍受等级上限限制） |

主角21级时，衰减从神仙52级开始。若神仙51级距升级差100经验，使用1041的一卷1200经验，先用100升到52级，剩下1100按20%结算，得到52级、当前经验220；本次实际增加320经验。

6. `getMaxLimitLevel`（L801–808）读取洞府主建筑的`coretege_limit_plus`，基础为200。原表拼写确为`coretege`，后端存档使用`cortege_limit_plus`。[洞府原表](../analysis/configs/hole/main_building_config.csv)与现有`activity_home.prepare`已接通，不需要再建一套上限。
7. “全选”`selectAllExpBook`（L604起）有预选控制：主角80级前以`floor(2.5R)`作为预选停止目标，80级起取洞府上限，并受经验表长度约束。因此“全选”不保证选中整个背包，也不等于在衰减段手动使用无效。

## 三、【B】离线结算与边界策略

以下服务端约定沿用或补强本地实现，不能认证为原服规则：

- 使用上限取`min(该品质经验表最高等级, 200+洞府附加值)`；主角低于80级时再限制到`3×主角等级`。已经满级时整笔拒绝，不扣材料。
- 当前未满级的一笔请求，扣除全部明确选择的卷数；升到上限后当前经验归零，溢出不储存、不退卷。这是本地既有策略；原客户端最高级的预览存在继续累加当前经验的分支，故不能把服务端丢弃溢出标成【A】。大额高档卷接近上限时应少量选择。
- 2026-10-29 按用户指定改为：每升一级，读取 `cortege_evolve_config.csv` 中对应品质、升级后等级的 `culture_point`；连续升级逐级累计。经验书、经验丹、战斗和传承共用该规则。
- 所有ID、页面、数量、目标和未锁定库存必须有效；同模板重复列表项拒绝。同一模板可以跨多个未锁定堆叠扣除。整批先验证再扣除，后端继续用独立角色副本和序列号缓存保证失败不保存、原包重放不重复扣书。
- 衰减使用十进制计算，累计当前经验后才转成存档／协议支持的数值，避免小数逐次二进制相加的尾差。不额外向上或向下取整；原服取整策略未知。
- 成就117的名称、描述、首次5点道行、不可重复是【A】；将1059／flag=1成功消耗任一有效密卷作为触发条件是【B】。以真实库存减少为准，所有40个ID覆盖；普通和高级都有效。经验丹、药灵丹、卖出、仅查询、失败与缓存重放均不应完成该成就。
- 不追溯赠送旧成就奖励。历史已消费日志不足以可靠重建每个账号的记录，下次成功吃任一档密卷即可按原表完成117。

## 六、2026-10-28 大库存使用卡顿、闪退修复

### 原因与修复

实际账号有22,536,962卷密卷、17种模板，其中1041占22,536,943卷。原客户端L328–335按每卷新建Lua条目，L354排序全部条目；使用成功回调L1004还会再次重建。安卓内核在16:38、16:58、17:03均记录游戏被`lowmemorykiller`终止，最后一次进程占用约1.3GiB，见[崩溃日志](../analysis/evidence/expbooks/crash_lowmemory_20261028.log)。服务端按模板结算，没有逐卷展开。

新增[客户端适配](../network_redirect/expbook_client.lua)，由`summon.client_source`加载，关闭服务时恢复原函数：

- 普通／高级密卷按`type_id`合并展示，同名不同档位保留独立行；显示已选数与库存。经验丹共用的页面同步适配。
- 多卷条目点击后使用原生数量弹窗，默认1卷；单卷直接选择，再点已选行取消。原经验预览、衰减确认及1059协议保持兼容。
- 全选按等级经验表计算剩余预算，再按各模板单卷经验计算数量，避免逐卷循环；保留原版全选不跨效率阈值／等级上限的约束。
- 使用成功后按最新库存重建；清除跨页残留选择，忽略已经关闭、切页或更换神仙后的旧数量回调；锁定堆叠不计入可用库存。

本次没有删减、迁移正式背包道具，也没有调整40档单卷经验、服务端升级规则或奖励概率。
