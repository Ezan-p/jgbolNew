**2026-10-27道具更新：** 小包子1020已接入背包单次恢复5体力；本地规则与普通包子1022的每日额度分开。1020／1022／1023成功回包均补齐原提示必需的 `effect_value`。规则边界和验证见[专项说明](小包子与贡献令使用机制及调试说明.md)。

复核日期：2026-10-26。适用客户端：仓库内金箍棒 3.87 原包。实现：本地离线服务端。

**【A】原版规则**表示原包 CSV、Lua 字节码、协议或客户端实际回调可直接证明的内容。**【B】推测规则**表示缺少原服服务端代码、配置或战报时采用的本地策略。原表的概率数值属于【A】，服务器如何组织抽奖属于【B】，二者不能混写成“已还原原服算法”。

### 【B】服务端解释

服务端重新检查前置、等级、体力、出战阵容及次数，不能只依赖客户端按钮。8888 按占位排除出模拟，其空位在 1028 中用零值表示，后续敌人不重新编号。**占位常量和界面行为属于【A】，排除出服务器模拟的具体方式属于【B】**；没有原服战报可证明其服务器内部表示。

敌人属性按原表基础值加成长乘以 `(等级−1)` 后取整；释厄没有 `skill_level` 字段，缺省使用 1。服务端公式、取整与缺省处理列为【B】，不改动原表数值。

## 3. 战斗、星级与结算顺序

### 【A】协议与客户端行为

1. 1026 提交 `fight_type/des_type/des_value/des_id`；旅途目标为 `des_type=1,des_value=0`，关卡 ID 为 double。客户端不提交胜负或伤害。
2. 1028 为初始阵容，1027 为结果和动作；每条动作提供技能、双方、站位、回合和八个伤害槽。event 121 携带效果事件，event 44 启动原版战斗回放。
3. event 45 传经验：角色 `obj_type=1,exp_plus`；神仙 `obj_type=4,exp_list`，经验表按出战位置索引。
4. 胜方剩余总血量不少于 70% 为三星，不少于 40% 为二星，其余一星，见 `fightUI:1774–1869`。结果 1/2/3 为我方胜、4/5/6 为对方胜、0 为平局或未决。
5. 回放完成后客户端发送 event 3；服务端只确认，不再次发奖。
6. `mapUI:139–152` 用最后战斗关卡的原表经验与银币展示结算。1019 会修改该标记，所以新开放但未挑战的关卡只发 1020。

### 【B】战斗模型及结算

使用现有 [战斗机制重建 V2](战斗机制重建V2.md) 与阵位规则：按攻后、防前、攻前、防后、攻上、防下、攻下、防上行动，替补在对应首发阵亡且未复活后登场。伤害、法术、精魄、星宿免死、如来护盾等采用现有候选服务端模型；不声称与原服公式完全一致。

最多 240 个动作，效果事件另有字节预算。双方尚未全灭而达到保护边界时返回未决，不能凭血量比例伪造胜利。失败与未决仍消耗本次体力和次数，不增加星级，不消耗首胜和首次三星资格。

| 结算项 | 当前【B】策略 |
| --- | --- |
| 角色经验 | 原角色等级表 `win_exp/lose_exp × 体力消耗`，处理连续升级及阵位额度 |
| 神仙经验 | 胜利给原关卡 `exp`，失败给 50%；按出战位置发放，等级上限沿用阵容模块；满级不再累积经验 |
| 银币 | 胜利给原关卡 `money`，失败为 0 |
| 首胜额外经验 | `first_win_prize` 第一段为数量、第二段作为百分比，抽中后加给各出战神仙；不加给角色。原字段标注 `exp_count|rate`，具体接收对象仍属推测 |
| 星级 | 保存历史最高星级；重复低星不会降低已获星级 |
| 天赋 | 关卡 `genius_prob`、天赋目标及属性来自原包【A】；触发后战前单体 +20%／全体 +10% 为角色资料模块的【B】配置，event 44 回传表现信息 |

## 4. 奖励、概率与防重复

### 【A】原表结构

关卡奖励格式为 `对象类型|类型ID|数量|等级|概率`，多条用 `/` 分隔；章节奖励为 `对象类型|类型ID|数量|概率`。对象 4/5/6/7/11/12 分别对应神仙、物品、法术、魂魄、元宝、银币。

| 奖励字段 | 【A】原始含义/数值 | 【B】发放策略 |
| --- | --- | --- |
| `first_random_prize` | 首次随机奖励 | 首次胜利且该字段非空时替代普通随机列表；失败不消耗资格 |
| `random_prize` | 通常随机奖励 | 胜利逐条独立抽奖，不保证一定掉落，不另加隐藏保底 |
| `com_win_prize` | 大胜奖励，客户端有独立展示 | 首次达到三星时结算一次，重复三星不再发 |
| `first_win_prize` | 两段经验/概率，例如普通 308 关为 `800|100` | 首次胜利抽取一次，按前节策略授予经验 |
| `pass_map_prize` | 普通每章配置包子 1022×1，概率 100 | 本章全部三星可领一次，flag=3、id=章节号；服务端再次校验并持久化已领标记 |

普通物品奖励出现概率值：0、10、15、20、30、100；释厄出现 25、30、40、50、60、100。它们是原表的值【A】。本地统一使用 `secrets.randbelow(100) < rate`【B】：0 不掉、100 必掉，每条、每场、每次扫荡分别抽取；不存在把整列当权重后“只选一件”的实现。

例：释厄 101 的重复胜利为 50% 掉落物品 2035；首次三星另给 30 元宝。释厄 201 的首次三星为 4 级武器灵石 1090，发放和显示都保留等级 4，不降为 1。普通 105 首胜及首次三星分别按原表发放 2038、2030。

命中奖励先写入角色副本并同步库存，再发 event 22：`prize_type=1/2/3` 对应随机、大胜、章节奖。经验、货币、掉落、次数及进度同笔保存。章节重复领奖、同请求重复包均不重复奖励；首次概率未中后也不会无限保留首胜抽奖机会。

旅途胜利与扫荡还调用现有节日模块的 `travel_drop`。节日额外物品依赖本地活动配置【B】，不属于上述原版关卡 CSV 掉落；概率测试和验收报告将两者区分。

## 6. 保存、跨日和回放

【B】以 UTC+8 零点重置关卡已用次数、刷新次数、释厄总次数、资源物品次数，保留星级、已领奖章及扫荡时间。自然恢复按离线经过的时间计算。

地图查询返回完整分片和资源属性；在线跨日使用不重建地图对象的增量分片，防止已打开关卡面板仍引用旧表。战斗时只以本次关卡发送 1019，保留正确剧情和奖励显示。

【B】会话内缓存最近 256 个旅途变更请求，同序号同包返回原回复，同序号异包及过期序号拒绝；重新登录清除会话缓存。这不等价于跨会话业务交易 ID，无法把重连后重新发送的新序号自动识别成同一笔操作。章节领奖和首胜资格另有持久化标记。
