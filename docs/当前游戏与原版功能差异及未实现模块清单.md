# 当前游戏与原版功能差异及未实现模块清单（3.87）

复核日期：2026-10-26（Asia/Shanghai）。对象为本仓库当前工作区，**包含未提交与未跟踪的实现文件**。对照材料是3.87原包提取的Lua字节码、协议、CSV，以及当前本地后端、客户端补丁和规则配置；不是与仍在运行的官方服务器做在线比对。

## 1. 当前结论

基础登录、战斗、阵容、主角和神仙养成、装备、宠物、灵阵、成就及大部分常驻活动已经有本地实现。当前缺口集中在**社交关系与跨账号互动、月卡和部分旧运营入口、旧跨服天梯、尚未接入的活动，以及已实现玩法中的少量子分支**。多数多人玩法已有NPC替代，不能再笼统写成“活动、竞技、组队或仙盟完全未实现”。

本次可复跑检查的结果：

| 指标 | 结果 | 统计含义 |
|---|---:|---|
| 原版具名Lua中扫描到的直接发送请求ID | 154 | 包含登录请求；仅是能被静态发送窗口识别的集合，不是协议全集 |
| 其中本地无业务路由的请求ID | **43** | 用真实 `Backend.respond` 分发确认，均落入 `game_unimplemented` |
| 旧59项中现在已有路由 | **16** | 已从“无路由”名单移出；有的仍是NPC替代或部分实现 |
| 旧21项暂缓活动中仍未接入 | **19** | 锻造、天工制物阁已接入，应移出 |
| 旧活动表漏列、当前仍未接入 | **1** | 入口21周末小游戏；其1308协议已在旧59项协议附录中，并非新发现的请求 |
| 本文列出的未接入活动入口 | **20** | 上述19+1；与43个请求ID重叠，不能相加 |

**43个请求不等于43个玩法，也不能据此算完成率。** 一项活动可有多个请求；1097聊天、1303组队、1350血战等已有路由的协议还存在分支限制；原渠道账号、版本上报及关闭活动也包含在43项内。原包有发送代码不等于当前按钮一定可见，等级、菜单开关、活动时间和补丁都会影响入口。

### 状态口径

| 状态 | 判断标准 |
|---|---|
| 未接入 | 原包有请求发送证据，当前后端没有对应业务路由 |
| 部分接入 | 已进入处理器，但部分动作被拒绝、固定空返回或缺少后续结算 |
| 离线替代 | 已有可运行结算，用NPC、单角色状态、本地榜单或模拟充值代替原在线服务 |
| 有意关闭／替代 | 例如跳过新手引导、关闭合服补偿、本地登录替代旧渠道；列出差异，不当作必须补回的错误 |
| 待确认 | 只有协议定义或物品文案，未找到可靠的原版发送入口；不能据此宣称玩家功能缺失 |
| 规则待校准 | 功能已经实现，但隐藏概率、服务器公式和赛季策略采用推测；不等同于“未接入” |

## 2. 证据、复核方法与验证范围

主要入口：

- [原版协议定义](../analysis/协议定义表.md)、[原始协议表](../analysis/evidence/protocol_tables.json)、[具名Lua提取目录](../analysis/evidence/lua_named)。
- [Backend分发](../network_redirect/backend.py) 的 `_respond`、模块 `HANDLED/handles/settle`，以及 `network_redirect/*_client.lua` 中的菜单适配。
- [本次机器证据](../analysis/evidence/server_integration/current_audit.json)：154个发送ID、客户端位置、分发采样、43项缺失、16项变化及源文件SHA-256。
- [可复跑审计脚本](../analysis/tools/audit_server_integration.py)。项目根目录执行：

```sh
python3 analysis/tools/audit_server_integration.py
```

脚本扫描 `main_server_send_msg` 后12行内、首次CALL前的协议名，使用原协议编码器生成合法结构请求。它不初始化Backend数据库，在业务处理器入口拦截；无路由请求则真实执行到未实现分支。带序号的缺失请求返回事件55，1326无序号返回空列表。共用协议额外采样 `channel/event_id/flag/fight_type`；这不是穷举所有参数。

因此，机器结果只证明**分发存在或缺失**。本文对空列表、分支拒绝、NPC替代、奖励来源等判断还使用人工代码复核。不会将业务入口被拦截后的结果写成“已完成业务测试”。

另对三种普通乾坤袋和仙佛密卷执行了**4个临时数据库协议探针**，验证第5节的业务断点，见[探针请求、回包、前后状态与源码哈希](../analysis/evidence/server_integration/growth_branch_probes.json)。这些探针执行了真实业务处理，与前述仅检查分发的脚本分开记录。

本次没有操作模拟器、真实角色存档、充值或官方服务器，没有重新执行全量回归。专项文档中的测试数、通关和实机截图属于各自历史验证，不能合并成一次新的全游戏验收。原版服务端源码与历史线上配置缺失，原客户端证据【A】和本地推测【B】仍须分开。

### 宠物：不能把“没有购买／抽取协议”直接解释为缺功能

原 `petUI` 的1330操作是吞噬、融合、选择出战、进入、培养、升星，界面的“召唤”指选择出战，并无独立买宠物／抽宠物请求。当前还有初次进入赠宠、仙盟游历捕捉、类别15奖励及洞府相关来源。因此不能以“缺少1330抽宠操作”创建一项所谓原版未恢复功能。

“宠物任务”也不是只有物品文案：原 `pethuntUI` 使用1301的任务查询／操作，当前 `guild_hunt.py` 成功任务发1346驯养宝箱，1051开箱产出1345驯养丹。当前每次成功任务1箱、每箱15丹为【B】配置。不能再把这条任务／开箱链记作完全缺失。

独立宠物、仙盟兽栏、洞府幻化虽有奖励衔接，不能混为一个数据系统。初始赠送、概率和部分材料投放属于本地补全策略；官方全部获取渠道仍需原版入口／运营数据证据，不能据此臆造另一套1330任务或抽取操作。

### 仙盟剩余差异

以下是后续开发建议，本次仅更新分析与文档，不更改游戏开放状态。

| 优先级 | 范围 | 推荐理由与验收条件 |
|---|---|---|

| P1 | 月卡闭环、关注／搜索范围／聊天、试炼好友分支、消息详情1220 | 都涉及已有页面的交互断点。先定义NPC替代或真实账号语义；验证原按钮、失败回调、存档重登、双方状态或明确离线结果 |
| P2 | 土地公1068、回归1345、升级奖励／消费奖励／旧促销 | 按原协议恢复完整循环；有资格和时间判断、扣费／到账、重复请求保护，不能仅填一个成功提示 |

每个实现至少验证“原入口 → 请求 → 服务端校验 → 状态更新 → 原客户端回调 → 重登一致”。涉及资源要覆盖失败不扣除、重复不发奖；涉及时间要覆盖到期、跨日、跨周；涉及战斗要覆盖胜、负、未决与回放。路由审计是发现缺口的工具，不替代这些验收。
