# 仙缘果功能与使用调试说明

日期：2026-10-26；适用版本：本仓库金箍棒3.87离线游戏。

仙缘果（道具ID **1246**）已接通：从背包选择目标，将果子兑换为指定神仙魂魄或五星五法界魂。本次修复了**兑换列表为空**和**使用请求被当作普通界魂兑换而拒绝**两处断点，沿用原客户端界面与协议。

【A】表示原包CSV、Lua字节码直接可证；【B】表示原服务端缺失时的本地补全。兑换倍率、选择方式和特殊神仙限制有【A】依据；完整目标名单来自原服务器下发，原包没有保存，因此本地名单明确属于【B】。

## 一、怎么使用

1. 更新代码后重启本地离线服务，重新进入游戏。代码与名单在启动／登录时加载，无需重打APK。
2. 在背包找到“仙缘果”，点击“使用”，打开神仙／界魂选择界面。
3. 选择目标，调整“转换数量选择”。每次可用 **1～15颗**，库存少于15颗时以库存为上限。
4. 查看“获得数量”，确认兑换。成功后关闭选择界面、显示奖励，背包和魂魄数量同步更新。
5. 神仙魂魄在神仙的魂魄页面查看；五法界魂是背包道具。魂魄达到合成条件后，需要另行点击合成，不会因使用仙缘果而自动生成神仙。

每颗果子的兑换量如下；批量使用按数量相乘：

| 所选目标 | 每颗获得 | 判断方式 |
| --- | ---: | --- |
| 尚未拥有的普通开放神仙 | 对应魂魄1个 | 当前神仙列表中没有该神仙 |
| 已拥有的开放神仙 | 对应魂魄10个 | 当前神仙列表中存在该神仙，不要求上阵 |
| 五星仙／妖／人／魔／佛界魂 | 所选界魂10个 | 无需事先拥有该界魂 |

**王母5027、元始天尊5046、如来佛祖5053必须当前已拥有，才会出现在仙缘果可选神仙中。** 这是原客户端的特殊过滤，不是名单漏项。只有该神仙的魂魄、曾点亮图鉴、已经回收掉神仙，都不满足当前拥有条件。

例如：未拥有某个普通开放五星神仙，使用15颗得到15个魂魄；攒到40个后，按原五星合成门槛合成该神仙，此后每颗可换10魂。本次验证了15＋15＋10颗→40魂→合成→再次使用获得10魂的完整后端流程。

本地兑换不收银两或元宝；这是与界面无费用提示相符的【B】结算选择，不代表恢复了原服务端收费实现。以后再使用所得五法界魂进行普通界魂兑换，仍遵循[神仙模块](神仙模块规则与调试.md)的独立条件和银两费用。

## 二、原版依据【A】

可复核附件：[原包核查报告](../analysis/evidence/xianyuan_fruit/official_audit.json)、[客户端字节码摘录](../analysis/evidence/xianyuan_fruit/client_contracts.txt)。摘录中的`[L…]`是原Lua源行号。

- [item_base.csv](../analysis/configs/item_base.csv)第186行：`type_id=1246`，`main_type=6`、`sub_type=3`、可堆叠、`use_limit=1`。这里的`use_limit`不能解释为每次只能用一颗；原专用界面明确支持最多15颗。
- [item_name.csv](../analysis/configs/item_name.csv)第186行写明“可指定获得顶级神仙的魂魄”，来源文案为“魂缘万寿山”。通用分类为随机袋，并不意味着这个专用使用入口随机抽取目标。
- `packageUI.requestUseItem` L1859–1860：遇到1246，调用`kickUI.showFruitUseLayer(parent,30)`；30是界面层级参数，不是消耗数量。
- `common_def.client_config_type.longer_hill=27`，`data.set_g_new_config` L3835将配置27交给`kickUI.onGetCortList`。
- `onGetCortList` L198–210使用`object_type → {模板ID: 真值}`结构生成目标列表；不能传模板ID数组，否则客户端会把数组下标识别为目标ID。
- `getFruitCorts` L1095–1125遍历下发目标，按当前神仙列表区分是否拥有，并过滤未拥有的5027／5046／5053。五法界魂另走道具分支。
- `showFruitUseLayer` L1173–1176将数量选择上限限制为15；L1187–1199规定已拥有神仙、界魂倍率10，未拥有神仙倍率1。
- 确认按钮 L1238–1266校验目标和果子数量，然后发送1051。目标魂魄使用`des_type=10`，界魂使用`des_type=5`；`des_id`是目标模板ID，不是已拥有神仙的实例ID，也不是神仙对象类型4。
- `commonLayerUI.recvUsedItem` L464–466关闭仙缘果选择层，L526–538刷新背包并用`attach_list`展示奖励。

请求示例：

```lua
-- 使用3颗，兑换当前已拥有的沙悟净5004魂魄，应获得30魂。
-- item_id必须替换为背包中的仙缘果实例ID。
{item_type=1246, item_id=仙缘果实例ID, item_count=3,
 des_type=10, des_id=5004}
```

成功回调为2998／事件21，包含`result=1,type_id=1246,count=消耗颗数,attach_list=实际奖励`。服务器先发送道具增减、背包快照1035、魂魄快照1046，再发送成功回调，避免结果已显示但背包或魂魄仍是旧数值。

## 三、本地名单与结算边界【B】

配置在[immortal_rules.json](../server_config/immortal_rules.json)的`xianyuan_fruit`中，明确标记`mode=inferred`。启动时校验目标存在、五星品质、无重复，并验证道具目标属于界魂。

本地神仙候选取自[adaptive_spirit_convert.csv](../analysis/configs/adaptive_spirit_convert.csv)中的46个五星条目；该表原本是界魂兑换表，**不是已恢复的仙缘果官方名单**。用它补足名单是本次离线策略。客户端再按三名特殊神仙的拥有条件过滤，通常显示43个神仙候选和5种界魂，最多46个神仙候选和5种界魂。完整ID与原名见核查报告的`offline_soul_targets`。

五法界魂目标如下；这些道具ID与神仙ID有重号，必须结合对象类型区分：

| 对象类型 | 模板ID | 道具 |
| ---: | ---: | --- |
| 5 | 5001 | 五星仙界魂 |
| 5 | 5002 | 五星妖界魂 |
| 5 | 5003 | 五星人界魂 |
| 5 | 5004 | 五星魔界魂 |
| 5 | 5005 | 五星佛界魂 |

本地结算还规定：

- 按请求处理时的当前神仙列表确定倍率，不以历史图鉴或魂魄数量代替拥有状态；不额外加角色等级、VIP或活动开启条件。
- 每笔限1～15颗，非法目标、无效实例、库存不足均拒绝，不扣材料、不发奖励。
- 只消费未锁定、未装备／绑定到神仙、等级1且数量正常的果子。请求指定的实例也必须有效。
- 原客户端按模板汇总数量、只发送一个实例ID，因此支持跨可用堆叠扣除：先扣请求指定堆叠，再扣其他可用堆叠；锁定堆叠不参与。全部校验完成才开始扣除。
- 得到的魂魄／界魂以有符号32位数量上限保护；超限整笔拒绝。该边界是本地策略。
- 沿用神仙模块的请求序列号缓存、过期请求拒绝和先编码后保存机制。同一连接中的相同请求重放返回缓存结果，复用序列号改参数拒绝；编码失败不保存半笔结果。重启后保留的是兑换后的存档，响应缓存并不跨进程持久化。

## 四、怎么获得仙缘果

| 来源 | 原版证据 | 当前离线实现 |
| --- | --- | --- |
| 魂缘万寿山 | 道具来源文案及`kickUI`、1323协议 | 活动1323的摘果、法力、积分和排行仍未接入；本次只修复背包道具使用 |
| 通天塔56～60层 | [层段奖励表](../analysis/configs/babel_tower_floor_prize.csv)第13行含`5\|1246\|1` | 已进入该层段奖励候选池；抽取方式与地图分配属于既有【B】实现，并非到56层必送 |
| 天机阁飞升礼包首次兑换赠品 | [exchange_zone.csv](../analysis/configs/exchange_zone.csv)第2行`gift_prize=5\|1246\|1\|10` | 当期首次兑换飞升礼包后，通过“天机阁首次兑换好礼”邮件发放10颗，领取附件后才进入背包 |

最后一项以[天机阁实现](天机阁离线活动实现说明.md)为准：旧全道具图鉴将`exchange_zone.csv`笼统标为“仙灵店铺礼包及赠品”，该标签不足以证明仙灵店铺出售仙缘果；当前代码实际使用它的是天机阁。现有仙灵店铺专项商品配置不含1246。

本次没有赠送或修改正式账号的果子，也没有新增获取掉率。万寿山活动未接入，不影响从其他已实现途径获得的果子在背包使用。

## 五、故障、修复与验证

原来有两处独立断点：

1. 登录配置缺少27，`g_self.cortege_list`没有目标来源，专用界面只能得到空列表。
2. 1051到达`immortal.exchange`后按普通界魂检查`main_type=11`，1246的原表分类为6，因此被拒绝；该旧路径还要求`des_type=4`，与仙缘果发送的魂魄类型10不同。

- [backend.py](../network_redirect/backend.py)：首次登录与重连都下发配置27；沿用既有同步及原子保存流程。
- [immortal_rules.json](../server_config/immortal_rules.json)：集中配置本地目标名单和来源标记。
- [专用测试](../tests/test_xianyuan_fruit.py)：所有46个神仙目标、5种界魂、拥有状态、锁定／异常库存、跨堆叠、满扣、数量上限、失败回滚、重放、数据库重开、账号隔离及40魂合成流程。
