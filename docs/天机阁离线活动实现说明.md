# 天机阁离线活动实现说明

更新日期：2026-10-27。适用原版 3.87 客户端及本项目 Python 离线服务端。

【A】为原包证据，【B】为离线推测。本页记录入口47、destinyUI、1227/195的天机阁。旧文档误将其命名为天工制物阁，现已纠正；截图中的天工制物阁是入口32、mondayUI、1219/1243，见[天工制物阁实现说明](天工制物阁离线活动实现说明.md)。

## 1. 可游玩流程

1. 在“活动 → 奇闻”中进入天机阁，翻页查看三页、共九种礼包。
2. 点击活动内充值入口，进入现有金卡充值界面。消耗背包金卡结算本地订单，不发生真实支付，详见[金卡充值系统](金卡充值系统实现说明.md)。
3. 在“其他 → 消息”领取“天机阁充值金砖”邮件，再返回活动兑换。未领取邮件的金砖不会提前加入背包余额。
4. 可单次或批量兑换，选择减五／减十金砖卡。每个礼包最多用一张卡，客户端显示的实付与服务端扣除一致。
5. 每期首次兑换每种礼包，收到独立赠礼邮件；打开充值面板的全民奖励页，领取已达成的四档奖励，获得减金砖卡及其他资源。
6. 活动常驻，每14天刷新一次，主界面及全民奖励页显示“刷新剩余：天／时／分／秒”。退出、重登及服务重启后继续当期进度；刷新时立即进入下一期，没有关闭间隔。
7. 刷新时累充、全民充值送豪礼、兑换次数及首次兑换资格全部重置。剩余金砖（包括未领取邮件中的金砖）按1:1兑换为蟠桃，通过“天机阁金砖返还”永久邮件返还，旧金砖不保留。

入口、背包、券、奖励、邮件和成就均使用原协议。角色等级等原版客户端入口限制继续由原界面决定，服务端不新增无证据的等级门槛。

## 4. 充值、券和全民奖励

### 基础金砖与额外奖励

【本地规则】天机阁30级开启。充值结算复用入口等级门槛：未满30级时，正常充值到账及其他充值权益照常结算，但不累计天机阁充值本金、不赠送基础或阶梯金砖、不增加全民金砖进度，也不发送“天机阁充值金砖”邮件。达到30级后只统计新订单，开启前的充值（含零头）不补算；元宝、月卡、成长基金及背包金卡充值均遵循此规则。

【A】原界面写明“每充值1元可获得1个金砖”。额外奖励表如下：

| 原表充值门槛 | 额外金砖 |
|---:|---:|
| 10元 | 10 |
| 200元 | 40 |
| 500元 | 100 |
| 1,000元 | 200 |
| 2,000元 | 300 |
| 5,000元 | 500 |

【B】沿用本地充值换算：到账本金10元宝＝充值1元。只统计当期成功完成的新充值订单，礼包赠送元宝、首充翻倍、历史充值和普通元宝收入不计入。成长基金的金卡购买订单按本金计入一次，后续领取等级返还不算充值。

【B】六档按当期累计本金达标各自动赠送一次，并与基础金砖合成该订单的一封永久邮件。跨多档一次全部补发；零头本金保留，后续凑满1元才产出基础金砖。例：累计模拟1,000元，基础1,000＋额外10＋40＋100＋200＝1,350金砖。原表给出了门槛与奖励，但未提供“累计／单笔、叠加／择一”的完整服务端解释，因此这一结算方式明确标【B】。

### 用券【A】

```text
券总数 = ten_card + five_card，须不大于购买礼包数
实付金砖 = max(0, 单价 × 购买数量 - 10 × ten_card - 5 × five_card)
```

券和金砖都从未锁定、未装备、未绑定拥有者的普通背包物品中扣除。券超过售价时可将实付降为0，不产生找零、不返还券；原客户端已有超额抵扣提示。所有数量由服务端验证，拒绝数量0、越界商品、超限购买、伪造券数量和资源不足请求。

### 全民奖励【A／B】

| 全服累计获得金砖【A】 | 每账号奖励【A】 |
|---:|---|
| 10 | 减五金砖卡×1、金丝乾坤袋×5、银两×500,000 |
| 100 | 减五金砖卡×1、银绸乾坤袋×5、银两×1,000,000 |
| 500 | 减十金砖卡×1、银绸乾坤袋×5、金丝乾坤袋×5 |
| 1,000 | 减十金砖卡×1、银绸乾坤袋×10、金丝乾坤袋×10 |

【B】“全服”解释为同一本地数据库中实际账号当期获赠金砖总和，含本人，含已发邮件但未领取的金砖。不制造虚拟充值人数或NPC充值记录；已被继承的旧默认模板不重复计算。一个账号自己达到门槛也能完整游玩全部分支，其他账号可共享门槛进度。

【B】每个账号每期每档可领一次，不额外要求本人充值；奖励直接到账，状态1未达成、2可领取、3已领取与原版枚举一致。换期后，已领取标记与未领取资格均清除，全服进度只统计新一期获得的金砖；仍离线的账号旧期记录也不会计入。旧邮件中的非金砖附件保留，金砖附件统一结算返还。

## 5. 其他服务端补齐规则【B】

配置文件：[pavilion_rules.json](../server_config/pavilion_rules.json)。

- 默认常驻、连续14天一期，以北京时间1970-01-05周一00:00为全服固定锚点，每隔14天刷新。例：2026-10-26 00:00至2026-11-09 00:00，随后至2026-11-23 00:00。结束时刻归入新一期；玩家中途进入显示本期剩余时间，不从登录时刻重新计14天。这是本地需求规则，不是2018年原服日历。
- 飞升礼包原界面有“还需充值”和“提升购买上限”字段，但缺少数值表。本地采用每累计模拟300元增加1次额度，最多增加10次，即每期最高13次。其他礼包维持原表基础额度。
- `plus_times`的界面语义为**下一档可以提升的次数**【A】，本地每档返回1、达到最高额度后返回0【B】，不能返回已经累计增加的次数。2026-10-26复核修正了旧实现：未充值且基础3次用尽时，显示“还需充值300元／可以提升1次购买上限”；累计1000元且6次用尽时，显示“还需充值200元／可以提升1次购买上限”；累计3000元达到13次上限后，不再提示继续充值提升额度。
- 本期购买量 `bought`、充值本金 `charge_gold`、累计产出金砖 `bricks_earned` 及全民已领取档位 `claimed` 持久化并在换期归零。六档累充赠砖重新达标可再获得，飞升追加额度归零，九种礼包限购及首次赠礼资格恢复。全账号历史充值、VIP与订单去重记录不清除；重放旧订单不会计入新一期。
- 结算清除背包所有1141金砖（包括锁定堆叠），并移除所有未领取邮件中的1141附件；按总数1:1发放1001蟠桃。邮件正文列明背包数、未领邮件数、返还总数及重置原因。全金砖旧邮件标记为已结算，混合附件仅移除金砖，其余附件仍可领。已领取的历史邮件不再次计数。零余额不发空邮件。
- 优惠卡1142／1143、已兑换物品及非金砖奖励邮件继续保留。返还邮件永久有效，领取后蟠桃才进入背包，不增加新一期全民金砖进度。
- 首次赠礼邮件键包含周期起止及商品编号，充值邮件键包含周期起止及累计本金，返还邮件键包含旧周期起止。重复请求、重登和重启不重复返还；离线跨多期只结算实际持有的旧资源一次。
- 登录、活动请求、在线心跳、充值，以及读取／领取邮件前都会处理到期状态。直接领取旧充值邮件也必须先清算，无法把旧金砖带入新一期。返还、移除金砖与进度重置一并保存；投递或活动响应编码失败可回滚。
- **旧七天存档迁移**：更新后首次处理角色时，将旧期剩余金砖结算返还并清空旧期进度，切换到当前统一双周期。即使旧周起点与双周起点相同也只迁移一次；旧期邮件与新期邮件使用不同起止标识，避免键冲突。升级时有尚未领取的全民资格会按重置规则清除。
- 活动时钟只前进，回拨后拒绝消费及领奖，防止恢复旧周期重复获奖。
- 成就125“天工制物”归属入口32的天工制物阁，已取消天机阁误触发。旧存档已获得的成就不追溯扣除。
- 客户端沿用原界面布局，倒计时每秒读取最新周期结束时刻，零点请求刷新而不是关闭活动。等待新数据期间拦截旧兑换／领奖操作，新一期同步后关闭旧购买弹窗并刷新余额、限购、累充和全民奖励。重进清理商品／奖励缓存，兑换动画结束后更新准确剩余次数。
