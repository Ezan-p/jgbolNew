## 核心伤害与选择【B】

- 普攻：`floor(max(0.05A, A-D) × 强袭修正 × 格挡修正)`，再结合下述修炼、星宿等；最终实际生命损失不超过当前生命。
- 法术：`S=0.25A+3M`；`K=1.2+(I-30)×0.6/420`；`floor(K×2/(N+1)×max(0.05S,S-D)×[1-R(1-ρ)])`。强度超过450继续线性外推，不强制封顶。觉醒与星宿先修正强度。
- 原表装备顺序逐项试掷，首个成功的主动技能替代普攻；全失败则普攻。概率只决定是否触发，不乘成功伤害。
- 八人阵容固定出手顺序为：攻后、防前、攻前、防后、攻上、防下、攻下、防上。单体攻击按三路目标优先级选择，替补接替对应位置；详见下节。九人历劫仍为独立九宫格，没有四首发四替补结构。
- 配置目标上限决定折算：普通八人阵容同时在场最多四人，全体技能N=4，倍率`2/5`；九人历劫N=9。替补不计入目标数，敌人不足N不提高单目标伤害。`skill_target_limits`可逐技能配置，但不能超过该模式场上容量。
- 星宿暴击只作用于物理公式，基础额外50%，暴伤与抗暴伤修正其倍率；抗暴率削减暴击概率。星宿免死在护盾／分摊后的真实致死生命损失处判定，成功留1血并消耗次数，未死不触发复活。
- 普通精魄强袭与星宿暴击可相乘【B】，不是同一触发事件。
- 普通修炼最终修正为 `max(0, d×(1+攻修率)×max(0,1-防修率)+攻修固定值-防修固定值)`，然后按追加攻击比例缩放；法术修炼用同样方式仅修正 `3M`，再与`0.25A`合并，后续扣防／强度／法抗正常结算。这一组合次序为【B】。支持原表6.25%等小数。
- 公式组1的弹道占位技能8／9／10按物理公式；公式组6的慈心善佑若被有效概率明确启用，只治疗己方存活目标，按 `floor(3M×K×2/(N+1))` 恢复且不超上限，不造成敌方伤害、不复活。原始0%概率保持不变，不新增获取渠道。

## V2.1：三路、前后排和替补

原客户端`constants.lua`的g_fight_pos与`charPositionUI`的headsPosition对应关系如下。5–8与1–4共享战场坐标，但不是同时出场。

| 阵位编号 | 位置 | 对应替补 |
|---|---|---|
| 1 | 后位／中路后排 | 5 |
| 2 | 前位／中路前排 | 6 |
| 3 | 上位／上路 | 7 |
| 4 | 下位／下路 | 8 |

固定主行动顺序（攻防相对位置，不按屏幕左右重新编号）：`攻1 → 防2 → 攻2 → 防1 → 攻3 → 防4 → 攻4 → 防3`。位置上没有存活神仙时跳过，有替补则由替补使用该位置的时机，伤害数组仍记替补原编号5–8。

单体攻击按以下优先级寻找已在场敌人：

- 中路：敌前位2／前替补6 → 敌后位1／后替补5 → 上路3／7 → 下路4／8。
- 上路：敌上路3／7 → 中路前2／6 → 中路后1／5 → 下路4／8。
- 下路：敌下路4／8 → 中路前2／6 → 中路后1／5 → 上路3／7。

前位尚存时不打前替补，前位和前替补都阵亡后才能越过它们打后位。某边路首发阵亡但其替补仍活，不算该路清空。

替补在整个伤害动作及复活判定完成后登场；首发复活成功不会派出替补。空缺首发的阵容从开场即启用对应替补。未出场替补不攻击、不反击、不受群攻／毒伤／治疗、不替他人分摊、不接受护盾、不触发祝福；登场后恢复正常战斗行为。连击重新按攻击者所在路线选敌，可以攻击刚接位的替补；它是独立追加动作，不是前一次群攻继续扩散。

群攻锁定施法瞬间在场的敌人，可以同时命中中路前后排与两条边路，不受单体前排遮挡。群攻杀死首发后，后登场替补只会成为下一次攻击的候选目标。目标数量仍按技能配置最大值N折算，不能把已阵亡者、未登场替补算进去，也不因实际只剩一人而把群攻提高为单体倍率。例如A=10000、M=3000、D=5000、I=300且无抗性，普通全体法术每名在场敌人伤害为`floor(6500×111/70×2/5)=4122`；四名满编首发各承伤4122，四名未登场替补承伤0。

## 19类精魄

下表中的数值均读原始普通101xx／高级102xx精魄的等级列【A】；未被原文确定的时序与组合方式均为【B】。同系高级替代普通，铭刻归属通过神仙ID匹配，支持历劫临时换阵位。

| 尾号／名称 | 本地规则 |
|---|---|
| 01 威慑 | 攻击时按概率削减目标下一次攻击的基础攻击贡献，反击也消耗一次；同类取最强值。另按第三参数削减来袭强袭的附加部分，不削减基础伤害 |
| 02 破甲 | 命中结算前按概率降低基础防御，本次伤害生效；不叠乘，刷新最强值，死亡清除 |
| 03 反击 | 主行动直接受击且未在本动作死亡时，按概率以普攻比例反击；群攻各受击者独立判断；分摊、毒伤不触发 |
| 04 招架 | 对已触发的反击再判定使其无效；目标携带反击时，提高强袭附加部分，不提高全部普攻伤害 |
| 05 吸血 | 按本动作实际扣除的敌方生命总量回血，含如来实际承担部分；护盾吸收、溢出伤害不计；不能借吸血复活 |
| 06 格挡 | 只对普通／物理攻击独立概率减伤，不影响法术 |
| 07 连击 | 主行动及其反击结算后，攻击者仍活且未在反击中复活，按概率追加一次普攻比例伤害；重新选最前存活敌人 |
| 08 法抗 | 只减主动法术伤害，不减普通攻击和毒伤 |
| 09 破法 | 相对削弱法抗效果；无法抗不凭空增伤。额外施法概率候选值：普通+3、高级+6个百分点，最高100%，可配置 |
| 10 愈合 | 第二回合起，每回合开始按概率回复基础最大生命的一定比例，不超过当前最大生命 |
| 11 强袭 | 物理攻击按概率增加伤害；与格挡独立判断，受威慑和招架的附加部分修正 |
| 12 战意 | 回合2、4、6……累加一次基础攻击提升，每次攻击重新由基础值计算，不指数叠乘 |
| 13 强壮 | 出场增加基础最大生命的一定比例，同时增加等额当前生命；不复活出场已死亡单位 |
| 14 幸运 | 相对提升愈合回复量；面对斩杀追加攻击时按第二参数闪避整次追加，不闪避普通主行动或连击 |
| 15 斩杀 | 本主行动未触发连击时检查原主目标：存活且血量比例严格低于阈值，按概率追加一次普攻；不把斩杀转移到别的目标 |
| 16 中毒 | 攻击命中后按概率施加；下回合开始损失基础最大生命的一定比例，单次最多10000；同类取最强并更新来源，不叠层；持续到解毒或死亡 |
| 17 解毒 | 回合开始先判定解毒，再判定毒伤；成功当回合不再掉毒血 |
| 18 祝福 | 出场每位携带者独立判定，在实际登场时均匀随机选己方已在场存活单位（可选自己）；不同祝福命中同一单位只取最大增益；与强壮都按未加成基础生命计算 |
| 19 复活 | 致死后按概率回复最大生命的一定比例；普通最多1次，高级最多2次，计成功次数；清毒、威慑、破甲与护盾，不重放出场祝福／强壮，不重置星宿免死次数 |

追加链边界：只有主行动可触发反击、连击或斩杀。追加行动仍有物理伤害、强袭、格挡、吸血、破甲、威慑和中毒，但不能继续产生新的反击／连击／斩杀。反击优先于攻击方的追加；连击优先于斩杀。攻击者在反击中死亡后即便复活，也不续接原主行动的追加链。

## 大乘经【B】

1. 技能21处于战斗技能列表才生效，取其等级对应的原表数值。
2. 先扣直接目标已有护盾；剩余伤害若可分摊，从同侧已在场存活的大乘经持有者（排除目标自己）中选分摊率最高者，同率选前阵位。
3. 将剩余伤害的`absorb_rate%`转移给该持有者；其已有护盾可吸收转移伤害，之后按真实生命扣减。转移不再次分摊，不触发反击或授盾。
4. 直接受击的大乘经持有者没有死亡时，以配置概率25%为己方已在场当前生命比例最低者授盾，同血比选前阵位，允许选自己。
5. 护盾容量取被保护者最大生命的`shield_rate%`（1级8%、10级35%），新盾只刷新至较高容量，不相加；持续到耗尽或死亡。这里把shield_rate解释为容量比例，触发概率25%为独立推测配置。
6. 吸血按分摊双方实际生命损失计；分摊之前不按主目标剩余生命截断，以免主目标残血时错误缩小转移伤害。
7. 群攻按阵位逐个结算，但**所有复活统一延后到整个动作扣血完成后**。如来若因替他人分摊而死，本动作不再替后续目标分摊，也不会复活后立即再次承受该群攻；下一动作正常参与。

## 回合与生命事件顺序

首发出场祝福／强壮 → 回合开始在场单位解毒 → 毒伤、免死／复活 → 存活者愈合 → 按固定位置出手表选主行动技能 → 消耗一次威慑并计算战意 → 破甲／威慑触发 → 伤害、护盾、分摊、免死 → 整个动作结束统一复活 → 确认死亡后替补登场（本次群攻不追加目标）→ 吸血 → 有资格的反击 → 连击或斩杀 → 下一主行动。

毒伤造成死亡的单位即使复活，本次维护阶段也不再愈合。死亡在当前动作中取消其反击资格，复活不会恢复该资格。每一位置每回合只有一个主行动时机，首发或替补共享。替补在该位置时机之前登场，可本回合行动；时机已过则等下回合。复活也不额外增加主行动。

## 回放、伤害统计与持久化

- 普通战报沿用1028／1027，九人历劫沿用1141／1140。每条伤害数组只表示直接受击目标的真实生命损失。如来分摊使用同一动作的 `101201 / field=65 / field_plus=-loss` 事件扣除分摊者生命，主数组不再重复包含这部分。原版单体攻击只消费 `des_order` 的伤害槽，不能用其它槽位表达分摊；群攻也沿用相同事件契约，避免重复扣血。
- event 121在战报前发送。回血、毒伤、复活通过`skill_result_list.field=65`及有符号`field_plus`表达。回合开始效果使用独立的`self_use=true`零伤害动作锚定，毒伤致死也有合法cur_action。
- 大乘经沿用原客户端模1000分支200／201／202／203（本地logic_type采用101200–101203）。200／202／203使用 `field=0` 只表达护盾视觉；201使用负的 `field65` 同步分摊者生命。原版201特效最终调用 `showSkillExtAttr`，支持该字段；同动作复活事件仍保留原顺序。已实机验证单体分摊、群攻直接伤害与分摊叠加、分摊致死后复活。
- 公式组6的治疗使用 `101101 / field65` 同步当前生命。旧 `logic_type=0` 会调用原版 `addAllHp` 并同时增加生命上限，现已修正；原CSV为0%的技能不因此被启用。
- 强壮作为自身生命上限预先计入初始阵容，替补尚未在场时不参与任何战斗互动；首发祝福反映在初始阵容，替补真正登场时才判定祝福，使用原生field=9999、hp_add/hp_max_add同步生命变化；强袭／格挡等结果直接反映在真实伤害，未为每次增减伤另补显示文字。
- 服务端`Actions.damage_totals`记录真实伤害并归属来源方，包含毒伤。活动／仙盟累计伤害不再只求和1027，避免漏算121中的毒伤。原存档中旧格式战报仍可退回数组统计。
- 逐鹿游历、攻塔、首领和冥界，以及仙盟嵌套回放都携带对应121事件；仙盟保存fight_events，读档后恢复数字索引。历史回放完整保留已存储记录，超出单包大小的响应通过预载引用展开，不再按28KB截掉历史。
- 最大动作数统一沿用全局配置（默认240，含维护／追加动作，协议数组上限255）。取消仙盟60、逐鹿／冥仙80动作的封包专用限制；旧 `event_budget_bytes`、`land_max_actions`、`abyss_boss_max_actions` 配置键兼容保留，不再据此截断正式战斗。正常胜负只在一方全部神仙（包括替补）阵亡后产生；双方仍存活且达到全局动作上限时返回0，原客户端补丁明确显示“未分胜负”，保留无获胜星级、无胜利奖励的判断。
- `battle_replay.py` 将完整特效或嵌套响应分包到121通道，每包不超过24KiB；每个预载对象最多2MiB，大历史按记录分层预载。客户端按索引合并、恢复完整对象后才交给原回调，包大小不再影响战斗计算。普通动作数组仍走原版1027／1140，未增加战斗动作上限。断包或缺失引用会明确报错，不以半份战报开战。
- 原版事件缓存未命中返回真值空表，导致嵌入战报的 `fight_events` 回退失效；通用补丁在播放前恢复完整事件。历史回放恢复的是深拷贝，界面修改回放方向或结果不会污染预载缓存。
- 空敌阵按胜利、空己阵按失败、双方全空按平局。角色奖励、资源消耗及重复请求幂等仍由各玩法原有事务负责。
