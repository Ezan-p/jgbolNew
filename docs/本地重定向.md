# DNS／寻址层本地重定向

本文描述默认的**仅重定向模式**。现已增加 `--offline` 和 `启动本地离线游戏.command`，提供 TLS、SDK 本地账号、LS／BS 登录、角色与伙伴、好友和地图初始响应；已实测原主界面与地图。使用及边界见 [本地离线服务](本地离线服务.md)。

已实现图片中的第一层：在游戏进程内注入 Bionic 寻址函数，将远端地址解析到设备回环地址；在 `connect()` 入口补充固定 IP、IPv4／IPv6 和端口重定向。本项目的 ARM32 模拟器没有内核 `nat` 表，不能直接使用 iptables DNAT。

```text
游戏主进程／已附加的 SDK 子进程
  getaddrinfo / android_getaddrinfofornet / gethostbyname / gethostbyname2
    → 127.0.0.1（IPv6 调用使用 IPv4-mapped 回环地址）
  TCP connect（包括服务器列表中的固定 IP）
    → 安卓 127.0.0.1:18770
    → adb reverse
    → Mac 127.0.0.1:18770 本地接收端
```

这里设备和 Mac 的 `127.0.0.1` 原本属于两个网络环境，通过 `adb reverse` 连接，不能直接把 Mac 回环地址当作模拟器宿主地址。接收端仅监听 Mac 回环地址，不开放到局域网。

## 使用

双击项目根目录的 **`启动本地重定向.command`**：先启动项目模拟器，再后台启动本地接收端、配置端口映射、冷启动游戏并提前注入主进程，最后执行 DNS 与 IPv4／IPv6 链路自检。会重启游戏，保留 APK、安装数据与存档。

双击 **`停止本地重定向.command`**：卸载钩子、关闭接收端、移除本工具创建的 reverse 映射。后续新连接恢复原始寻址。已经失败的 SDK 初始化不会自动重试，必要时先在 Android 中关闭游戏，再用原来的 `启动游戏.command` 启动。

```sh
# 在项目根目录运行；需要项目虚拟环境中的 Frida 16.2.1
.runtime/venv/bin/python redirect_game.py start --probe
.runtime/venv/bin/python redirect_game.py status
.runtime/venv/bin/python redirect_game.py stop

# 前台运行；Ctrl+C 清理
.runtime/venv/bin/python redirect_game.py run --probe

# 仅附加已启动进程；不覆盖附加前的请求或已建立连接
.runtime/venv/bin/python redirect_game.py run --attach

# 有时限的冷启动实测；结束后自动清理
.runtime/venv/bin/python redirect_game.py run --probe --duration 20
```

默认读取 `game.json`。自定义配置使用全局参数 `--config /路径/game.json`，放在子命令前。`--port` 可更换本地及设备端口；默认 18770。重复启动不会重复注入，已有其他程序占用监听端口或 reverse 映射时拒绝接管。原 `停止游戏.command` 也已接入清理：先停止重定向，再关闭游戏台与设备。

首次使用会启动工作区已有的 Frida 16.2.1 ARM32 server，只在设备回环地址监听。此服务可与现有日志观测工具共用，停止重定向时保留；关闭模拟器也会结束该服务。仅重定向模式没有修改 Mac／Android 系统 hosts、APK、证书信任、渠道登录回调或原启动配置。离线模式额外提供进程内证书信任和本地登录回调。

## 仅重定向模式的接收端边界

| 请求 | 当前行为 |
|---|---|
| `GET /__redirect_health` | 返回本地链路标记，供自检使用 |
| `/update/jgb/p360_a/server_list.txt`、`/update/jgb/p360_na/server_list.txt` | GET／HEAD 返回已有 `analysis/server_lists/server_list.raw.txt` 原始快照 |
| 其他 HTTP 接口 | 返回 501，日志保留 Host、路径、状态；不转发远端 |
| TLS | 记录 ClientHello 的到达并关闭，尚未提供 TLS 握手或证书 |
| 其他 TCP | 记录收到的字节数，不伪造业务应答，空闲 10 秒或收到 1 MiB 后关闭 |

服务器列表保持原字节、原区服 IP、端口和版本；固定 IP 由 `connect()` 层拦截。当前列表版本仍可能触发后续资源更新请求；接收端没有实现更新资源服务。默认模式只验证流量接入；SDK、TLS、3001／3002、1001／1002／1017 由显式启用的 `--offline` 模式处理。

覆盖范围是**已附加的游戏进程中，经过上述解析 API 与 libc `connect()` 的 TCP**。SOCK_DGRAM／UDP、QUIC、直接系统调用、系统下载服务或其他应用代理的连接不在覆盖范围。AF_UNIX 不改写。主进程默认在启动恢复执行前安装钩子；SDK 子进程每约 0.5 秒发现一次，再附加，存在启动早期窗口，不能把它当作全设备断网沙箱。主进程后续自行重启也有重新附加窗口。

## 日志与复核

`status` 显示是否运行、进程 PID、设备、端口及本次会话目录。

- `.runtime/redirect/controller.log`：后台控制器输出；长期使用需自行归档。
- `.runtime/redirect/sessions/<会话>/events.jsonl`：结构化记录，包含原域名／目标 IP／原端口／新端点、HTTP 状态、自检结果。
- 同目录 `console.log`、`session.json`、`summary.json`：可读日志、会话元数据、结束计数。事件日志沿用观测模块的滚动和常见凭据脱敏；不保存 HTTP 请求体、查询参数或原始游戏载荷。

`connect` 返回 `-1` 且 `errno=115` 是此 Android 的非阻塞连接进行中状态，不能仅凭该返回值判定失败。应结合 `local_accept` 与 `http_request`／`tls_received`／`tcp_received` 判断请求是否实际到达。

本次验证记录：[network_redirect_validation.json](../analysis/evidence/network_redirect_validation.json)。实测：不存在的 `.invalid` 域名返回 `127.0.0.1`；IPv4／IPv6 测试地址均收到本地健康标记；调用方 sockaddr 保持原端口；游戏自身服务器列表请求返回 200、59,531 字节，SHA-256 与快照一致。360 SDK 与统计请求也已接收，未实现接口返回 501。时限测试退出后 reverse 映射为空。

```sh
.runtime/venv/bin/python -m unittest discover -s tests -v
node --check network_redirect/hooks.js
node --check network_redirect/probe.js
```
