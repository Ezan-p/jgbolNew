## 1. 本次问题与修复结果

截图中的“包裹 → 法术”为空，首先是存档中的独立法术已被误删，而不是缺少法术配置。

排查时，`ezan` 存档与运行中的客户端均有 73 本神仙自带法术、0 本独立法术。原版 `packageUI` 第 673～678 行会隐藏 `protogenic != 0` 的自带法术，因此该页完全空白。自带法术仍应在阵容中查看、升级，不能卸下或作为材料。

本次完成：

- 补齐闲置法术的威力与大乘经专用属性，避免新获取的法术显示为零或转换后保留旧类型数值。
- 修复全量、分片背包同步导致连续升级窗口持有旧对象的问题。

- 按已有备份与操作日志恢复当前账号可核实的 72 本独立法术，保留原编号、等级及两本法术与原神仙的装备关系。

## 2. 根因：法术的 count 不是数量

原协议 `1035` 使用统一附件结构传输物品和法术，但字段语义不同：

| 字段 | 普通物品 `attach_type=5` | 法术 `attach_type=6` |
|---|---|---|
| `id` | 物品实例或堆叠编号 | 每一本法术的独立编号 |
| `type_id` | 物品模板 | 法术模板 |
| `count` | 数量 | 法术升级失败补偿概率点，正常初始值为 0 |
| `level` | 物品等级 | 法术等级 |
| `protogenic` | 不适用 | 1 为神仙自带，0 为独立法术 |
| `equip_order / equip_pos` | 装备位置 | 神仙阵位／法术槽 |
| `effect_value` | 装备属性等 | 当前法术效果值 |

原 `lineupUI` 第 753～754 行将法术属性 60（`prob_compen`）写入实例 `count`；`skillUpgradeUI` 使用它显示和计算升级补偿。

错误代码曾在扣金卡、灵石、福利兑换材料后执行全背包 `count > 0` 过滤。这会删除未失败过或刚升级成功的所有法术，包括自带法术。后续 `formation.prepare()` 又补齐缺失的自带法术，造成“神仙还有法术，独立法术却消失”的表象；已升级的自带法术也有被重建为 1 级的风险。

现在这三处只移除**本次实际扣除且数量归零的材料实例编号**。福利兑换还明确限制材料为物品类型，避免与法术模板编号混淆。没有通过把法术 `count` 改为 1 来掩盖问题。

## 3. 法术列表与同步

客户端适配位于 [skill_client.lua](../network_redirect/skill_client.lua)，通过既有 `summon.client_source()` 注入，并在重定向停止时恢复原函数。

### 3.1 列表规则

沿用原版列表、图标、星级、品质排序、筛选及升级按钮。背包只展示独立法术；自带法术保留在完整分类中，供阵容读取。

原版读取背包法术页时会对 `g_reorgItemsInfo[6]` 执行 `table.remove`。适配层临时提供分类数组副本，调用原版显示或刷新后恢复共享数组。只复制数组，不复制法术实例，保证养成窗口与背包使用同一个对象。

没有独立法术时显示：

> 尚无可装备的法术。神仙自带法术可在「阵容」中查看和升级。获取途径：旅途掉落、乾坤袋、三星赐福；五星被动法术也可通过碎片合成获得。

### 3.2 分片与连续升级

服务端背包按每包最多 128 条发送，第一包 `first_send=true`，后续为 `false`。

适配层在第一包到达时保存旧法术索引。新快照中的实例只有 `id` 和 `type_id` 都相同才原位更新，保持升级窗口引用；后续分片继续使用该索引。原版队列判定最后一包、完成排序后，才清空临时索引并刷新已打开的背包。

被消耗的法术仍从新列表消失；乾坤逆转产生的新编号不会复用旧类型的图标或 CSV 缓存。此处理也同步 `level`、`count`、`upgrade_level`、`awaken` 和装备位置等协议字段。

## 4. 养成和数值

### 4.1 普通升级

请求：`1071`，`data={des_skill_id=目标编号,src_skill_list={材料编号...}}`。

沿用现有结算与原表：

```text
材料价值 = 各材料在 skill_enhance_worth.csv 中对应品质、等级的价值之和
升级成本 = skill_enhance_cost.csv 中目标当前等级、品质的成本
成功率 = min(100, floor(材料价值 × 100 / 升级成本) + count)
```

一次成功升 1 级、清零失败补偿；失败不降级，增加配置的补偿概率点。成功和失败都消耗所选材料。当前 `server_config/formation_rules.json` 中 `skill_failure_compensation=1`，为离线推测规则【B】，不宣称是原服算法。

普通可获取法术共 54 种，等级为 1～10。拒绝重复、非数字、非正整数材料编号、目标自身、已装备、自带、锁定、参悟或觉醒材料；满级目标不扣材料。事务在角色副本上结算，编码成功后保存；同序号同请求重放原响应。

### 4.2 威力与大乘经

`formation.refresh_skill()` 为已知法术统一刷新：

```text
effect_value = floor(对应基础值 + upgrade_plus × (level - 1))
```

装备、闲置、自带法术均会更新。`equipment_crafting.grant()` 在产出独立法术时立即填充显示字段，因此乾坤袋、宝箱和合成共用的奖励入口也正确。

大乘经（21）的 `absorb_rate / shield_rate` 使用原 `rulai_skill_base.csv`：1 级为 3 / 8，10 级为 12 / 35。普通法术清零这两个专用字段，避免类型转换后残留。

### 4.3 装备、参悟、觉醒和战斗

- 装备沿用 `1037`：独立法术进入第 2、3 槽；不可替换自带槽，不允许同一神仙重复装备同类型法术。卸下后仍保留实例。
- 参悟沿用 `1076`：8 种指定五星被动法术达到 10 级，按原配方消耗两本材料。原 CSV 生命 10% 与原界面 12% 的冲突，仍按已有离线配置处理，见 [法术参悟规则与调试](法术参悟规则与调试.md)。
- 乾坤逆转沿用 `1212`：使用逆转符，按规则返回参悟材料，并产生新实例编号；本次补齐转换后闲置法术的效果刷新。
- 自带法术觉醒沿用原转生模块，见 [转生模块规则与调试](转生模块规则与调试.md)。
- 装备后的被动属性与主动战斗技能仍使用统一阵容、战斗结算；本次没有更改掉落概率和战斗伤害公式。
