## 2. 第五精魄槽与四槽锁定

### 2.1 原版规则 A

1. 铭刻入口需要角色38级；旧普通铭刻最多4个槽。
2. 地魂达到50级获得属性389“精魄格子”+1，客户端对应字段为`fate_rebullding_jp_slots`。本地沿用已有逆天改命激活前置；第五槽不是花1000元宝购买的槽位。
3. 只对紫色精魄提供铭刻锁定按钮，原版质量值为5。紫色同系精魄会替换已有金色前身。
4. 铭刻请求为`1311`，携带`serial_num`、`ext_skill_id`、`des_cortege_id`、`lock_list`。锁定列表是**槽位编号**，不是精魄类型或背包实例ID。
5. 费用按本次选中的锁定数量整体查表，不是逐槽费用累加：

| 锁定数量 | 元宝费用 |
|---:|---:|
| 0 | 0 |
| 1 | 100 |
| 2 | 300 |
| 3 | 700 |
| 4 | 1000 |

四槽1000元宝由原表直接确认；“保护四槽，让第五个可用槽承接铭刻”是该新增档位与第五槽共同支持的用途。剩余多个槽如何随机选择、异常状态如何拒绝，仍按下方 B 明确说明。

### 2.2 服务端补全 B

有效槽位为普通已开槽`1..min(4,equiped_ext_skill_limit)`，在逆天改命已激活且地魂≥50时另外加入编号5。普通4槽上限保持不变，不把普通开槽字段无条件改成5。

- 普通四槽最多锁3个；五个槽全部开放时最多锁4个，绝不允许五槽全锁。
- 第五槽也可被保护。例如`{1,2,3,5}`只允许替换第4槽，不能把“第五槽”硬编码为每次替换目标。
- 所有锁定槽必须存在、处于已解锁集合、装有紫色精魄，编号必须是互不重复的整数。
- 非法/重复占位、未解锁槽残留精魄、空堆叠等异常存档拒绝铭刻，避免错误覆盖。不会静默删除旧存档精魄。
- 源精魄必须存在、未装备、未锁定且数量充足。目标已有相同类型时拒绝重复铭刻。
- 同系紫色替换金色走固定槽位；否则优先填最小编号空槽；都已占用时，在可用且未保护、未物品锁定的槽中等概率选择，替换后的旧精魄销毁。等概率和销毁策略是沿用的本地 B。
- 普通槽不足4个时保留原有离线开槽策略：基础10%加幸运值，失败增加10幸运值，成功归零。此概率没有原服证据，本次没有把它升级为 A。原有“锁住现有三槽以开第四槽”路径保留。
- 全部校验成功后扣一次锁定费、扣一个源精魄并提交；源背包是堆叠时拆出独立铭刻实例，剩余数量留在背包。
- 同一会话同序号同请求返回既有响应，不再次扣1000元宝；失败通过原有事件55返回原因，数据库角色状态不变。成功仍返回事件148、147及现有物品/角色同步消息。
- 物品的`is_lock`是持久背包保护，`lock_list`是本次铭刻保护，二者均检查，但不会把本次锁定转成永久锁定状态。

### 2.3 原生客户端遗漏与补全 B

【A：观察到的客户端事实】v107实际资源索引为1263，其三张相关CSV已与原服末版逐行一致；但`jpmkUI.lua`仍在源行53令共享局部量`MAX_JP=4`。锁定弹窗源行891按此值遍历，源行864按`MAX_JP-1`限制锁数，费用和确认回调也引用同一变量。因此仅改服务端，用户仍无法通过该窗口完成四锁。

【B：修复方式】新增`essence_hotupdate_client.lua`，在原生`showJPLockLayer`调用前读取当前神仙的`fate_rebullding_jp_slots`：有额外槽时把原生函数共享上值设为5，否则恢复4。保留原布局、紫色品质筛选、价格读取、提示、发送与回调；嵌套按钮回调继续共享同一值，确保显示五槽后确实能锁四槽并提交正确费用。

补丁可重复安装且不会叠包，可恢复原函数和上值。该修复依赖项目现有Lua调试上值API与1263原生铭刻函数；没有宣称兼容所有历史客户端。

【A】威慑的作用文字由“基础攻击力”变为“攻击力”；强壮由“生命上限提升基础生命值的%s”变为“生命上限提升%s”。原表没有继续给出服务端属性组成或具体乘区。

### 3.1 战斗口径 B

**威慑。** 先算本次行动的战意、逆天回合攻击等加成，再对本次攻击力乘`max(0,1-减攻比例/100)`。一次威慑在下一次攻击行动消费；本地的反击也算攻击行动。多次未消费威慑取最强值，不累加。例：100攻击，经1.5和1.25两项加成后为187.5，20%威慑后为150；旧计算减去基础100的20%会得到167.5，现已纠正。

**破法。** 使用原表新百分比，沿用相对削弱法抗效果：有效法抗=`法抗比例×(1-破法比例)`，两项比例各自限制在0～1。例：法抗40%、高级破法5级70%，最终法抗减免12%。文字中的主动技能概率“小量提升/提升”没有数值，仍采用本地普通+3、高级+6个百分点，不伪装为原表值。

**强壮。** 入场时以完整战斗快照的当前生命上限为基数，增加`floor(生命上限×比例/100)`，同时增加相同当前生命；不改写永久属性或回存强壮加成。灵阵108按百分点加到已佩戴强壮的比例上，因此高级强壮5级15%+对应满级灵阵2%=17%。`base_hp`保留入场前快照，用于原文字仍明确“基础生命”的愈合和中毒；该基数包含哪些永久养成来源及祝福与强壮的组合顺序仍属于既有 B，不能从改名断言完全复原原服。

**咒罚。** A明确20万、3回合、可叠加；具体补全如下：

1. 攻击命中后目标仍存活时独立判定中毒；各次攻击可增加一层，反击、连击等沿用既有攻击触发链。每层保留施毒方、逻辑类型和施加时的伤害比例。
2. 从施加后的下一次回合开始结算，每层分别结算3次，不刷新其他层的剩余次数，不设置额外层数上限；整场仍受既有30回合与战报限制约束。
3. 每层伤害=`min(200000,floor(base_hp×该层比例/100))`，再按实际剩余生命扣除。**20万按每层一次伤害限制，层总和可超过20万，这是 B 的具体解释**，不能声称原服一定采用此分配方式。
4. 同一目标按施加先后逐层结算并各自记战报；记录实际损失和施毒阵营，避免高伤害导致统计超过实际扣血。
5. 清心在回合开始判定一次，成功清除全部中毒层；所有层到期后删除中毒状态，逆天“对中毒目标增伤”随之不再生效。
6. 某层致死后终止对该目标的本次中毒结算；复活清除旧中毒，余下层不继续伤害复活后的生命，本回合也不额外再触发一次愈合。
7. 战斗内兼容原有单层中毒字典，以便旧测试/注入快照正常运行；正式新施毒统一生成带剩余次数的层列表。中毒状态不是持久玩家存档，无需迁移数据库。

例：基础生命10000，第一回合中10%毒，第二回合开始扣1000；第二回合再中5%毒，第三、四回合各扣1500，第一层到期；第五回合扣500，第二层到期。累计4500。
