# 仙盟模块规则与调试

> 当前实现（2026-10-26）见 [仙盟模块 NPC 离线实现与调试说明](仙盟模块NPC离线实现与调试说明.md)。本文保留最初规则审计；下方【B】数值表及历史测试结果不代表当前实现。94既支持客户端查询又支持更新；管理按钮采用批量role_list，原生禅让走11/new_rank=1，均已按新证据接通。

适用客户端：金箍棒 OL 3.87。服务端实现：本仓库 Python/SQLite 本地后端。日期：2026-10-24。

## 证据边界

- **【A】原版客户端规则**：来自 APK 内 LuaJIT 字节码、原版 CSV、协议表及未修改客户端的回调验证。只能证明客户端契约和随包数值，不能据此宣称恢复了官方服务端。
- **【B】推测规则**：缺失服务端的配置、时间表、对手、权限分配、结算和持久化策略。本次以可运行的单账号离线环境补齐；不是官方线上数值，也不提供真实多人或跨服务器联网。
- 原版资源未修改。可复现提取脚本：`analysis/tools/audit_guild_rules.py`；资源路径、SHA-256：`analysis/evidence/guild/audit.json`；枚举：同目录 `enums.json`；完整字节码清单保存在同目录。
- 【B】集中配置：`server_config/guild_rules.json`。代码中固定的离线逻辑在下文列出；宴席及盟战排行奖励直接读取原 CSV，不把可证实数值当作猜测。

### 【A】管理与查询

## 【B】本地服务端补全规则

以下不是官方数值。所有活动使用当前角色 SQLite 存档，重启保留；每日按UTC+8跨日。真实玩家间的并发、跨服路由、正式淘汰赛和赛季归档不在本地架构内，以明确的离线对手和本地排行代替。

### 【B】实现与完整性约束

- 退出/重新加入保留账号当日次数和领奖标记，防止反复换盟刷新奖励；离开时清除队伍关系并取消未领取取经行程。
- 服务端校验成员身份、管理权限、目标、金币/银两/贡献、限购、次数、倒计时及领奖状态；失败不保存扣费中的临时对象。
- 同一会话相同序号与相同请求返回缓存，旧序号或同号不同参数拒绝；缓存最多256条。重连后缓存重置，持久化的领奖/次数状态继续生效。非领奖类操作跨重连重新发送属于新交易，不承诺跨进程请求幂等。
- 背包差异、玩家属性与操作响应由同一次事务完成后保存；战报先成功编码，再保存扣费和收益，避免编码失败却扣款。
- 原版合服补偿77、过期服务器广播和未触发的历史事件没有伪造成功响应；本地没有对应合服活动。不存在的申请/成员/战斗目标明确拒绝。
- 战斗复用仓库已有本地战斗引擎；官方随机种子、隐藏AI和真实玩家战力不能从客户端恢复，属于【B】。
