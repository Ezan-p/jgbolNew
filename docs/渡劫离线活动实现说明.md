# 渡劫离线活动实现说明

实现日期：2026-10-25。入口为「活动 → 渡劫」，8级开放。这里指原客户端 `crossDoomUI` 的渡劫，协议1029／1041／1072、战斗类型3；不是 `undergo_ordeal` 对应的历练。

本次把固定弱敌替换为 `analysis/npc_design/v1/catalog.json` 的完整NPC阵容，补齐查看、挑战、单人刷新、整盘刷新、扫荡、法术奖励、特殊骰面、离线反击、忽略消息、跨日和旧存档迁移。全部状态保存在当前账号本地存档，不读取真实玩家，也不等待在线玩家。

## 1. 原版依据与推测边界

**A：原版可核对内容。** 直接读取3.87原始Lua字节码、协议、CSV和说明图片，不依赖网络攻略。证据由 [audit_rape_rules.py](../analysis/tools/audit_rape_rules.py) 重建，保存于 [official_audit.json](../analysis/evidence/rape/official_audit.json)。

- [原版玩法说明](../analysis/evidence/rape/info1.png)说明获胜可领悟法术；[额外奖励说明](../analysis/evidence/rape/info2.png)明确单列全部击败后再获额外法术奖励。
- `crossDoomUI`有三列、骰面 `form_type`、整列法术预览、击败标记及顺子／豹子动画。顺子要求三个骰面按升序或降序连续；豹子要求三者相同。
- 原客户端同时遍历 `form_list[1]`、`form_list[2]`，并按 `rand` 降序排列头像。服务端必须发送空的第一类列表，并提供稳定排序，否则可能出现Lua错误或扫荡标记错位。
- 8级开放；扫荡需25级或VIP5，VIP5以下每名实际扫荡对手收费1元宝；单守卫刷新界面提示5元宝。
- 原生反击消息使用事件78；反击战斗类型12，以消息键为 `des_id`、法术类型为 `des_value`，目标类型1；忽略消息请求1060，回调事件84。
- 法术候选来自 `skill_name.csv.product_desc` 中明确写有“渡劫”的条目，且必须存在于生产法术配置。

**B：原服缺失后的本地规则。** 三列各三名守卫、55%／70%／85%战力梯度、法术品质权重、骰面等概率、顺子额外奖励翻倍、豹子自动通关、单场具体数量和离线反击触发策略，均是可调整的推测实现，不声称复刻原服务器概率。

## 2. 玩家流程与结算

| 操作 | 实际行为 |
|---|---|
| 进入／查询 | 生成或读取当前三列九守卫；反复查询不会重新随机或重复发奖 |
| 查看阵容 | 查看当前目标的神仙、装备、法术、助威及实际四维；对手与战斗使用同一NPC快照 |
| 单场挑战 | 每场消耗1精力，使用八位生产战斗引擎，含首发、替补、法术、精魄和命星；客户端不能上传胜负 |
| 单场胜利 | 守卫标为已击败，获得本列法术1本及现有配置的1000银币 |
| 清空一列 | 在最后一场胜利上追加本列预览数量的法术；普通额外1本，顺子额外2本；只发一次 |
| 清空整盘 | 全部列完成，保留完成状态，可继续整盘刷新开始新盘 |
| 单人刷新 | 消耗5元宝，换成另一份NPC配置，保持原显示位置；已击败目标不能刷新 |
| 整盘免费刷新 | 使用VIP对应免费额度；普通账号当前3次，沿用VIP表；丢弃当前盘进度并重新匹配 |
| 整盘付费刷新 | 消耗现有配置的20元宝；刷新次数计入现有统一使用次数，沿用原后端额度口径 |
| 一键扫荡 | 按显示位置逐场运行同一战斗逻辑，最多处理当前精力能支持的未击败目标；失败也消耗本次精力和扫荡费用 |
| 精力／元宝不足 | 返回明确错误，整笔事务不写入，已扣资源和已生成奖励不残留 |

普通九场全胜，共获得9本单场法术＋3本整列额外法术；顺子盘为9＋6本。法术均为1级独立物品。豹子按本地策略直接结算完整通关的法术（普通合计12本），不进行战斗、不扣精力、不发战斗银币。骰面查询与重连不会再次结算。

法术品质1～5的**单条候选权重**分别为50、35、20、5、1；这不是各品质的最终概率，概率还受该品质候选数量影响。各列独立抽取，可重复。同列单场和整列奖励使用同一法术类型，便于玩家按预览决定是否刷新。

失败保持守卫未击败，可培养、换阵后再战或刷新。战斗引擎未决结果0按未胜处理，不伪造胜利；返回实际战报。

## 3. NPC分配

1. 通过现有NPC加载器读取设计库，并按当前统一战力算法重算；排除设计库已标注 `replay_limit_observed` 的样本。
2. 只选择角色等级不高于玩家的NPC。使用玩家当前1～8号出战神仙战力总和，不将背包候补直接加入。
3. 每列三个位置分别以玩家战力的55%、70%、85%为目标。以绝对战力距离排序，其次比较等级距离和稳定NPC标识。
4. 在最近三名中，仅保留距离不超过“最佳距离＋目标战力10%”的候选，再随机选择。低战力或稀疏样本区使用最近真实样本；不强行把NPC四维乘比例。
5. 不为凑齐九个不同名字强行升级难度。同一NPC模板可以在不同守卫位置出现，各有独立对象ID和胜利状态。单守卫付费刷新则明确排除刚才的NPC。
6. 生成后的NPC保持固定，升级或换阵不会让正在打的守卫同步变强；整盘／单人刷新才按当前状态重新匹配。

生产战斗读取NPC完整阵容与装备效果，保留精魄、命星、飞升、转生、替补和助威结算属性。当前战力是匹配指标，并不保证固定胜率；不同流派仍有克制和随机法术效果。

对象编号由账号内持久化的 `rape_sequence` 自950001起递增，整盘刷新、单人刷新和反击消息均不复用已发编号。服务端仅接受当前盘或当前有效反击记录中的目标，不能提交任意NPC／真实玩家编号。名字显式带“离线”，且控制在战报固定字符串长度内。

## 4. 离线反击

为了保留原版消息入口，每个本地日最多在首次挑战未胜后生成一条NPC反击机会，保存同一NPC模板及对应法术。此为离线玩法推测；不会扣除玩家已获得或已装备的法术。

- 消息有效期24小时，查询渡劫时同步列表；跨日不会重置有效期或重复生成旧消息。
- 反击每次消耗1精力。胜利发1本消息指定的法术和战斗银币，并标为完成；失败可再次尝试。
- 成功消息保留完成标记，避免原客户端旧消息再次显示为可领取。再次提交完成消息会拒绝。
- 可查看对应NPC阵容，也可通过原生“忽略”按钮删除消息；伪造消息ID、法术类型、过期目标均不结算。
- 刷新主盘不删除有效反击记录，反击胜利也不会再次触发主盘奖励。

请求／响应：1029→事件40；1041→事件40增量；1039→事件11；1026类型3→1028阵容＋1027战报＋事件41／44；1072→事件114；1026类型12→战报＋事件77／44；1060→事件84；反击列表为事件78。技能、银币、精力、元宝和库存由既有后端增量同步。

所有操作沿用Backend的离线副本、编码后提交及请求序号防重机制。失败不会落盘，重放相同请求使用缓存结果；请求缓存和序号水位仅在当前服务会话有效；重启后依靠持久化守卫／领奖标记防止重复发奖，不宣称跨重启的网络请求缓存。

每日按现有UTC+8配置刷新主盘与免费次数。旧存档的未完成盘原地补NPC、骰面、双类型列表和排序，保留原对象ID、已击败状态及原技能，不补发历史奖励。已清空列迁移为已领奖。NPC库存不会复制到玩家存档。
