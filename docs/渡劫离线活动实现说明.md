# 渡劫离线活动实现说明

更新日期：2026-10-26；当前规则版本 `offline-rape-2`。入口「活动 → 渡劫」，8级开放，对应 `crossDoomUI`，不是 `undergo_ordeal` 历练。本版按用户最新规则修正守卫人数、整列奖励、剩余刷新次数和“继续”换盘流程，替代2026-10-25文档中的固定九守卫、单场奖励及豹子自动通关规则。

## 1. 当前玩法

| 项目 | 实现 |
|---|---|
| 三列守卫 | 每列骰面为1～6，该列就生成1～6名守卫；例如骰面4／6／2，对应4／6／2名守卫；全盘共3～18名 |
| 挑战消耗 | 每场1精力，真实模拟战斗；失败保留目标，可调整阵容后重试 |
| 单守卫奖励 | 无法术、无银币；只记录击败状态。骰面为1时，击败唯一守卫即完成该列 |
| 整列奖励 | 全部守卫击败后，只发该列预览的法术类型和数量，每列一次 |
| 顺子 | 骰面升序或降序连续时，每列预览2本；普通盘每列1本，结算始终与预览一致 |
| 豹子 | 保留原客户端骰面动画，但不自动击败守卫、不自动发奖，仍须逐列完成 |
| 单守卫刷新 | 5元宝，替换为另一NPC，保留显示位置；已击败守卫不能刷新，不扣整盘免费次数 |
| 整盘免费刷新 | 每次扣1次免费额度；响应立即返回扣除后的剩余次数，普通账号当前额度3次，VIP沿用现有表 |
| 整盘付费刷新 | 20元宝；不再增加免费使用计数，剩余免费次数不会变负数 |
| 一键渡劫 | 25级或VIP5开放；按当前位置逐场模拟，最多处理现有精力支持的目标；VIP5以下每场另扣1元宝 |
| 通关后继续 | 点击“继续”立即请求新盘；优先消耗1次免费刷新，额度不足则扣20元宝；资源不足保留已完成盘并提示 |

普通盘完成三列共发3本法术，顺子盘共发6本，与守卫总数无关。法术均为1级独立物品。一键渡劫完全复用单场战斗与整列结算，不直接判胜；失败也消耗该场精力及扫荡费用。

普通查询、退出后重进或重连只读取当前盘，不会暗中刷新或扣费。整盘仍有守卫未击败时，服务端拒绝“继续”；玩家可以使用正常刷新按钮放弃本盘重新开始。

## 2. 本次两个界面问题的原因与修复

### 免费刷新次数

原客户端 `setFreeFreshTink` 直接显示 `card_data.free_count`，`freshCard` 也以该字段判断免费或付费；它不计算“总额度减已用次数”。旧服务端一直把总额度发送为 `free_count`，导致服务器已扣次数而左侧仍显示初始值。

现改为：

```text
free_count = max(0, rape_flush_limit - rape_refreshes)
```

只有成功免费刷新增加 `rape_refreshes`，事件40直接携带新剩余次数。客户端原回调收到响应后重绘次数，无需退出活动。另设 `rape_total_refreshes` 统计免费、付费和“继续”的成功换盘，供日常活跃度使用；两个计数都按UTC+8跨日清零，失败及普通查询不累计。

### 一键渡劫后的“继续”

原版 `pressGoOnCard → pressInfoBegin` 发送1029的 `flag=1`，只查询服务端仍保存的已完成盘。服务端并不知道这是点击“继续”，因此重复显示已击败的三列。

新增可恢复的 [rape_client.lua](../network_redirect/rape_client.lua) 补丁，让“继续”发送1029的本地扩展 `flag=4`。服务端先核对整盘已结算，再选择免费或付费刷新，返回原生事件40的 `update_type=2/3`。补丁同时清除上一盘 `is_all_pass`，避免一键渡劫完成状态残留。普通查询仍为 `flag=1`。

连续双击时，首个请求生成新盘，第二个请求因新盘未完成而被拒绝，不会连续扣费；相同请求序号的重放沿用Backend缓存。客户端不预先扣除本地次数，最终显示以服务器成功响应为准。

补丁通过 `summon.client_source` 随现有客户端兼容代码加载，并在卸载时还原原函数；需要重新启动本地重定向／游戏以加载新版补丁。

## 3. 离线NPC匹配

读取 [NPC设计库](../analysis/npc_design/v1/catalog.json)，使用现有加载器按生产战力算法重算，并排除 `replay_limit_observed` 样本。匹配限制NPC角色等级不超过玩家；玩家战力取1～8号出战神仙之和，不计背包候补。

每列位置循环采用55%／70%／85%的目标战力，以绝对战力距离、等级距离和稳定标识排序，从最近三名中选择误差接近的候选。没有对最终四维强行乘倍率。4～6号守卫重复这三个匹配档位；同一模板可出现在不同位置，但对象ID、胜利状态独立。

战斗使用真实完整阵容，包含首发、替补、装备、法术、精魄、命星、飞升、转生和助威结算属性。阵容查看与战斗引用同一NPC。生成后的对手保持固定，培养或升级不会让旧对手同步变强；刷新时才重新匹配。

名字带“离线”，符合战报字符串长度。对象序号从950001递增，不跨日重置；刷新后的旧ID不能继续挑战。战力只是匹配指标，不保证固定胜率；未决结果0不发奖、不标为胜利。

## 4. 离线反击与持久化

反击为独立玩法，保留上一版策略：每天首次未胜最多生成一次本地NPC反击机会，有效期24小时，不抢走玩家库存。反击胜利发消息指定法术1本和原配置银币；此处不属于三列守卫结算。消息可查看阵容或忽略；伪造、过期、已完成消息不能重复领奖。

主盘、守卫胜利状态、整列已领奖、序号、刷新次数和反击记录均保存到当前账号。操作在离线副本完成，编码成功后提交；资源不足或非法请求不残留扣费和奖励。请求缓存仅在当前服务会话有效，重启后以持久化击败／已领奖状态防止重复发奖。

旧版本当前盘迁移时保留原有守卫和胜利状态，把骰面校正为该列已有守卫数，并标记 `version=2`，避免新增守卫、删除进度或追缴历史奖励。旧三守卫盘显示为骰面3；下一次刷新按随机骰面生成1～6守卫。已领取的列不会补发，新版也不补发历史单守卫奖励。
