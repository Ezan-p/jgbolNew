# 两周年／元始祈愿离线活动实现说明（3.87）

更新：2026-10-28（Asia/Shanghai）。活动入口 **46**，原版模块 `twoYearsCelebrateUI`，请求 **1334**，回调事件 **179**。

2026-10-28按需求改为常驻，每14天刷新，显示刷新倒计时，换期清空剩余供品及充值等活动进度。2026-10-27补齐未满进度祈愿的随机奖励，独立介绍、奖励明细、概率和边界见[元始祈福活动实现说明](元始祈福活动实现说明.md)。原版领取后奖励为元始天尊魂魄，按原版保留。

本实现涵盖两周年活动的祈愿、元始领取、领取后魂魄产出、玉清阁、五个充值礼包、元始天尊福袋、跨日结算及存档恢复。沿用原版美术和窗口，补齐人物按钮绑定与缓存刷新。这里的“完整”指这项活动的可玩闭环，不表示整个项目所有未接入玩法已经恢复。

**【A】**来自3.87原包的规则、文案、协议和界面结构；**【B】**为缺少原服务端资料时采用的推测及离线适配。未取得原服运营配置、历史活动排期或结算日志，因此不能把下列【B】数值称为原版精确数值。

## 1. 如何进入和游玩

启动／重启本地离线游戏，登录后在**奇闻列表选择「两周年」**进入。已有账号不需要清档。

1. 点击原版祈愿按钮；优先消耗免费次数，免费次数不足时消耗祈愿供品1807。未满进度时增加进度并随机发放一份奖励，包含达到100%的这一次。
2. 进度达到100%后点击人物领取元始天尊。满进度未领取时，祈愿按钮也会执行领取；领取本身免费。
3. 领取后继续祈愿，获得元始天尊魂魄。
4. 玉清阁第一格出售漏祈愿补购的供品，第二格出售元始福袋。福袋在背包开启，活动关闭后仍能使用。
5. 原版充值按钮接入项目已有的**本地模拟充值**，不发生真实扣款。达到条件后逐日激活五个礼包，点击各礼包查看内容和领取。

游戏进程和重定向服务若在修改前已经启动，需要重新启动本地离线游戏，才能加载新增的1334路由及Lua适配。配置修改后也建议重启，保证登录下发和服务端校验一致。

## 2. 原版规则【A】

| 内容 | 原包证据与实现 |
|---|---|
| 活动身份 | `activityUI.activityID.twoyears=46`；与福利周年邮件、天缘召唤、洞府祈愿不同 |
| 请求 | `1334 msg_yuanshi_activity`，`serial_num=I, flag=B, index=B` |
| 操作枚举 | 0进入、1领充值礼包、2祈愿／领人物、3进玉清阁、4购买 |
| 回调 | 2998封装事件179；原 `event_mgr` 动态调用 `d_twoYearsCelebrateUI.onGetResult` |
| 开放条件 | 客户端读取 `g_new_config[24].yuanshi_info.begin_time/end_time`；没有两周年专属等级门槛 |
| 免费祈愿 | `free_times`，无免费次数时检查物品1807；没有足够供品时阻止发送 |
| 祈愿进度 | `cur_progress`按百分比显示；进度满后可获得主角等级×2的元始天尊；继续祈愿产出其魂魄 |
| 供品 | 1807“祈愿供品”，增加一次额外祈愿；未祈愿的日期增加一份玉清阁出售供品 |
| 福袋 | 1808“元始天尊福袋”，开启获得等级为主角等级×2的元始天尊 |
| 玉清阁 | 两个商品位置；`object_type/attach_type/need_gold/buy_times`；购买回调奖励字段为 `shop_list`；`wish_times`显示已祈愿天数 |
| 五个礼包 | `gift_config[1..5].prize_list`展示内容；`gift_list[i]`不存在表示未激活，0表示无可领份数，正数表示可领取份数 |
| 激活顺序 | 上一礼包激活后，次日才能激活下一礼包；五档说明依次为任意充值、30元、30元、50元、50元 |
| 复领资格 | 当日任意充值后可以领取所有已经激活的礼包；具体计数累积方式仍缺服务端证据 |
| 人物请求 | 原 `getChar()` 和 `pray()` 都发送 `flag=2,index=0`，不存在独立人物领奖请求 |

原包细节：`getChar`只有函数定义，没有绑定到人物菜单；现代奇闻列表 `funUI.getFunList` 第490—491行已包含两周年入口，下发开放时间即可自动显示；不需要另造菜单。原回调购买后只刷新显示，却仍从进入商店时的旧缓存读取限购。上述事实由原字节码确认，修复方式归【B】，不能描述成原包本来就能完整运作。

## 3. 缺失规则的推测与数值【B】

独立配置：[server_config/yuanshi_rules.json](../server_config/yuanshi_rules.json)，强制 `mode=inferred`。

| 项目 | 当前采用的推测 |
|---|---|
| 活动期 | 按需求【U】常驻，每14天刷新；以1970-01-05 00:00 UTC+8为锚点；显示距下次刷新倒计时，不显示活动结束倒计时 |
| 当前周期示例 | 2026-10-26 00:00 至 2026-11-09 00:00（左闭右开）；下一期至11月23日；全账号按同一锚点刷新 |
| 参与起算 | 首次进入活动或活动期内首次模拟充值时登记；不把登记之前的日期算漏签 |
| 日界线 | UTC+8零点；每天1次免费祈愿，未用次数不累积 |
| 进度 | 每次祈愿加10个百分点，最高100%；完整使用10个免费日即可满进度，但晚加入一期时不保证剩余天数足够 |
| 未满进度奖励 | 每次随机一份：银两100000（40%）、包子×1（25%）、仙丹×1（20%）、金丝乾坤袋×1（10%）、VIP乾坤袋×1（5%）；五类来自本次需求，数量和概率为补充设定，不是官方概率 |
| 满进度领取 | 下一次 `flag=2`免费发整只元始，不扣供品或次数；先达到100%，再领取；之后同操作恢复祈愿含义 |
| 领取后奖励 | 每次祈愿1个元始魂魄；仍优先使用免费次数 |
| 重复神仙 | 已有元始时，满进度人物奖励转换为40魂魄【B】；福袋1808每袋按开启当时主角等级×2发放魂魄【U，2026-10-30修复】，批量开启逐袋计算 |
| 神仙等级 | 实际发放时按主角等级×2生成，经验设为0，统一重算属性并生成天生法术；极端存档以原五星经验表最高等级为上限 |
| 漏祈愿补购 | 已登记且整日没有任何祈愿的日期，每日累计1份供品库存；有一次祈愿就不算漏日；首次当天库存0；库存当期保留，买一份减一份 |
| 供品价格 | 每份100元宝；不直接赠送补签次数 |
| 第二格商品 | 选择1808元始福袋，每份1980元宝，每日限购1份。原包仅证明有第二格和福袋道具，**不能证明第二格原商品就是福袋或原价1980** |
| 充值计量 | 沿用本项目10元宝对应1模拟元，以充值基础元宝累计，不计赠送元宝；任意充值要求实际到账金额>0 |
| 新礼包激活 | 当天累计达到下一档门槛时激活，每天最多新增1档；超额充值不跨日预激活，不追补离线未充值日期 |
| 旧礼包份数 | 当天第一次充值，为所有此前已激活礼包各加1份；当天重复充值不重复增加旧礼包份数；新激活礼包当天另有1份 |
| 领取与保留 | 未领份数在当期累积；一次点击领取所选礼包全部积存份数。未充值日不新增资格，也不清空此前已经取得的资格 |
| 换期 | 清零进度、祈愿次数／天数、人物领取及当日标志、充值金额、礼包激活／未领份数及日期、补购库存和福袋已购计数；旧免费次数清空后恢复新一期当日1次。清空背包（含锁定栈）和未领取邮件中的1807供品；保留1808福袋、已有神仙、魂魄及其他奖励。账号总充值／VIP不受影响 |

## 4. 客户端及服务端接入

- [activity_yuanshi.py](../network_redirect/activity_yuanshi.py)：状态、时间、祈愿、商店、礼包、福袋、配置校验。
- [activity.py](../network_redirect/activity.py)：1334路由、1808背包路由、奇闻状态时间更新、登录后跨日准备。
- [backend.py](../network_redirect/backend.py)：登录公共配置、模拟充值到账联动、即时更新礼包状态；沿用现有神仙／背包／魂魄增量与完整快照。
- [yuanshi_client.lua](../network_redirect/yuanshi_client.lua)：保留原界面，启用原奇闻入口、补人物领奖按钮和满进度祈愿按钮分流；同步购买缓存和充值状态。
- [summon.py](../network_redirect/summon.py)、[summon_client.js](../network_redirect/summon_client.js)：现有离线适配加载与撤销机制，无需修改或重打APK。

神仙、物品和货币均由服务端结算，不接受客户端指定进度、价格、奖励或充值金额。新活动状态位于账号存档 `activity.yuanshi`，各账号独立。`permanent`标记常驻，`refresh_time`表示下次重置；`begin_time/end_time`保留为周期起止兼容字段。归零会重新查询，刷新前拦截旧领奖／购买操作，收到新一期后关闭旧商店和礼包详情并清理缓存。

非法操作、道具锁定、库存不足、元宝不足、时间回退均拒绝；福袋验证所选物品ID并只扣该物品栈。活动处理使用脱离数据库的角色副本，响应编码成功后才保存。连接内相同序列号重发复用响应、变更内容或旧序列号被拒绝；重启保留进度、限购、充值订单和礼包资格，不会靠重新登录刷新免费次数。序列号缓存本身沿用项目现有的连接级策略。

旧28天存档的同起点周期保留进度并缩短到14天；已跨入新的14天周期则立即重置。离线跨多期只进入当前一期，不追补免费次数或旧期库存；旧账号无需清档。详细规则见[元始祈福活动实现说明](元始祈福活动实现说明.md)。
