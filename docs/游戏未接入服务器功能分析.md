# 游戏未接入服务器功能分析（3.87）

检查日期：2026-10-25（UTC+8）。对象：当前工作区原版客户端静态提取资料、`network_redirect/` 本地 Python 后端、客户端补丁和 `server_config/` 配置，包含尚未提交的代码。

## 1. 结论与统计口径

目前游戏已经接入本地服务器，大部分基础养成与单人玩法已有结算。剩余缺口主要集中在：角色资料／成就／称号、部分回收与出售入口、社交、独立宠物与灵系统、独立竞技／跨服／组队、月卡与外部运营服务，以及尚未开放的限时活动。

本次从原客户端调用资料筛出并用真实 `Backend.respond` 分发函数确认了 **59 个未路由请求 ID**。这不是“59 个未实现玩法”：一个玩法可能使用多个协议，其中也包含已被本地登录替代的旧账号请求、关闭的活动入口和版本上报。共用协议下的缺失分支不包含在这59个 ID中，另见第4节；协议表中没有找到调用点的保留项也不计入。

关键区别：

| 状态 | 本文含义 |
|---|---|
| 未接入 | 客户端存在发送代码，当前后端没有业务分发；请求落入 `game_unimplemented` |
| 部分接入 | 协议或模块已有实现，但部分子操作、入口或闭环缺失 |
| 离线替代 | 本地有结算，以 NPC／本地榜单／模拟支付替代真实在线服务；不应记成完全未接入 |
| 暂缓／关闭 | 客户端存在功能，但本地未开放；是否继续实现需重新排期 |
| 待确认 | 只有协议枚举或无法证明当前入口可达，不能直接算玩家可见缺陷 |

**“接入本地服务器”不代表恢复官方服务器。** 当前账号可独立存档，但真实玩家共同世界、共享仙盟、跨服匹配和支付渠道仍未恢复。本文不统计客户端纯本地设置、动画等无需服务器的行为。

## 2. 检查方法与证据

1. 对照 [协议定义表](../analysis/协议定义表.md) 与 [协议字段原始提取](../analysis/evidence/protocol_tables.json)，区分请求和服务端响应；没有把1027战报、1032属性通知等当成缺失请求。
2. 检索 `analysis/evidence/lua_named/lua/ui/` 和 `data.lua.txt` 的协议引用，并对关键项检查相邻 `main_server_send_msg` 调用。附录列出文件行号；文本中的 `[Lxxx]` 是原 Lua 源码行号，两者不同。
3. 检查 [Backend.respond](../network_redirect/backend.py) 的分发顺序，以及各模块 `HANDLED`、`handles()`、`settle()` 和客户端补丁，避免只凭文件名判断已实现。
4. 对59项无路由候选发送合法编码的零／空参数请求，使用真实分发函数，均记录到 `game_unimplemented`。有请求序号的候选均返回事件55“尚未接入本地服务端”；1326无请求序号，返回空列表。
5. 探针使用未初始化 Backend 对象，只替换日志与完成包装函数，不创建数据库、不读取真实角色、不修改存档。它验证的是路由缺失，不是业务参数合法性、真实账号认证或端到端 UI。

机器证据：[未路由请求、客户端引用、探针返回与源文件 SHA-256](../analysis/evidence/server_integration/unhandled_requests.json)。该文件记录检查时刻；项目仍在开发，后续代码变化应重新检查。此次未启动或操作模拟器，也未连接历史官方服务器，因此不声称逐按钮实机验收。

## 7. 建议接入顺序与验收条件

| 建议顺序 | 范围 | 完成条件 |
|---|---|---|
| P1：补核心操作断点 | 1307角色面板、1031改名、1069／1070切换、1086回收、1088出售 | 原按钮可操作；服务端校验、扣费、到账、回调完整；重登状态一致，重放不重复消费 |
| P2：补独立养成 | 成就、称号、1310灵、1330宠物 | 先确认原版数据与操作枚举，再补存档／计算／同步；无依据的服务端数值单独标推测 |
| P2：补离线运营闭环 | 月卡、兑换码、回归及其他运营入口 | 有明确发行／购买规则、有效期、次数、原子到账和重复领取保护；与已有模拟充值／邮件区分 |
| P3：确定多人目标 | 关注、世界／私聊、1303组队、1344跨服、1350竞技 | 先决定真实多人或明确NPC替代。真实多人需两个账号的双向可见、权限隔离、并发和持久化验证 |
| 暂不排期 | 上述21项限时活动、旧渠道账号中心、无入口保留协议 | 保持关闭；待明确范围后逐项恢复，不能先打开全部入口 |

每项至少验证“入口→请求→服务端判断→状态写入→原客户端回调→重新登录”。涉及资源必须验证失败不扣款、重复不发奖；涉及时间必须验证跨日／到期。当前59项探针只证明未路由，不替代未来功能验收。
