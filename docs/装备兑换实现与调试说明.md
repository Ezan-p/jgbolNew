# 装备兑换实现与调试说明

更新：2026-10-28；适用原版3.87客户端及本项目离线服务端。

## 入口与操作

**首页 → 活动 → 活动页右上方「装备兑换」小按钮**。入口恢复为最初的文字按钮样式，本地开放等级为30级（用户指定），未达到时点击提示“角色达到30级开放装备兑换”。该入口不需要先获得装备合成符，进入时查询服务端当前配方和已兑换记录。

原版背包使用 **装备合成符（1003）** 也会调用同一个界面；保留这个旧入口。普通碎片的背包合成、铁匠铺材料合成是另两条流程，不要与活动页「碎片」兑换混淆。

兑换页有「装备」「碎片」两栏。左上方「上一组／下一组」切换目标，每组显示三个，标注当前编号范围；末组不足三个时与上一组重叠，保证原版三个槽位均为真实目标。全部61种四／五星装备、四种通用碎片均可到达，切组／切目标清空旧材料选择。

选目标 → 添加材料 → 勾选指定数量 → 确认 → 兑换。原版允许选择强化过的装备，超过10级会先弹确认；本次已恢复这个原版行为。已穿戴、锁定、专属、进阶、铸星或转生装备不作为材料，法宝也不作为活动材料。

右上角「×」移除当前兑换图层及其倒计时、选择框和动画，回到进入前页面。重复打开不会叠加兑换层，关闭后到达的兑换结果更新状态并给出成功提示，不访问已销毁图层。

## 每周刷新与兑换限制

**按用户要求，活动每周刷新一次：北京时间（UTC+8）每周一00:00刷新，每个角色每周最多兑换1次。**「装备」与「碎片」两栏共用这1次额度，任一栏兑换成功后，本周不能继续兑换其他目标。该规则替代旧版的每件装备终身一次、碎片累计10次限制，不是原服规则考据结论。

- 右下角两栏均显示「本周剩余兑换：1/1」，兑换成功后变为「本周剩余兑换：0/1」。顶部显示「每周一00:00刷新（北京时间）」。
- 兑换成功、奖励动画完成后提示：**「兑换成功！本周装备兑换次数已用完（1/1），下次刷新：YYYY-MM-DD 00:00（北京时间）」**，其中日期由服务端计算。
- 本周再次尝试会提示次数已用完及下次刷新时间，服务端也会拦截，不扣材料、锻造符或货币。
- 下周恢复1次，并清除上一周的目标已兑换标记，可以再次兑换同一件装备；未用次数不结转，多周未登录也只恢复1次。
- 关闭页面、重登、服务重启不会恢复本周已用次数。跨周时，已打开页面会重新查询服务端；离线角色在下次查询或兑换时刷新。
- 普通背包的「40碎片＋50万银币」合成不消耗本活动次数；买更多锻造符也不会增加活动次数。

旧存档的累计记录没有兑换时间，无法判断哪些属于本周。首次升级到周规则时，将原`appointed/exchanged`归档到`equipment_forge.legacy`，本周从1次可用额度开始；只迁移一次，不追回历史奖励。之后以持久化的`week_start/used`为准。

## 原版依据与补全边界

【A】为原包可核对的客户端或表格事实；【B】为原服配置缺失后的本地补全。**没有取得原服活动配方，因此不宣称材料比例及完整目标目录是原服原值；每周1次为用户指定规则。**

| 内容 | 实现及来源 |
|---|---|
| 查询、兑换协议【A】 | 查询1055；兑换1053，`compose_type=1/2/3`分别为普通碎片合成、指定装备、换碎片；事件7／6 |
| 配方与次数字段【A】 | `appoint`提供目标、材料品质、数量及已兑换标记；`exchange.count_limit-exchanged_count`为剩余次数；`flag=1`为已兑换 |
| 材料类别【A】 | 原`getEquipsByQuality`只遍历武器和防具，按品质匹配、排除已穿戴；强化等级超过10弹确认 |
| 对应锻造符【A】 | 五星武器／防具／法宝1008／1009／1010；四星1011／1012／1013；每次一个 |
| 材料配方【B】 | 5件四星武器／防具，加目标对应锻造符，换1件指定装备；无需额外银币或元宝 |
| 碎片兑换【B】 | 5件四星武器／防具换40个所选通用碎片，不消耗锻造符；与装备共用每周1次额度【用户指定】 |
| 装备目录与限制【B】 | 原物品表中全部61种四／五星装备；下周可再次兑换同一目标。原UI固定三个展示位，本地补充分组切换 |
| 活动期限及等级【B】 | 沿用本地长期活动时间`1—2147483647`及用户指定的30级门槛；界面显示北京时间每周一00:00刷新，不再显示长期期限的天数倒计时 |
| 养成投入处理【B】 | 普通强化装备按原版允许消耗，但不返还强化银币；已进阶／铸星／转生装备继续保护。镶嵌灵石按既有服务端逻辑返还 |
| 锻造符供应【A+B】 | 原表明确为活动期集市商品；价格、数量、VIP与排序用原表，销售日期改为本地活动期 |

四种碎片为：6001四星法宝、6002五星武器、6003五星防具、6004五星法宝。获得碎片后另行合成装备：**40碎片＋50万银币**，结果池和权重读取原`material_transform.csv`【A】；这50万银币不是活动兑换碎片的费用。

## 五星武器符等锻造符怎么获得

**当前离线版的获取方式是花元宝购买： 首页 → 集市 → 全部商品，找到对应名称的符购买。** 商品较多时需要滚动列表。每份一个，VIP0即可购买，当前没有每日购买次数限制；购买后进入背包，兑换指定装备时由系统自动扣除对应符，无需提前在背包使用。

| 道具名称 | 物品ID | 单价（元宝） | 用途 |
|---|---:|---:|---|
| 五星武器符 | 1008 | 1500 | 兑换一件指定五星武器 |
| 五星防具符 | 1009 | 1500 | 兑换一件指定五星防具 |
| 五星法宝符 | 1010 | 2000 | 兑换一件指定五星法宝 |
| 四星武器符 | 1011 | 200 | 兑换一件指定四星武器 |
| 四星防具符 | 1012 | 200 | 兑换一件指定四星防具 |
| 四星法宝符 | 1013 | 500 | 兑换一件指定四星法宝 |

例如，兑换五星武器：先用1500元宝购买1个「五星武器符」，再到**活动 → 装备兑换 → 装备**选择目标，添加5件符合条件的四星武器／防具，确认兑换。成功后扣除这5件材料及1个五星武器符，获得目标武器；兑换环节不再额外扣元宝或银币。同一种符可用于该类别的不同目标，但装备和碎片合计每周最多兑换1次，购买更多符不会增加额度；下周可再次兑换同一目标。

「碎片」栏兑换不需要这些符。装备合成符（1003）是旧入口道具，也不能代替上述六种目标对应的锻造符。

**原版来源【A】**：六种符的`item_name.csv`获取说明均为“活动期间集市出售”；价格、每份数量和VIP要求直接来自`item_buy_config.csv`。原表销售日期为2013-12-11至2013-12-16，不能把这段历史日期当成当前活动日程。

**本地补全【B】**：已将这六种符恢复为本地长期活动期间的集市商品，不复活其他历史限时商品。当前核对到的原包配置及本地奖励实现没有为这六种符配置关卡掉落、乾坤袋抽取或任务赠送渠道；获取时应走上述集市购买路径，不需要刷副本或开袋寻找。

如果集市中看不到这些商品，需先重新启动本地服务并重新连接游戏，再打开「全部商品」刷新列表；仅重新打开活动页不会更新旧服务进程的商品目录。相关商品由`equipment_crafting.market_goods()`读取原表，并经`market.catalog()`加入集市。

依据：[原版字节码](../analysis/evidence/five_star_acquisition/forgeUI.txt)、[原表](../analysis/configs/item_buy_config.csv)、[本次原包哈希与规则审计](../analysis/evidence/equipment_exchange/official_audit.json)。关键位置：原`forgeUI`的141—155行、579—581行、640—663行、734—818行；`packageUI`1903—1904行。

## 两个问题的修复

1. **无法关闭**：原`forgeUI.returnBack()`调用旧`activityUI.returnBack()`，但之前适配器把兑换层直接加到主界面，旧返回函数未移除它。现在由兑换模块管理自身图层，关闭清理选中项、待发送请求及场景退出引用，保留下层页面。
2. **右下角显示`-30/10`**：原`getForgeResult`用奖励字段`count`扣剩余次数，旧配置下奖励40碎片使`10-40=-30`。服务端现在随成功事件返回已保存的完整兑换状态；客户端按这个状态校正原回调计数，同时保留`count=40`供奖励弹窗使用。采用每周规则后，两栏均为`1/1 → 0/1`，不会把奖励改成1个或只截断负数掩盖问题。

原版新版活动页有`forge=26`枚举，但3.87包的活动列表没有加入它，也没有对应`btn26/pic26/hz26`素材；本地在活动页右上方补充文字按钮，复用装备兑换界面素材。原来的三个固定目标槽位导致后续目标隐藏，本次通过分组显示修复。

查询与活动状态同步都会读取存档并检查是否跨周。旧累计记录按上面的迁移方式归档；已有周记录不会因为重登而重置。截图里的负数是客户端计算结果，重新查询即按真实记录恢复。客户端忽略上一周迟到的状态包，避免覆盖新一周额度。

所有兑换仍走角色副本结算、成功回复编码后保存：材料缺失、重复ID、错误品质、锁定／穿戴、无锻造符、次数耗尽或编码失败均完整回滚。同一请求重放不会重复扣材料或发奖励。

## 实现与验证

- `network_redirect/equipment_crafting.py`：周周期与旧存档迁移、共享额度校验、配方查询、材料验证、奖励与成功提示回传、锻造符原表商品。
- `network_redirect/equipment_exchange_client.lua`：入口、关闭、周额度与刷新提示、跨周查询、成功提示、三个槽位分组、材料过滤；由`summon.client_source`随离线启动注入。
- `network_redirect/activity.py`、`market.py`：活动状态及集市联动。
- `server_config/equipment_crafting_rules.json`：明确标注推测的本地规则。
