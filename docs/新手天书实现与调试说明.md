# 新手天书实现与调试说明

更新：2026-10-28。适用于本仓库的金箍棒3.87本地账号版。

“新手天书”现已接通原版任务界面、14项目标、奖励配置、进度提示、顺序领奖和持久化；9级目标按用户要求改为50元宝。它与开场教学 `guideUI`、福利中的“新手成长计划”、升级入口的每日新手礼包是不同系统。

本文以【A】表示原包能够直接核实的内容，以【B】表示原服务器缺失后的本地补全。没有将本地策略当作原服实现。

## 1. 入口与使用

在主界面或旅途地图点击左侧天书图标。新角色在第六场教学战斗后按原引导打开天书，领取首个20元宝奖励。完成目标后出现可领取提示；按原表顺序领取，后面的目标可以提前达成，但不能越过前面的奖励领取。全部领完后原版隐藏天书图标。

保留原版“前往”跳转、奖励说明和“新手手册”。最后一项在离线版显示“绑定本地游戏账号”，拥有本地账号的角色自动满足，仍须完成并领取前面13项才能领奖。此替代不收集实名信息，也不会把 `reg_card_finish` 写成已实名。

无需重新打包APK。后端与客户端适配代码均由本地重定向服务加载；以后修改配置，需要重新启动本地离线服务并重新登录。仅重开面板不会让旧服务进程载入新Python代码。

## 3. 原版依据和补全边界

[原包审计记录](../analysis/evidence/tian_shu/official_audit.json)包含8个原始文件的SHA-256，以及奖励表、教学阶段表与原包逐值一致性校验。

| 项目 | 依据与实现 |
|---|---|
| 【A】界面与排序 | `lua/ui/tianShuUI.lua`，使用现存资源和原14行CSV |
| 【A】普通领奖 | `1201 msg_take_prize {flag=4,id=任务ID}`；返回事件57的 `task_stage/prize_list` |
| 【A】教学首奖 | `1204 {stage=13}`；仍返回事件35完成教学 |
| 【A】进度 | 登录1017携带 `task_progress/task_prize`；第n任务为 `1 << n`，最低位不用 |
| 【A】奖励展示配置 | 事件80配置的 `[2]`，由 `data.getGoldConfig` 传给天书 |
| 【A】月卡提示 | 原版 `month_exp` 文案“三天月卡”；任务12回调打开月卡 |
| 【B】奖励分支 | 默认选择原表第一套；历史渠道/服务器选择条件不可恢复，配置可切到第二套 |
| 【B】Boss定义 | 普通旅途 `boss_type=2` 的地图最终Boss且 `pass_star>=3`；精英和中间小头目不代替首奖条件 |
| 【B】历史恢复 | 只使用现有存档中能核实的等级、养成等级、通关、修炼次数、胜利记录等，不由角色等级或榜单名次臆造获胜 |
| 【B】蟠桃会20次 | 按累计有效战斗计算，免费与付费都计入；跨自然日累计，首次迁移只能恢复当日仍保留的战斗次数 |
| 【B／用户指定】9级奖励 | 固定50元宝，替代原三天月卡；禁用该任务的月卡文案及领取后跳转 |
| 【B】渠道任务替代 | 非空本地 `register_account` 视为绑定完成，不调用失效渠道或伪造实名认证 |

9级天书奖励直接增加50元宝，不增加充值统计、VIP进度或单充/累充，不修改月卡到期时间及领取记录。已经领取的旧奖励继续保留领取位，不回收已有月卡，不重复补发50元宝。

## 4. 持久化、同步和兼容

- `task_progress`、`task_prize`永久保存，角色升级或装备被消耗后不会撤销已达成目标。
- `tian_shu`保存版本、蟠桃会累计次数及当日已观察次数。重复查询、重连、同一战斗响应重放不重复计数；不把时钟倒退当成新的一天。
- 装备强化和法术升级由成功结算后的存档事实触发；封神榜、修炼和渡劫由服务端战斗结果触发，失败/平局不算胜利，单纯战报回放不作为新的胜利。
- 每次普通领奖先获取SQLite写锁，在同一次存档中保存物品、货币/月卡和领取位。响应编码失败时回滚。同会话相同请求返回原响应，其他重复请求由持久化领取位拦截；新序列号和重启都不能再次获得同一奖励。
- 教学首奖与普通天书首奖共用任务1领取位。即使先走普通入口领取，再完成教学13，也不再发20元宝。
- 兼容上一版教学：缺少 `tian_shu` 状态但确实完成教学13的存档，补记首奖已领；旧模板 `guide_progress=0x7fffffff` 是跳过教学哨兵，不作为已经收到20元宝的证据。
- 原 `event_mgr`处理属性12、刷新天书提示，但没有处理属性13。本地适配接收独立的 `local_tian_shu` 状态，先更新两组位，再走原版属性12提示和事件57回调，解决已领状态未刷新的问题。
- 原版“全部领完”判断会永久缓存true，适配改为每次重算，避免在同一客户端切换账号后继续隐藏其他账号的天书。

既有任务位会保留。已经删除的旧装备/法术、已被清理的旧战报，以及迁移前未保存的多日蟠桃会历史不能精确还原；重新完成一次对应玩法即可继续，不清空角色和背包。

后端测试使用临时SQLite存档；原生客户端验证拦截网络发送、临时替换界面数据并在结束后还原，没有领取正式账号的天书奖励。

```sh
.runtime/venv/bin/python analysis/tools/verify_tian_shu_client.py
```

- 初版（9级仍为月卡）[天书及关联后端回归](../analysis/evidence/tian_shu/related_tests.log)：100项通过；另有[教学与普通入口共用首奖测试](../analysis/evidence/tian_shu/tutorial_dual_entry.log)1项通过。覆盖完整14项顺序领奖、原奖励总额、重启及序列冲突防重、错误回滚、首奖迁移、真实玩法结算、20场蟠桃会跨日累计、月卡追加及每日领取。
- [原版客户端验证](../analysis/evidence/tian_shu/client_validation.json)：当前12项检查；14项任务×3种状态共42个原生Cocos单元格，配置、位序、领奖请求、教学分支、跳转、奖励回调（9级不再打开月卡）和账号切换。完整生产注入脚本另作编译检查。此处不是人工逐项点击游玩的录像，也没有从新建账号自然养成至全部通关。
- 扩展测试发现已有 `test_recharge.test_same_order_is_account_scoped` 在第二个新账号尚未初始化召唤状态时直接调用加物品辅助函数，报 `KeyError: 'summon'`。[禁用本次天书进度逻辑后仍复现](../analysis/evidence/tian_shu/unrelated_recharge_failure.log)，不将其计为本功能验证通过，也未为此改动其他玩法。

本次已重新启动本地离线服务，DNS、IPv4/IPv6连接、Java HTTPS与原生HTTPS自检通过，见[服务加载记录](../analysis/evidence/tian_shu/service_reload.json)。冷启动后需在游戏登录页点击“进入游戏”，载入本账号的最新天书状态；未代领正式账号奖励。
