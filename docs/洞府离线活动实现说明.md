## 入口与基本流程

角色达到50级后，从“活动 → 洞府”进入。先建主建筑，再建药园、佛堂、修炼房和灵兽殿；种植、祈愿和目标奖励获得仙币，商店兑换仙木、修炼果及宠物材料，逐步升级建筑。主建筑、药园、佛堂达到当前规模上限后挑战红尘劫，胜利并支付原表材料即可扩建。

- 【A】五类建筑最高20级；初始规模的建筑上限11级，后续规模上限20级。规模共有3级；药园最多8块田，药田最高12级，四项修炼最高40级。
- 【A】材料、建筑依赖、豪华度、药田产量加成、种子成长时间、修炼费用与经验均读取 [原包 hole 配置](../analysis/configs/hole)。不缩短玩家作物的生长时间。
- 【A】主建筑每级增加5级神仙等级上限，20级增加100级。本次补上服务端 `cortege_limit_plus` 同步，仍受角色等级和经验表限制。
- 【B】豪华度作为全队固定生命加成；最大规模、所有建筑满级时为56250。红尘劫沿用原包 NPC 类型和本地战斗引擎，缺失的敌方等级采用已有本地配置；预览战力现在由实际敌方四维按本地权重计算。
- 【B】首次建成灵兽殿即发一次初始灵兽；满背包时延迟发放。与独立宠物系统共享实体、出战状态与幻化成长记忆。

需要重新启动本地重定向／游戏以加载 Python 服务和客户端补丁。日常游戏继续使用 [启动本地离线游戏.command](../启动本地离线游戏.command)，不需要重新创建账号。

## 本地 NPC 邻居与协作

数据来自 [players/catalog.json](../analysis/npc_design/players/catalog.json)，通过现有 `npc_players` 加载器解析。首次进入时，从等级至少50级的条目中选取10位固定邻居：以玩家首次进入的等级为基准，依次匹配“等级−10、−5、0、+5……+35”，目标限制在50—99；按等级差、固定角色ID选取，排除重复。名单保存在当前账号，升级、查询、跨日、重启不会换人。

【A/B】姓名、角色ID、等级和签名保持资料库一致；原版好友头像字段 `show_type` 要求神仙类型，因此取该 NPC 首发神仙，而非直接填入玩家头像编号。洞府布局为独立活动模拟：建筑等级 `min(20, 1 + floor((角色等级−50)/2))`；建筑超过11级使用第二规模，95级起使用第三规模。药田数量、豪华度由原表计算。不会将模拟洞府增益写回 NPC 原始战斗配置，也不会复制当前玩家的修炼、宠物或私人留言到 NPC 家中。

| 操作 | 离线规则【B】 |
|---|---|
| 访问 | 返回该邻居自己的规模、建筑、药田、留言；可从原版好友列表进入 |
| 邻居种植 | UTC+8每天零点重种原表第5种24小时作物，覆盖全天协作；不改变玩家自己的成熟时间 |
| 单田施肥 | 每位邻居的每块田每天一次，增加一次施肥计数并奖励1万银币 |
| 一键施肥 | 保留原版有效月卡要求；只处理尚未施肥且未成熟的田，重复点击不会重复发奖 |
| 邀请 | 每位邻居每天应邀一次，为玩家所有尚未成熟、未达施肥上限的田各施肥一次；没有可照料作物时拒绝，不浪费当日机会 |
| 施肥增产 | 每次增加5%，上限按所种种子的原表 `friend_plus_times`；10位邻居可覆盖最高10次需求 |
| 留言 | 1—200字，拒绝控制字符；保留玩家留言并由 NPC 用资料库签名回复，每家最多保留30条；不向外部玩家发送消息 |
| 来访记录 | 自家留言记录邀请结果，并设置新事件提示；可按原协议清除提示 |

旧版900001／900002好友的已邀请、已施肥和留言记录迁移至名单前两位 NPC，旧编号仅作为请求兼容别名，不再展示。未到次日不重置已经用掉的协作机会。

## 药园、祈愿与修炼

药园保留原版种植、升级、除虫、助手和收获协议。虫害在生长中段发生【B】，助手雇期与虫害区间相交即可代为处理；错过一次虫害减产10%。雇期最多向未来累计48小时，雇佣费用沿用本地配置每小时20元宝。

收获按“基础产出 ×（100%＋药田加成＋规模加成＋好友加成）× 剩余产量比例”向下取整。最高药田60%、最高规模20%、西瓜5次施肥25%时，基础800仙币产出1640；助手覆盖虫害时不扣损失。

佛堂必须先建成才能祈愿。每天一次，七次为一轮，漏签不清空循环；第七次附加奖励及佛堂倍率读原表。修炼四类为攻击、防御、法伤、法抗；银币每次200万换200经验、每日10次，元宝与修炼果档按表结算。

修炼批量操作不能超过当前修炼房容纳的经验；最后一次允许必要的向上取整消耗，新修炼超出上限的经验不存储、不计入周榜。旧版已经付费积存的超额经验保留，修炼房扩容后自动用于升级，不重复计入周榜。达到当前上限后不再扣费，升级修炼房后可以继续。服务器只接受实际费用和经验，不接受客户端提交的积分或胜负。

## 四类洞府福利

原版 `1348/24`：`flag=1`查询；`flag=2`领取。`all_activity` 保留原版编号72、69、70、68及结构；状态为1未达成、2可领取、3已领取。配置集中在 [home_rules.json](../server_config/home_rules.json)，全部新增经济与周期参数为【B】。

| 福利 | 离线实现 |
|---|---|
| 洞府目标（72） | 两个原生页签。四类修炼分别达到1／10／20／40级；五类建筑分别达到1／5／11／20级。每目标奖励“目标等级×100”仙币，共36项，永久一次 |
| 洞府养成计划（69） | 豪华度5000／20000／45000分别获得100／300／600元宝；即时领取尚未领过的累计档位，最高合计1000元宝，无需等线上活动结束 |
| 全民建设（70） | 玩家与10位邻居共同构成11人本地群体。豪华度2000／10000／25000／45000分别要求3／3／2／1人达到；玩家自身也必须达到对应豪华度。奖励200／500／1000／2000仙币，每档永久一次 |
| 修炼大比拼（68） | UTC+8周一零点换周，统计本周实际获得的修炼经验。与同一组10位 NPC 排名，按经验降序、角色ID升序打破平局；原生榜单显示姓名、经验、名次和预期奖励 |

全民建设原版 UI **固定读取0—3索引**的四档奖励，本地响应按该格式返回。养成计划原版文案提示“结束后发邮件”，客户端补丁已改为即时领取说明。

NPC 周榜日经验为 `400 + (角色等级−50)×20 + (角色ID mod 5)×100`，随本周已过秒数线性增长，周末结算按完整七天计算。最终第1—11名元宝奖励依次为300／200／150／100／80／60／50／40／30／20／10。仅本周实际修炼过的玩家获得奖励。

下一次本地活动初始化（例如登录、进入活动）发现跨周时，给上一参与周发一封**永久有效的系统邮件**；邮件用周编号作为幂等键。长时间离线只结算保存的参与周，不为未参与的中间周凭空补奖。邮件附件沿用系统邮件的领取和防重复机制，榜单不可通过伪造 `flag=2`直接领奖。

洞府按钮原先依赖线上活动 `TimeList`。补丁现在识别服务端 `offline_home`，即使没有线上日历也始终开放四类福利；奖励红点按当前可领取状态返回。长期福利不受旧节日日期影响，周榜仍明确显示周一结算及邮件领取方式。

## 商店与持久化

原版商店同时读取两栏 `shop_data[1]`、`shop_data[2]`。此前只返回一栏会使原版第二栏访问空值，本次补齐：

- 第一栏保留五项兑换：经验材料、仙木、修炼果、转换丹和宠物培养材料；天仙令已下架。仙木每份100个，消耗100仙币，每日限购10份（最多1000个）。
- 第二栏放入三种宠物升星石1347／1348／1349，每份5个，分别消耗300／600／1200仙币，每日各10份；其他商品价格与限购沿用现有 [activity_rules.json](../server_config/activity_rules.json)。所有商店价格均为本地推测值。
- 商品通过配置中的固定 `purchase_key` 保存购买次数，沿用原全局索引1、2、4—9；下架天仙令原编号3留空，旧购买记录不迁移到其他商品。旧存档当天已购数量继续生效。请求使用本栏连续序号：第一栏1—5，第二栏1—3。
- 商店每天零点恢复库存；主动刷新只重新读取当前库存，不收费、不重置限购。无额外随机商品和隐藏购买请求。

建筑、药田、虫害、助手、祈愿循环、修炼、宠物、邻居、福利已领状态与周积分保存至当前账号。跨日只重置每日计数及邻居作物。洞府检测到日期倒退会拒绝操作，避免倒拨日期刷新次数；不能将本地存档理解为防用户直接编辑文件的防作弊系统。

所有操作沿用 Backend 的离线副本、编码成功后提交机制。资源不足、无效ID、越界页号、重复领奖、重复施肥及编码失败均不留下资源变动；相同会话请求序号重放使用已有响应。
