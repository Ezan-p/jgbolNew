# 养成数值实时刷新修复说明

本次修复魂魄列表飞升后的数量、阵容装备预览的属性，以及法术升级结果显示旧值的问题，并处理同一数据同步机制导致的连续培养、装备和灵石养成窗口旧引用问题。没有调整消耗、收益、成功率或养成公式。

## 根因与处理

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 飞升后魂魄数量仍为旧值 | 原 `data` 接收 1046 后替换魂魄数组，`allLineupUI` 的列表仍缓存旧数组；只刷新单行会继续读取旧数量 | 重新绑定可见列表的数据源，并重新计算行数、排序及飞升／合成条件；保留筛选和滚动位置 |
| 最后一种魂魄耗尽后仍显示 | 原事件分发直接忽略 `spirit_count=0` | 同时修复导出函数和实际注册的 1046 回调，使空快照清空列表 |
| 装备强化后等级变了，属性没变 | 服务端发送通用 `effect_value=209`，原 `lineupUI.updateItemInfo` 对它是空分支 | 武器／防具／法宝分别发送原客户端支持的攻击 201、防御 202、生命 203；在结果回调前写入实例 |
| 法术升级结果与连续升级读旧数值 | 阵容等入口可能传入法术副本；原升级结果只更新部分状态，标签仍读取旧 `params.skill_info` | 打开与结果重绘前，按实例编号和类型重新绑定当前法术；保持等级、威力和失败补偿一致 |
| 培养、装备等窗口操作多次后落后一拍 | 1034／1035 全量列表替换实例；先发一次增量只能更新第一次持有的对象，下一次操作窗口仍引用旧对象 | 对相同编号、相同类型的神仙和物品原位合并快照；跨分片保留旧索引，完整接收后清理 |
| 阵容预览来自旧副本 | 预览入口及旧菜单可能保留同步前的行对象 | 打开预览／强化窗口时读取当前实例；已有可见预览在数据变化后重画 |

原包依据：

- `lineupUI` 源行 617～723：装备增量读取，201／202／203 会更新效果值，209 被忽略。
- `charPositionUI` 源行 2123～2574：装备／法术预览使用传入实例，强化与法术升级入口继续传递该实例。
- `trainingUI` 源行 65、758～760、1078～1080：窗口保留神仙引用，部分回调先绘制潜力，随后才重新取神仙。
- `data` 源行 2300～2345、`allLineupUI` 源行 203～244、365～440：魂魄数组替换、缓存和列表数据源。
- `event_mgr` 源行 751～759：原 1046 分发跳过空列表。

## 同类问题的覆盖范围

- 魂魄：飞升、合成、飞升回收、兑换、获得新魂魄、耗尽和多包同步。
- 装备：武器、防具、法宝的单次／连续／批量强化、注灵、升阶、灵石镶嵌／升级／卸下、封神和连续铸造。
- 法术：阵容副本进入升级、连续升级成功、失败补偿、材料消耗及背包分类保留自带法术。
- 神仙：培养、定向培养及其他继续持有神仙实例的养成窗口；快照可同步增量协议不能完整表达的小数和大数经验。
- 通用同步：已删除实例不回填，类型变化不沿用旧模板对象；只读的其他玩家阵容和已退出场景不重绘。

该修复针对上述已确认的数据同步和界面缓存问题；不是对每个活动、动画和界面组合都做过人工穷举。
