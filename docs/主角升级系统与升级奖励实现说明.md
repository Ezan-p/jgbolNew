# 主角升级系统与升级奖励实现说明（3.87）

实现与验证日期：2026-10-27（Asia/Shanghai）。

本次接通主角经验、连续升级、每级自动奖励、原版升级弹窗、阵位同步，以及“升级奖励”入口的新手每日礼包和加成。**【A】表示原安装包／客户端直接支持的规则；【B】表示原服配置缺失后补齐的本地规则。原服服务端源码及历史运营配置不可用，不能将【B】当成已恢复的原服数值。**

## 1. 修复前的问题与当前行为

| 问题 | 当前实现 |
|---|---|
| 旅途已有升级循环，但升级不发奖励、没有升级弹窗事件 | 统一经验结算，逐级发奖；发送原版事件2，让原客户端逐级展示升级弹窗 |
| 封神榜、渡劫消耗精力但没有主角经验 | 按战斗开始等级读取原表精力胜／负经验；渡劫反击、扫荡逐战结算，重播不发经验 |
| 太虚与旅途分别触发升级后的同步不完整 | 共用经验入口；同步等级、剩余经验、下级经验、阵位、背包与战力 |
| `1131` 无业务路由，`buff_data.buff_type=0` 隐藏入口 | 恢复原版3级入口、查询、每日领奖、倒计时和加成；登录、福利刷新、升级及跨日同步状态 |
| 原客户端当天重新进入面板复用旧缓存 | 保留原UI，只在重新打开时重新查询，避免升级超过加成门槛或重登后显示旧状态 |
| 旧存档可能保留错误的 `next_exp`／阵位 | 加载时按原表校准；保留等级、经验、资源及养成，不推算补发历史升级奖励 |

### 2.3 “升级奖励”入口的真实语义

原版 `levelUpBuffUI.lua` 源码行514～535要求人物至少3级，且 `common_config[24].buff_data.buff_type>0` 才显示入口；`can_take` 控制可领提示。

原包文本 `assets/release_/08b0428edce64d19f304d30c3829ec87.data` 的 `lub_tink*` 明确说明：

- 新手期间**每天**领取道具，显示还可领取的天数。
- 存在银两和经验百分比加成、加成有效期、每日有效体力额度及失效等级。
- 超过经验加成等级后，仍可领取每天奖励。
- 同一UI还支持合服福利和限时经验活动，属于其他活动分支。

因此，1131并不是“达到10／20／30级领取固定档位礼包”。原缺口清单中的“分档状态”表述已更正。福利模块另有成长基金等按等级奖励，本次不重复发放那些奖励。

| 原协议 | 实现 |
|---|---|
| `1131 {op_type=0, flag=1, id=0}` | 查询每日新手福利 |
| `1131 {op_type=0, flag=2, id=0}` | 领取当天一份礼包 |
| `2998/event 140 friend_buff` | 原 `callback_getBuffData` 接收查询／领奖结果 |
| `2998/event 80` 中 `[24].buff_data` | 同步入口和可领状态 |
| `1131 flag=3/4` | 原合服领奖／限时经验查询；本地无对应活动，不开放并返回明确提示 |

查询返回 `flag/can_take/left_times/left_days/exp_add/exp_plus/expect_level/max_strength/attach_list`；领取返回 `flag=2/attach_list`。不使用名称相近的 `event 156 upgrade_buffer`，该事件实际属于法术进阶回调。

原始反汇编证据：[mainUI](../analysis/evidence/lua_named/lua/ui/mainUI.lua.txt)、[levelUpBuffUI](../analysis/evidence/lua_named/lua/ui/levelUpBuffUI.lua.txt)、[event_mgr](../analysis/evidence/lua_named/lua/event_mgr.lua.txt)、[common_def](../analysis/evidence/lua_named/lua/common/common_def.lua.txt)。

## 3. 原服缺失部分的补齐规则【B】

集中配置：[server_config/progression_rules.json](../server_config/progression_rules.json)，明确标记 `mode=inferred`，启动时校验格式、范围和奖励ID。

| 补齐项 | 当前值／策略 | 选择理由 |
|---|---|---|
| 每级自动奖励 | 每次实际升一级发小包子1020 ×1，从1升2起 | 小包子来源有原文；数量缺失，采用最小实用奖励，间接提供5体力 |
| 额外自动资源 | 不另加元宝、银两、直接体力／精力或主角四维属性 | 原包未提供这些每级奖励的可靠数值；属性养成仍由修炼等已有系统承担 |
| 新手福利有效期 | 首次创建／迁移本功能状态所在北京时间自然日起7个自然日 | 原UI提供天数，但原服时长不可恢复；迁移旧档也给完整起始周期 |
| 每日礼包 | 小包子1020 ×2、银两10000 | 采用已知升级相关道具和基础资源，避免虚构五星神仙等奖励 |
| 开放与领取 | 3级起；每天一次；超过30级仍可领；错过日期不补领 | 3级门槛与超过加成等级继续领奖来自【A】，补领策略与期限为【B】 |
| 新手加成 | 3～29级，经验和银两额外+50%；每日前60点体力有效 | 原UI有这些字段，实际数值缺失，采用可配置的温和加速 |
| 加成范围 | 旅途／释厄／太虚的主角、上阵神仙经验和战斗银两；包含失败结算及首胜神仙额外经验 | 原文只称“银两和经验”，具体适用细节不充分，明确作为【B】 |
| VIP加成 | `exp_plus=0` | 未找到该活动独立VIP加成表，不复用充值VIP的其他倍率 |
| 精力经验应用 | 封神榜、渡劫、渡劫反击每消耗1精力给一份相应胜／负经验；渡劫扫荡逐战结算 | 原表值为【A】，各玩法挂接及平局按失败处理的服务端策略为【B】 |
| 主角上限 | 99级；达到后经验最多保留99级行的22453200，不再升100、不再发奖 | 原表只到99级为【A】；满级剩余经验保留方式为【B】 |
| 旧档迁移 | 历史等级记为已处理，不补发未知历史奖励；下一次真实升级正常发奖 | 防止重启、旧档加载或人工调整等级产生重复奖励 |
| 合服／限时双倍 | 不创建虚假合服或运营周期 | 1131相关分支明确拒绝；未来有证据可独立接入，不冒充新手礼包 |

新手福利从账号首次创建／本功能首次迁移开始计自然日，**不是进入面板或首次领取时才开始**。例如起始日只玩到2级，这一天也计入有效期。`left_times` 记录尚未领取份数，`left_days` 记录剩余自然日；跳过日期后两者可能不同，但每天仍最多领取一次，到期全部停止。

### 3.1 经验计算与整数边界

设战斗前等级为L，实际消耗体力为S，仍可享受加成的体力点数为E，百分比P=50：

```text
主角经验 = 原表[L][win_exp或lose_exp] × S
         + floor(原表[L][win_exp或lose_exp] × E × P / 100)
神仙经验／战斗银两 = 对应基础结算 + floor(对应基础结算 × E × P / (100 × S))
```

无有效加成时E=0；不会给精力玩法套体力加成。额度只使用实际有效的部分：3级消耗3体力、当日仅余1点加成额度时，胜利主角经验为 `15×3+floor(15×1×50/100)=52`。

获得经验后，循环扣除每一级的 `upgrade_exp`，保留余数，逐级发奖和更新阵位。扫荡每一战重新读取当前等级与加成额度，所以跨等级后后续经验基础值随之变化。单场以战前等级判定加成，跨到30级后下一场停止享受。

神仙升级上限、四维成长、首胜奖励等沿用现有养成／旅途系统，本次不改写它们的原有规则。满级神仙仍不积累本次战斗经验。

## 4. 代码、存档与安全结算

- [progression.py](../network_redirect/progression.py)：状态初始化、表内等级校验、经验循环、每级奖励、加成额度、1131查询／领取与升级事件。
- [journey.py](../network_redirect/journey.py)：旅途与释厄；[activity_undergo.py](../network_redirect/activity_undergo.py)：太虚，共用经验结算。
- [activity_rank.py](../network_redirect/activity_rank.py)、[activity_rape.py](../network_redirect/activity_rape.py)：封神榜和渡劫精力经验；战报重播和不消耗精力的防守模拟不会重复结算。
- [backend.py](../network_redirect/backend.py)：登录／迁移、消息分发、属性与奖励同步、升级事件；[welfare.py](../network_redirect/welfare.py)：福利刷新不再把新手入口置为关闭。
- [progression_client.lua](../network_redirect/progression_client.lua)：原面板重新打开时刷新数据，经现有客户端补丁加载链生效。

状态保存在角色JSON的 `progression`：`rewarded_level`、`start_day`、`claimed_days`、`strength_day`、`strength_used`。仍由当前账号自己的SQLite存档持久化。

所有经验、奖励、日期由服务端计算。沿用现有分发器的串号缓存和临时角色副本；重发同包复用响应，过期串号拒绝，编码／校验失败不提交本次奖励。跨重启的重复每日领奖由 `claimed_days` 拒绝。加载／迁移不会把现有包子或已领奖状态清空。

等级、背包、阵位等先同步，升级事件在战斗回放启动事件44之前发送；扫荡同样带升级事件。原版 `playerLevelUp` 逐级展示，每级只显示这一份奖励。
