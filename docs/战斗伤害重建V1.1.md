# 战斗伤害重建 V1.1

本次依据用户提供的《普通攻击与主动法术伤害计算说明_V1.1.md》补全伤害结算。该文档明确声明公式为候选规则【B】，不能据此认定原服机制已完全还原。原包技能强度、等级成长、触发概率及精魄逐级参数为【A】。

## 已接入

- 普通战斗（旅途及复用其引擎的活动、仙盟玩法）和九幽冥仙共用 `network_redirect/combat.py`。
- 普攻采用 `max(0.05A, A-D)`；法术采用 `S=0.25A+3M`、线性强度倍率、`2/(N+1)` 目标折算及 `1-R(1-ρ)`。
- 技能沿用装备顺序逐项尝试触发，首个成功者替代普攻；全失败则普攻。多技能选择顺序为现有本地策略【B】，并非已证实的原服行为。
- 精魄铭刻参数从 `ext_skill.csv` 的等级列读取：普攻强袭／格挡独立概率判定；法抗／破法只影响法术；威慑及招架只修正强袭附加部分。
- 觉醒、星宿作用于法术强度，不重复叠加技能等级倍率。伤害分数保留至最后取整，并限制在目标当前生命以内。
- 威慑削攻持续至下一主行动；破甲取最强值、不叠加，作用于后续命中；战意按每两回合提升攻击。这些状态时序与叠加策略属于【B】。九幽原有破甲即时生效及复活、吸血、追加行动事件保留。
- 显示战力系数未调整，未修改玩家存档。

## 配置

`server_config/journey_rules.json` 的 `battle` 明示 `formula_revision=candidate-v1.1`。移除旧的法力50%与防御折算开关，配置法力／攻击系数、强度曲线及目标上限；加载时校验数值。

原表只有单体／群体标记，群体描述为全体，因此默认 `multi_target_limit=8`【B】。`skill_target_limits` 可按技能编号覆盖；不能随存活敌人数减少提高单目标伤害。原始 `formula` 是公式组编号，仓库尚无可直接执行的原服公式实现，不能把编号当成目标数。

## 文档算术校正

A=10000、M=3000、D=5000、I=300：普攻5000、法术10307；法抗30%时为7215（文档写7214，但精确计算 `6500×111/70×0.7=7215`）；破法42%时8513。实现以公式和最终统一向下取整为准。

## 尚未证实或未覆盖

完整原服还原仍需要原服战报校准。一般战斗的吸血、反击、连击、治疗、中毒、祝福、复活等完整事件链、如来护盾与分摊并非此次伤害公式修复覆盖范围；九幽已有的相关事件逻辑仍保留。破法描述中的“释放概率提升”未给明确数值，因此不臆造概率。普通精魄与星宿的暴击叠加、修炼增益顺序、特殊公式组及精确选敌规则仍为候选实现，需要后续证据。

## 验证

`tests/test_combat.py` 覆盖文档公式、算术校正、最终取整、生命钳制、普通与法术效果隔离、配置目标数、概率边界、精魄参数、状态时序以及两种引擎的一致性和输入隔离。
