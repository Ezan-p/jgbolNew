# 仙盟模块剩余功能分析

适用客户端：金箍棒 OL 3.87。检查对象：本仓库 Python/SQLite 本地后端。检查日期：2026-10-25。

本文只回答“还剩哪些没有实现/只做了占位”，不重复已在 [仙盟模块规则与调试](仙盟模块规则与调试.md) 中说明的完整规则与调试步骤。实现范围以 `network_redirect/guild*.py` 为准，客户端契约以 APK 内 LuaJIT 字节码、协议枚举和原版 CSV 为准。

## 一、结论摘要

### 1. 当前已经接入的范围

仙盟主流程已经可以离线跑通：

- 仙盟创建、加入、退出、解散、公告、内部公告、改名、任命、禅让、踢人、禁言、解禁、清空禁言、查询、申请列表（空）、事件、聊天。
- 神树查询、任务、种植、培育、捐献、购买树种、守护排行、守护战斗。
- 贡献商店查询、刷新、购买。
- 宴席查询、举办、抢礼、赠礼、领奖及宴席增益。
- 秘境组队、挑战、战报、寻宝（部分子类型）、灵兽试炼、援助、指定成员、领奖、兽栏、幸运捕获、战报。
- 灵兽任务、战斗、游历、捕捉、商店、排行。
- 本服盟战报名、随机目标、押注、战斗、排行奖励；跨服查询、跨服战斗、跨服商店、跨服领奖。
- 取经入口、合成、路线、资料、刷新、出发、护送令、拦截、领奖、黑名单、请求护送。
- 仙盟聊天 1097/1098 与查询 18/7；配置段 8 推送。

证据记录显示原版客户端 52 个回放步骤通过；本次复跑 `tests.test_guild` 30 项与全量 330 项测试通过。注意：这些通过只证明所列步骤没有 Lua 错误或服务端异常，不等于每个按钮、每种失败状态和完整战斗播放都已人工验收。

### 2. 剩余缺口总览

本文共整理 **35 项**缺口/限制，按性质分为四类：

| 类型 | 含义 |
|---|---|
| 占位/固定数据 | 界面能打开，但数据固定、只统计本人或没有真实结算 |
| 未接入 | 客户端可达的流程没有服务端实现，或客户端期望的事件从未推送 |
| 多人/跨服缺口 | 单机离线架构下以 NPC/固定对手代替，真实多人语义缺失 |
| 工程/不可恢复 | 官方数值、随机种子、并发/跨进程幂等、回放覆盖等限制 |

> 部分条目同时具有多种性质（例如 A1 既是“未接入”，也是“多人缺口”），因此上表不按类型做严格计数；35 项为下文字段编号总数。

> 说明：本仓库定位是可运行的单账号离线环境。“真实多人、真实跨服、官方线上数值”不是当前架构能完整恢复的内容，本文会明确标注，不会把它们说成普通待办。

### 3. 最值得优先处理的 6 项

1. **神树种植威望门槛缺失**：`require_pop` 恒为 0，客户端提示“威望达到 0 可以种植”，服务端也没有校验。
2. **寻宝“扫完剩余次数”未扣费**：返回了 `sweep_gold_cost=10`，但实际没有扣除元宝，存在经济漏洞。
3. **盟战核心规则缺失**：生命点、按职位计算的功勋点、连胜与失败扣生命点均未实现；行动力只有简单计数。
4. **灵兽只有计数没有养成**：兽栏中的灵兽只是类型 ID 列表，没有属性、品质、经验、合成、升级、升星。
5. **组队申请审核是死流程**：申请 27 直接进队，28/29 永远返回“没有待处理的组队申请”，50 也不返回申请列表。
6. **客户端期望的 93/94 更新事件从未推送**：灵兽游历/捕捉后的 `update_list`、广播和列表刷新缺少服务端事件。

### 离线替代说明（不是 bug）

以下行为是当前单机架构的刻意替代，本文不计为“未实现”：

- 默认创建“本地仙盟”并提供一个 NPC 盟主；加入默认盟自动通过，避免没有第二个真实账号。
- 盟战、跨服、秘境、取经、灵兽战斗使用本地 NPC 或固定对手，不进行真实玩家匹配。
- 排行、押注结果和部分奖励使用本地规则或固定名次，不连接官方赛季数据。
- 所有战斗使用 `network_redirect/journey.py` 的本地战斗引擎，不恢复官方随机种子、隐藏 AI 和线上战力。
- 合服补偿 77 没有对应合服活动，刻意不伪造成功响应。

## 五、建议实施顺序

### 阶段 1：先修正确性/经济漏洞（单机也值得做）

1. **B1 神树威望门槛**：补配置项（原版数值未知，先按【B】明确一个阈值），在种植 14 校验并返回真实 `require_pop`。
2. **D3 寻宝扫荡扣费**：flag 6 扣 `sweep_gold_cost`，失败不扣；顺带补齐 flag 1/3 的专用返回。
3. **E2 盟战核心规则**：生命点、行动力、按职位功勋、连胜/连败、失败扣生命点，先做本地可验证版本。
4. **C1 福气榜**：至少按赠礼/抢礼累计本盟成员的 `fortune`、`normal_gift`、`advanced_gift`，替换固定 0。
5. **A3 仙盟列表/排名**：至少加入 2–3 个 NPC 仙盟并按威望/等级排序，让列表与名次有业务含义。

### 阶段 2：补主要玩法与多人流程

1. **D1 组队申请/审核**：建立申请记录、申请列表 50、同意 28/拒绝 29/清空 30，并补推送。
2. **A1 入盟申请/审核**：建立申请记录、事件 82 的 `event_id=7/8/9`，保留自动通过作为单机开关。
3. **D4 灵兽试炼**：boss 血量持久化、成员伤害榜、援助人数、阶段奖励。
4. **D5 灵兽实体与养成**：这是独立的大功能，建议单独设计 `pet` 数据模型、背包/兽栏、合成/升级/升星与属性计算。
5. **D6/D7/D8 灵兽任务/游历/商店/排行**：任务池、捕捉概率、93/94 推送、声望周结算。
6. **E1/E3 盟战赛程/分组/押注**：在本地 NPC 盟基础上做小组赛和名次奖励。
7. **F1/F2 取经社交**：被劫记录、黑名单生效、请求护送、路线品质/保护状态。

### 阶段 3：多人/跨服/架构

1. **A2/A4/A7**：更多 NPC 成员、职位层级校验、等级人数成长。
2. **E4 真实跨服**：需要跨进程/跨服务器路由、房间、赛程和商店同步，超出当前单机后端范围。
3. **G4 跨进程幂等/并发**：引入请求幂等键、数据库事务锁、多账号存档隔离。

### 阶段 4：低优先或明确不补

- A5 禁言时效、A6 每日申请/加入额度、A8 资金流水：属于完善度，不影响主流程。
- B3 树等级收益、B5 商店随机刷新、C2 宴席广播：需要先确认原版规则。
- G2 未路由协议：77 合服补偿明确不实现；10/17/49 暂未发现入口。
- G3/G6：官方战斗数值、随机种子、完整回放覆盖无法从客户端恢复，只能标注边界。

## 七、边界声明

1. 本文是静态代码 + 客户端字节码 + 本地运行时探针的检查结果，不代表官方服务端行为。
2. “未实现”包含三类：真正缺失（如灵兽养成）、离线替代（如固定 NPC 对手）、有意不实现（如合服补偿 77）。后两类不应简单当成 bug。
3. 真实多人、真实跨服、官方随机种子、隐藏 AI、线上赔率和赛季数据不在当前单机架构内；如果目标是联机，需要另建网络层与并发模型。
4. 客户端回放通过只证明所列步骤没有 Lua 错误，不证明每个按钮、每种失败状态和完整战斗播放都已人工验收。
5. 建议先明确产品目标是“单机可玩”还是“多人联机”：单机优先做阶段 1；联机则阶段 2/3 中的 A1、A2、D1、D2、E4、G4 需要提前排期。
