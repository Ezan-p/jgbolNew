### 战斗和结算

- 【A】1026 提交 `fight_type/des_type/des_value/des_id`；旅途目标为 `des_type=1,des_value=0`，关卡 ID 通过 double 字段传输。客户端不提交胜负或伤害。
- 【A】1028 提供双方初始血量、类型、进化等回放阵容；1027 提供战斗 ID、结果和动作列表。每条动作包含施法方、站位、技能、回合、目标及最多八个伤害值。
- 【A】先缓存阵容及结果，再通过 2998/event 44 启动 `fightUI.actFight`。event 45 中角色用 `obj_type=1,exp_plus`，神仙用 `obj_type=4,exp_list`，神仙经验表按出战位置索引。
- 【A】原版胜利星级按剩余总血量比例：不少于 70% 为三星、不少于 40% 为二星，其余一星（`fightUI:1774–1869`）；结果枚举我方险胜/普通胜/大胜为 1/2/3，对方胜为 4/5/6，平局为 0。
- 【A】结束回放发 2998/event 3。服务端只确认，不再次奖励。
- 【A】角色等级表含 `win_exp/lose_exp/upgrade_exp/cortege_count`；神仙经验使用 `cortege_experience.csv`，关卡神仙经验及银币字段为 `exp/money`。第一普通关原表神仙经验 100、银币 150，第一章最后一关神仙经验 200、银币 240。
- 【A】`mapUI.getLastFightExpAndMoney:139–152` 根据 `last_fight_npc` 取原表经验和银币。`event_mgr:763–895` 的 1019 处理会修改这个关卡号，并推进下一关。不能为“新解锁但未挑战”的下一关补发 1019。

### 奖励

| 字段或协议 | 【A】原包内容 | 【B】服务端采用的解释 |
| --- | --- | --- |
| `first_random_prize` | 首次奖励条目，格式 `对象类型\|类型ID\|数量\|等级\|概率` | 首次获胜且此字段非空时替代普通随机奖励；否则读 `random_prize` |
| `random_prize` | 通常随机奖励，格式同上 | 每条按整数百分比独立抽取，0 不发、100 必发，无额外隐藏掉率 |
| `com_win_prize` | 大胜奖励，客户端有独立展示 | 首次达到三星时发放一次；重复三星不重发 |
| `first_win_prize` | 非空条目为两段数值，例如普通 308 关 `800\|100` | 首次获胜按第二段百分比抽取第一段经验，加给每位出战神仙；不改角色经验。接收对象及含义缺少原服验证 |
| `pass_map_prize` | 章节奖励四段格式，普通章节配置包子 1022×1，概率 100 | 普通章全部关卡三星可领取一次 |
| event 22 | `prize_type=1/2/3` 分别用于随机、大胜、地图奖励 | 道具、货币、神仙或魂魄先保存、同步，再发原版展示回调 |
| 1201 | `flag=3,id=章节ID` 领取地图奖励 | 服务端再次校验完整三星及未领，禁止仅凭客户端状态领取 |

【A】原表奖励对象类型 4/5/6/7/11/12 对应神仙/物品/法术/魂魄/元宝/银币。实现校验全部关卡奖励引用，错误配置拒绝整笔结算。

## 【B】缺失服务端规则的实现配置

[journey_rules.json](../server_config/journey_rules.json) 明确 `mode=inferred`，版本 `2026-10-24-journey-1`。启动校验版本、范围和策略枚举；无效配置拒绝加载。

| 推测项 | 当前实现及理由 |
| --- | --- |
| 日期边界 | UTC+8 每日零点清除挑战、刷新、资源道具计数；保留星级、已领奖和真实扫荡结束时间，防止借跨日取消冷却 |
| 自然恢复 | 体力每 360 秒 +1、精力每 900 秒 +1；离线时间也累计至 30/15，自然恢复不削减超额资源。原包有上限但缺少可靠的服务端恢复间隔 |
| 资源道具限额 | 包子与仙丹分别每日最多使用 10 次，库存使用和购买使用共用各自计数及价格序号 |
| 普通刷新 | 全局每日最多 10 次；每次将本关已用挑战次数减 10，最低归零，同时增加刷新次数。精英刷新恢复完整单关额度，不能重置全局 30 次挑战 |
| 角色经验 | 原角色表 `win_exp/lose_exp × 本次体力消耗`；连续升级、更新经验阈值和出战槽位，满级经验截在阈值 |
| 神仙经验 | 胜利按关卡 `exp`，失败给 50%；每名出战神仙单独获得，首胜额外经验按上表处理；等级上限和培养点延用既有阵容模块策略 |
| 银币 | 胜利按关卡 `money`；失败为 0；不额外赠送推测的固定掉落 |
| 扫荡星级 | 使用该关历史最佳星级；不因扫荡自动升级星级或补发尚未取得的三星奖励。逐次结算奖励，但整批资源校验失败时全部回滚 |
| 战斗先手与顺序 | 挑战者先手，按位置 1–8 双方交替行动，死亡位置跳过；普通单体攻击默认打对方存活最前位置 |
| 普通伤害 | 采用V1.1候选5%保底与最终取整，完整精魄事件见[战斗V2](战斗机制重建V2.md) |
| 主动法术 | 使用0.25攻击+3法力、强度倍率、配置目标数折算、法抗与破法；概率只决定触发，详见[战斗V2](战斗机制重建V2.md) |
| 回放上限 | 最多 240 次动作，低于协议 byte 数组上限；未分胜负时比较双方剩余血量比例，相等判平，避免无限战斗 |
| 奖励随机 | 每条独立百分比；首次胜利与首次三星的资格以历史最佳星级判定，失败不消耗首胜资格；概率命中与资产保存属于同一次结算 |
| 持久化与重试 | 在角色副本上计算，先编码回复，再保存。会话缓存最近 256 个旅途请求，同序号同包返回原回复，同序号异包或过期序号拒绝；登录清空缓存。这不是跨会话交易 ID 系统 |
| 旧存档 | 仅初始化缺失的旅途字段，不赠送进度或资源；无法从旧服务端的空关卡回复恢复历史通关。已有背包、神仙与经济保留 |

### 无法据客户端宣称已恢复的部分

【B】战斗后续已统一接入19类精魄、星宿免死、大乘经护盾／分摊和完整生命事件回放。缺失原服战报的时序和叠加采用明确候选设计，见[战斗机制重建V2](战斗机制重建V2.md)，不代表原服公式已证实。

【A】关卡 CSV 还存在 `genius_prob` 等历史字段；当前审计的旅途执行链没有足够证据恢复其效果。【B】保留原表值，不发送未经验证的“神佑”等额外奖励事件，也不虚构隐藏概率。原服后续若有配置或战报，应优先替换上述推测。
