# 封神榜离线活动规则与调试

日期：2026-10-25。入口仍为原版“活动 → 封神榜”，也可从名人山进入。重新启动本地游戏服务后加载新后端及客户端兼容补丁。

## 可玩的流程

6级开放。玩家与99名本地NPC组成百人榜，初始第100名；旧存档保留当前名次、积分、已领晋升奖励和当日挑战消耗。选择可挑战对手、查看阵容、调整自己的阵容、战斗、胜利换位、翻牌领奖、积分兑换；登顶后仍可挑战身后的对手。榜首展示与名人山一致。

每天恢复基础次数，普通账号5次，VIP额度沿用VIP模块。每次主动挑战消耗1精力；封神令牌1021每枚增加3次当天机会，最多累加300次。令牌使用、战斗胜负和奖励都由本地服务端结算。请求重发不会重复扣资源、发奖或交换名次；编码失败和无效操作不提交存档。

## 证据口径

- **A：原包依据。** 原版3.87协议、`rankUI`、`checkLineupUI`、`fightrecordUI`、物品描述及CSV。审计可运行 `analysis/tools/audit_rank_rules.py`，结果见[审计及榜单映射](../analysis/evidence/rank/audit.json)。
- **B：服务端缺失后的推测。** 百人榜规模、NPC挑选、挑战范围、每天一次离线防守、奖励补领与离线累积上限、翻牌概率等，集中在实现和配置中说明，不称作官方算法。
- **C：NPC设计。** 阵容来自用户指定的 [analysis/npc_design/v1/catalog.json](../analysis/npc_design/v1/catalog.json)，五档培养、三种流派沿用[NPC设计说明](NPC玩家设计说明.md)。

## NPC与排行

固定使用代表等级5～99的快照，排除设计库中已标记 `replay_limit_observed` 的样本。用当前统一战力结算器重新计算，再按实际战力排序，等间隔选出99种不同阵容；NPC标识为930001～930099，独立于玩家账号和其他活动。审计文件列出每个标识、模板、等级、流派和战力。

NPC不跟随玩家等级或战力自动加强。上阵、替补、法术、装备、助威、精魄、觉醒与命星都取自同一快照；战斗附加精魄和命星效果，查看页按真实阵位排序，并展示相应装备与技能。没有将NPC的库存或养成资源写入玩家账号。

【B】向前1／2／5／10／20名提供挑战，重复位置合并。靠近榜顶时用身后对手补足5个挑战目标；额外显示前十名，远处的前十仅能查看。胜过前方对手就交换名次；挑战身后对手落败会交换名次；败给前方对手不降名次。未分胜负不交换名次、不发胜利奖。

【B】已有晋升记录的玩家，每天首次打开榜单时，由身后一名NPC进行一次本地防守战。离线多天也只处理一次，不扣玩家精力或次数，不发主动挑战奖。失败后保留该NPC为反击目标，并使用原版 `top_relation=3` 提供反击按钮。反击仍消耗正常挑战资源并按当前排名结算。没有读取其他本地账号或访问真实玩家服务器。

原有活动战斗引擎仍有动作数和效果数据包上限。触及上限的战斗按引擎的未决结果显示，不按剩余血量伪造胜利，不发胜利奖，也不发生防守降名次。已知高风险NPC不纳入榜单，任意玩家养成阵容仍可能打成未决。

## 积分、日奖和翻牌

【A】沿用原表 `top_score.csv`、`top_score_exchange.csv` 的全部名次区间和兑换内容，逐值与原包核对。

- 每半小时按当前名次的 `score` 增加积分。胜利另外获得当前名次的 `score`。半小时增长由原界面文案确认；胜场加分是保留的本地推测。
- UTC+8零点结算昨日最高名次对应的 `day_score`，第二天可领取一次。当天首次加入没有昨日奖；跨日不需要先挑战。
- 【B】断线期间按最后已存名次累积，最多补7天的半小时积分；只保留最近一天的未领奖，过期日奖不逐日堆积。积分封顶16777215，与原客户端常量一致。
- 晋升奖按历史最好名次领取一次，之后掉名次仍可补领。原表5000／1000／500／100／10／1档均保留；由于本地榜压缩为100名，首次胜利会同时满足前四档，这是本地百人榜的明确差异。
- 【B】胜利额外银币1000，翻牌从蟠桃5个（70%）、封神令牌1枚（10%）、蟠桃10个（20%）中选一项。原版卡片协议必须正好5项且只有1个 `flag=true`，该项在服务端先入包，其余四项仅展示。关闭翻牌或断线不会丢奖，重复播放不会再领奖。

兑换项目：5000积分换100蟠桃；50000积分换1000蟠桃；50000积分换15个1343物品。晋升奖励保持原表，服务端拒绝积分不足、重复领取、未达到历史名次和伪造项目。

## 原客户端兼容

[rank_client.lua](../network_redirect/rank_client.lua) 保留原榜单、挑战、兑换和五张翻牌布局，修正昨日排名和日奖可领状态，并增加“战报／防守”按钮。按钮使用原版战报列表与动画，返回时回到封神榜。榜单与战报的读操作不重新结算奖励。

查看NPC时按1～8号阵位发送神仙，避免原客户端 `sortCharacters` 用数组下标覆盖阵位。远程神仙不发送本地对象ID，防止详情页错误查玩家自己的精魄；发送精魄、命星的阵位索引。装备补齐原查看公式要求的 `goss_plus=0`，神仙同时提供四维原字段与展示字段。

战报跨日和重启保留最近5场，含主动挑战和防守。为适应原版单包上限，列表按字节预算显示可完整传输的最新记录；不截断单场回放。回放使用原有跨服战报容器118，列表与进入按钮明确位于封神榜，不产生额外跨服挑战。
