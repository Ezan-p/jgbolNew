# 主角修炼离线活动实现说明

更新：2026-10-26。活动入口为“主角修炼”，与神仙培养、洞府修炼和好友试炼分别处理。

## 游玩流程

角色达到5级后，从活动进入主角修炼，点击开始挑战阎罗王。使用当前上阵神仙进行真实本地战斗，播放原版战报；胜利后自动结算一项永久属性，返回结果框查看奖励，再返回修炼页面。失败可以在结果框重试，也可以返回调整阵容。

可成功修炼次数为 `max(0, 角色等级−4−已成功修炼次数)`。5级有1次，每升1级再增加1次；99级累计95次。未使用次数会累积，不随每天刷新。失败和未决战斗不扣次数、不发奖励；挑战不消耗体力、精力、银币、元宝或道具。

## 原版证据【A】

- [practiceUI 反汇编](../analysis/evidence/lua_named/lua/ui/practiceUI.lua.txt)：51—152行对应5级开放、次数公式和累计四维展示；154—169行对应请求；171—291行对应胜负结果、返回和失败重试。
- 原版请求为 `1026 {fight_type=4, des_type=1, des_id=0, des_value=0}`，对手由服务器确定。阵容走1028、战报走1027、事件44开始播放。
- `event_mgr` 的事件5接收单个 `addition_field/addition_value`。`createPracticeContent` 使用互斥分支，每次消费一个属性。因此本实现每胜只发送一个奖励事件，修复旧版同时发四项、结果框只显示一项并遗留其他字段的问题。
- 原客户端运行时文案为“提示：所有上阵神仙，%s增加%d点”“修炼次数不够，请先提升主角等级”“提示：调整阵型，增强实力，再次修炼”。加成为角色永久属性，当前及以后上阵的神仙都可享受；统一属性重算也会更新背包面板。
- 使用 [cortege_base_0.csv](../analysis/configs/cortege/cortege_base_0.csv) 的5001号阎罗王及原包形象、姓名、基础属性、成长、天生法术207。基础气血522、攻击218、防御124、法力137；每级成长分别39、15.7、9.28、10.29。战斗计算复用现有本地引擎，不能据此声称恢复了官方服务端伤害公式。

## 补齐的离线规则【B】

缺少官方修炼关卡表、奖励数量和抽取概率，以下明确为推测，可在 [practice_rules.json](../server_config/practice_rules.json) 调整。

| 项目 | 当前实现 |
| --- | --- |
| 固定对手 | 阎罗王5001，一名；不读取通用活动对手配置 |
| 等级曲线 | 第n次成功前挑战n级阎罗王，范围1—95；补做低阶修炼不会因角色升级而突然变难 |
| 天生法术等级 | 固定1级 |
| 奖励选择 | 气血、法力、攻击、防御各25%，每次成功仅选择一项 |
| 奖励数量 | 气血+20／法力+10／攻击+5／防御+5；沿用 activity_rules.json 的 train_increase |
| 失败策略 | 进度不前进，下次挑战同一等级，免费重试 |
| 额外资源 | 不另加经验、银币、物品或未恢复的首胜礼包 |

[95阶段曲线](../analysis/evidence/practice/stage_schedule.csv) 可查看每次挑战等级、原表成长后的四维和法术。[规则审计](../analysis/evidence/practice/rules_audit.json) 记录原版来源与推测边界。

## 存档与防重复结算

`rule_index` 和四项累计加成继续使用原字段；旧存档曾经同时获得的四维加成不会扣回或重新计算。最近一战的阶段、阎罗王等级、胜负、奖励、时间和规则版本保存于 `activity.practice_last_result`。

服务器决定胜负与奖励，不接受客户端指定敌人、奖励或结果。相同请求序号重发返回已缓存响应，不重复抽取或发奖；不同合法请求序号表示下一次挑战。编码失败、参数非法或次数不足时整次操作回滚。跨日、重连和服务端重启不会刷新已消耗的永久次数。

- 原版动画验收完成：真实战报自然播放结束，结果为3星胜利，返回修炼奖励框，未消费奖励字段为空、错误记录为空，测试后已恢复玩家状态。
