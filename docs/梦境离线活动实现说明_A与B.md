# 梦境／仙梦居离线活动实现说明：原版规则 A 与推测规则 B

> 2026-11-03：已按要求隐藏“梦境／仙梦居”入口，重新启动客户端以加载入口补丁。活动实现与存档保留；下文入口操作说明为隐藏前的记录。

日期：2026-11-02（Asia/Shanghai）。原版入口 **40**，模块 `dreamUI`，请求 **1325**，回调 **2998／169**。本次实现已接入当前工作区的离线服务端与客户端适配脚本；沿用原版美术、拼图、动画、好友选择和奖励窗口。

**A** 表示原包／原服资源末版1263的客户端证据；**B** 表示缺少原服务端实现、运营参数或存在版本冲突时，本次采用的明确补全。A 能证明客户端规则和配置表值，不等于取得了原服结算日志。NPC 好友是离线模拟角色，不代表真实联网玩家。

## 1. 进入和完整游玩流程

使用当前工作区启动本地游戏，重启服务和客户端以加载新增路由与适配脚本，无须清档。**角色18级后，在奇闻中选择「梦境／仙梦居」**。

1. 点击入梦，预览本关完整图片，再开始拼图。
2. 依次点击两块图片即可交换，拼回完整图像后自动提交，服务端验证并发放本关解梦奖励。
3. 经过原版解梦成功、图像演出和奖励流程后进入祝福页。
4. 从梦境好友列表选择 **1～2位离线NPC**，发送祝福。玩家领取一份本关自身祝福奖励，每位被选好友各收到一份对方奖励，然后进入下一梦。
5. 完成六关及各关祝福后，可查看仙梦居祝福；本期累计充值本金达到30元，领取造化神石×3，一期一次。

第六关奖励的传世金卡需在现有金卡系统中**实际兑现**后才计入充值；获得金卡本身不计费、不自动兑现。本地金卡兑现不发生真实支付。默认14天换期，入口显示本期剩余天数／小时，重新打开入口时更新。

**本次未重打、安装或覆盖现有 APK／v108 分发包。** 已安装独立离线APK内嵌的是旧服务端时，需要后续重新打包更新；仅重启旧APK不会获得工作区的新代码。模拟器原生验证使用隔离图层和临时数据，不改变玩家存档。

| 项目 | 已确认的原版事实 |
| --- | --- |
| 开放等级 | 手册明确18级；UI也读取服务端 `min_level` |
| 六梦名称 | 梦·相遇、梦·相识、梦·相知、梦·相恋、梦·相爱、梦·相守 |

| 充值相关 | 原客户端读取 `plus_data.min_charge/charge_prize`、`dream_data.can_take/take_charge` |

原协议只上传最终拼图排列，不上传初始随机盘、每步交换、时间或移动次数。当前保留这一契约，服务端验证正确排列及关卡状态；不宣称具备原协议之外的逐步操作反作弊能力，也不另造步数或倒计时惩罚。

### 2.1 六关解梦奖励 A

原表四元组是 **物件类别｜道具ID｜等级｜数量**。服务端内部统一为 `[类别, ID, 数量, 等级]`，转换后才发奖。

| 关卡 | 末版1263解梦奖励 | ID及关键等级 |
| --- | --- | --- |
| 1 相遇 | 包子×5、仙丹×5、超级召唤符×2 | 1022、1023、1007 |
| 2 相识 | **6级法宝灵石×1、7级武器灵石×1、7级防具灵石×1** | 1092／6级、1090／7级、1091／7级 |
| 3 相知 | 五法界魂箱×10、圣母蟠桃×10 | 1249、1343 |
| 4 相恋 | 五星灵器×3、太古水晶×5 | 1314、1323 |
| 5 相爱 | 猎魂宝箱×20、紫色精魄碎片×5 | 1325、10001 |
| 6 相守 | 传世金卡×1 | 1152 |

每关 `own_wish_prizes` 都是：**金丝乾坤袋1032×5、银绸乾坤袋1033×5、蟠桃1001×100**。

每关 `other_wish_prizes` 都是：**蟠桃1001×68**。

这三类奖励分别结算。拼图正确只发解梦奖励；发送祝福才发自身及好友奖励；充值领奖另有独立资格。第二关三颗灵石分别按6／7／7级落入背包，不把等级读成数量。

## 3. 缺失规则的补全 B

独立配置：[dream_rules.json](../server_config/dream_rules.json)，强制 `mode=inferred`。

| 项目 | 本次采用的规则 B及理由 |
| --- | --- |
| 开放与周期 | 常驻入口，每14天刷新；北京时间零点，以1970-01-05为锚点，与现有双周活动一致。原服具体排期缺失 |
| 当前一期示例 | 2026-10-26 00:00≤时间＜2026-11-09 00:00；下一期11月9日至23日 |
| 跨日 | 普通跨日不重置关卡、祝福或充值。避免每天重复刷出整套金卡及奖励 |
| 每关结算 | 解梦奖每关一次；本关必须先解梦、再祝福，祝福完成后进入下一关；第六关祝福后 `cur_dream=7`，不生成第七张图 |
| 自身祝福奖 | **每关一份**，选1位或2位好友收益相同，不按好友人数倍增 |
| 好友奖励 | 每位被选好友各得蟠桃×68，同次不可重复选同一好友 |
| 好友来源 | 从现有[玩家资料库](../analysis/npc_design/players/玩家资料目录.md)选择等级最接近的6位NPC，按角色ID打破同级并列；首次生成后本期固定 |
| 收祝福上限 | 每个NPC本期最多6份，本账号梦境内累计；不同关可祝福相同NPC。未冒充原服全服收件上限 |
| 到账方式 | `npc_balances`记录各NPC收到的物品余额，`receipts`保存本期关卡、目标、祝福语、时间和奖品；没有修改不可变NPC资料快照，也未冒充真实账号背包或邮件 |
| 社交边界 | 梦境名单只供梦境使用，不覆盖公共好友列表；不创建真实玩家关系，不自动回赠，不把NPC收到的蟠桃额外发给玩家 |
| 充值口径 | 接已有金卡系统的统一本金到账钩子；按现有10元宝本金＝1元计量，赠送元宝不计。期内入账可先于18级或首次进入梦境；历史充值不追补 |
| 本活动金卡 | 解梦获得1152只增加道具。实际兑现后按现有50元本金计入本期，因此六关奖励卡在期内兑现可满足最终领奖门槛；此资格认定属于B |
| 领奖资格 | 六次解梦和六次祝福完成、本期本金≥门槛且尚未领过，才能领取一次最终奖励 |
| 换期 | 清零关卡／祝福状态、当期收件数及记录、当期充值、最终领奖状态；重新生成期内好友。保留玩家已有背包、累计VIP充值和NPC已到账物品余额 |
| 时间回退 | 已登记梦境状态后，活动操作或充值时间早于最后处理时间时拒绝，不通过调时刷周期 |
| 旧请求 | 增补 `local_token`，每次成功解梦／祝福／最终领奖后更新。重启保留令牌；换期更换令牌；旧页面不能跨关、跨期结算 |

默认一整期完成六次祝福，共得自身祝福奖：金丝乾坤袋×30、银绸乾坤袋×30、蟠桃×600，另加表内六关解梦奖。选两位好友不会把这份收益翻倍；每位均收到全部六次祝福的NPC，其蟠桃余额增加408。

| 文件 | 作用 |
| --- | --- |
| [activity_dream.py](../network_redirect/activity_dream.py) | 原表解析、1325四操作、周期、状态、奖励、NPC账本、充值资格与校验 |
| [activity.py](../network_redirect/activity.py) | 注册1325；1205／事件47下发 `dream_data` 活动入口信息；启动校验梦境规则 |
| [feature_levels.py](../network_redirect/feature_levels.py) | 服务端18级门槛 |
| [recharge.py](../network_redirect/recharge.py) | 已验证金卡本金到账后累计本期梦境充值 |
| [dream_client.lua](../network_redirect/dream_client.lua) | 接原UI回调、末版奖表和NPC好友；修复原最终页资格参数与旧奖品文本；添加过期请求保护 |
| [summon.py](../network_redirect/summon.py)、[summon_client.js](../network_redirect/summon_client.js) | 原表专用覆盖、适配脚本加载和撤销 |

保存路径是每个角色JSON下的 `activity.dream`。关键字段：`start/end/last_time`、`cur_dream/status`、`charge_gold/take_charge`、`token`、`friends/received/receipts/npc_balances`。首次参与或本期首次充值时初始化；普通登录不发奖，不追补未参加的历史周期。不同本地账号的进度和NPC账本相互隔离。

原请求号、操作枚举和原业务字段保持；修改请求额外携带服务端颁发的 `local_token`。事件169返回完整 `dream_data/plus_data` 以及适配所用的 `local_rewards/local_friends/local_activity`。不接受客户端指定奖励、价格、进度、充值额或NPC余额。

每次业务沿用现有后端的独立角色副本：所有目标先校验，再结算，响应编码成功后保存。错误拼图、空／重复／越界好友、上限冲突、非法祝福语、未达充值资格、重复领奖及旧令牌均拒绝；不会部分发奖后跳关。相同连接内相同序列号重发复用原响应；跨连接仍以持久化状态和令牌防止重复结算。
