# 成就系统原版规则与修复说明

更新日期：2026-10-25。适用客户端：本仓库《金箍棒OL》3.87。

**【A】** 表示从原版客户端配置、协议和 LuaJIT 静态证据直接确认；**【B】** 表示缺失官方服务端源码、历史数据或配置后，为本地离线服务实现的推测规则。即使条件文字来自【A】，触发时机、历史补算、去重和服务器结算算法仍按【B】标注。

本次接通原版成就菜单、登录全量同步、本人/他人查询、实时完成通知、进度、重复次数、道行和持久化。276 条原表中，247 条开放、29 条关闭；205 条连接本地玩法结果或可证明的存档事实，42 条缺失上游结算使用显式模拟服务。模拟服务支持排行、连续上榜、关注关系、灵阵等语义事件，**并不代表联网跨服比赛或其他玩家真实行为已经实现**。关闭条目保持关闭。

## 【B】服务端补全规则

实现文件：[achievements.py](../network_redirect/achievements.py)、[backend.py](../network_redirect/backend.py)。配置文件：[achievement_rules.json](../server_config/achievement_rules.json)，明确标记 `mode=inferred`。

1. 达到 `full_progress` 算完成一次；不可重复条目最多一次。可重复条目按完整目标次数累加，正数 `max_repeatable_times` 是上限，0 表示没有原表业务上限；受原版 W 字段约束，本地最大表示 65535 次。非重复完成后的进度为完整目标；重复条目未封顶时显示余数，封顶后进度为完整目标。超额进度不再增加道行。
2. 道行＝`floor(固定道行总和 × (100 + 百分比道行总和) / 100)`。固定奖励及每档 VIP 的 10% 来自【A】，百分比相加、向下取整、全部历史固定道行参与加成是【B】。道行最大为有符号 I 的 2147483647。没有增加原表以外的初始道行；旧版本无来源的 `tao_point` 会以当前成就账本重算。
3. 401“一元复始”只要求所有**开放**的第一次成就完成；关闭条目不阻塞。缺失上游的第一次成就仍须提供真实本地结果或显式模拟，不能自动送全。
4. 时间按 UTC+8。登录天数按实际进入/重连的不同自然日累计；当日多次登录只算一天，不用签到次数替代，不虚构安装修复以前的登录天数。跨日持续在线而不重新登录不增加登录天数。
5. 422/423/446/447 以自然日为界，未完成进度日切归零，已完成永久保留。446 分别累计同一关卡，不能把多个关卡相加。456 以精英战斗成功结果累计，每五连胜算一次；失败清除未满五次的余数，保留已完成次数；不将扫荡当作连续手动胜利。
6. 424/425 在本地封神榜记录连续保持前十/第一的起点，满 86400 秒完成，跌出范围重新计时；离线期间本地榜单没有其他玩家争夺，因此按保存的本地名次延续，不声称还原真实线上防守。
7. 拥有、等级、首次通关类条件按角色存档补算：VIP、境界、神仙品质/飞升/转生档位、法术等级、装备品质/升阶、灵石、命星、精英星数、普通大关、九幽、洞府建筑/修炼/豪华度、灵兽等。物品/神仙/关卡各自保存最高已计入值，防止查询、卸下重装或降低再升高重复计入同一个“拥有/首次达到”里程碑。旧存档缺少物品 `attach_type` 时兼容旧版普通物品记录，不修改其原始字段。
8. 明确描述“某操作一次”的条目使用成功结算：参悟、飞升、转生、装备升星/封神、培养消耗、保存培养、传承、乾坤袋、密卷、祈福、喂包子、渡劫获书、仙盟捐献/购买/拦截等。失败、仅查询、放弃培养、缓存重放不增加完成次数。飞升次数按成功增加的飞升级数计算，回收后再次付费飞升仍可累计到原表上限。
9. 【B】具体补算解释：普通大关通关及全三星各按关卡组首次记录；225 按不同精英关卡首次三星计数；471 按九幽已击败的 boss 层数计数；239 的 10 飞不限制品质，240–243 限五星；灵兽品质 2/3/4 分别对应无暇/完美/传说；灵石 11/12 级对应封神/提炼；装备铸造 4 级作为鸿蒙档。紫书以本地取经书等级 ≥4 解释；128 在发车时计入，232 在到达后完成结算时计入。以上映射均不冒充官方服务端结算。
10. 战报及本人取经信息使用真实成就道行，不再使用固定 0 或以战斗力代替。成就与背包、货币放在同一角色 JSON 和同一次 SQLite 提交里；在提交前验证协议可编码。玩法已有的请求序列缓存保证重复请求返回同一结果而不再结算。1067 只查询，不接受任何客户端传来的成就 ID、次数或道行；未知目标返回原版提示事件。跨服 flag 使用本地已存在角色作为模拟目标，不凭空复制本人进度。原库若存在重复角色 ID，非本人查询会拒绝歧义目标。

## 【B】缺失服务的完整模拟路径

42 条缺失上游规则不会靠登录自动完成，也不会把虚构排行展示成真实结果。它们接入 `simulate_fact`，以确定的上游事实替代缺失服务，再走同一个进度、封顶、道行、存档和查询流程。

| 上游事件 | value | 成就与处理 |
| --- | --- | --- |
| `tian_yuan` / `revive` / `book_stolen` | 正整数次数 | 106 / 119 / 120 |
| `craft_exchange` / `cross_participation` / `treasure_trip` | 正整数次数 | 125 / 134 / 139 |
| `party_lucky` | 正整数次数 | 320 |
| `duty_rank` | 0 未上榜；正整数名次 | 216、217；431–439 连续上榜；同一天重复结算不增加天数，断日或未上榜清零未达目标进度，已完成项不回收 |
| `party_daily_rank` / `party_week_rank` | 0 或正整数名次 | 218、219 / 220、221 |
| `cross_rank` | 0 或正整数名次 | 前 3/20/50 对应 236/237/238 |
| `follow` / `follower` | 正整数目标角色 ID | 去重后的关注/被关注人数触发 302、303 / 304、305 |
| `fortune` | 323、324、325、326 之一 | 显式模拟对应禄星结果，不能输入其他成就编号 |
| `feed_rank` | 0 或正整数名次 | 445 |
| `spirit_array` | `{"stage":1..6,"level":正整数}` | 激活本阶及之前阶；四象、六合达到配置满级分别触发 465/562 |

【B】模拟榜单容量默认 100，位于 JSON 配置。2026-10-26补正：【A】灵阵每个阵位技能满级为5，已按原版客户端修正模拟上限，并接入真实激活及四象/六合全阵位满级结算，详见[灵阵系统原版规则与修复说明](灵阵系统原版规则与修复说明.md)。`spirit_array` 的高阶视为低阶已激活；只在显式提供四象/六合满级事实时结算各自满级条目。

模拟凭据 `receipt` 持久保存；完全相同的凭据及内容重复提交无效果，换内容复用凭据会拒绝。语义事件与按 ID 的管理员结算都写入带 `source=B` 的审计日志。该接口不暴露为游戏网络消息。

可执行入口：[simulate_achievements.py](../simulate_achievements.py)。先准备 JSON 文件，例如：

```json
[
  {"event":"cross_participation","value":1,"receipt":"offline-cross-season-1-join"},
  {"event":"cross_rank","value":3,"receipt":"offline-cross-season-1-final"},
  {"event":"spirit_array","value":{"stage":4,"level":10},"receipt":"offline-array-4-max"}
]
```

```sh
# directory 必须是已有 game.sqlite3 的目录；account 必须是已有账号。
.runtime/venv/bin/python simulate_achievements.py --directory /你的存档目录 --account local-player --events /tmp/achievement-events.json
# 审阅预览结果后应用到指定本地存档：
.runtime/venv/bin/python simulate_achievements.py --directory /你的存档目录 --account local-player --events /tmp/achievement-events.json --apply
```

默认预览使用只读 SQLite，不创建账号、不迁移存档。`--apply` 会获取数据库写锁并比较预览时读取的角色数据，冲突时拒绝覆盖；一个批次全部成功才提交。应用后重新登录即可收到更新。还支持管理员明确确认的结算凭据 `{"id":459,"amount":1,"receipt":"unique-settlement"}`，其中 amount 是进度单位，不是直接指定最终完成次数；这属于显式模拟结算而非条件验证，正常游戏不调用。
