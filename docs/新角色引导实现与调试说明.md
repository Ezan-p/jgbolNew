# 新角色引导实现与调试说明

本次将原版 3.87 的新角色引导接入本地账号服务：新注册、未继承旧档的账号，从原版开场、命名和头像选择进入教学；服务端处理原版 `1204 msg_new_role_guide`，保存阶段并返回原客户端认识的数据与回调。无需新增客户端界面或重新打包 APK。

## 生效范围与使用

1. 重启本地离线服务，使用现有本地客户端登录。
2. 注册一个新账号，**不要选择继承旧存档**。
3. 按原版界面完成开场、命名、初始选将、战斗、召唤、上阵、装备和任务领取。
4. 中途退出后重新登录，客户端根据 `1017.guide_progress` 恢复到下一个未完成阶段。

已有账号不清零进度，不删除伙伴、装备或货币。继承旧存档的账号沿用旧档进度。历史调试账号 `local-player` 继续使用跳过引导、初始伙伴 5004 的兼容行为；实际本地注册账号没有这项例外。测试时应新建账号，不能通过只清空旧档的进度位来重放发奖流程。

## 原版依据与离线补齐边界

本文【A】表示直接来自原包的协议、配置或客户端逻辑；【B】表示原服务端缺失后采用的离线实现，不表示已还原官方服务端数值。

| 内容 | 依据与实现 |
| --- | --- |
| 【A】请求 | `1204`：`serial_num=I,stage=B,head_type=I,name=s`。`name` 根据阶段承载姓名、选将序号或对象 ID 字符串。 |
| 【A】阶段表 | [guide_schedule.csv](../analysis/configs/guide_schedule.csv)，阶段 1～13，以及 21～30 的活动引导。 |
| 【A】进度位 | `guideUI.getBitInGuideIndex` 先按低位展开，再删除第一个元素。因此阶段 n 对应 `1 << n`，不是 `1 << (n-1)`。 |
| 【A】初始选将 | `guideUI.startChat` 的 `one=4061`、`two=4053`；请求 `name` 为 `"1"` 或 `"2"`。 |
| 【A】教学关卡 | 原版 `guideUI.getFightNpc` 对应 101、102、102、103、104、105，第二场与第三场使用同一关。 |
| 【A】成功回调 | `2998` 的事件 35，由 `event_mgr` 调用 `guideUI.guideSucceed`。命名成功省略 `result`；失败返回原命名错误码。 |
| 【A】教学战报 | `1028` 阵容、`1027` 战报，教学旅途 `fight_type=7`，携带 `guide_stage`；事件 44 启动回放。 |
| 【A】教学装备 | 103 关首胜表固定掉落 2041；复用旅途首胜结算，不额外重复赠送。 |
| 【A／B】任务奖励 | `task_guide_prize.csv` 的首个 Boss 三星目标为 20 元宝；本实现将阶段 13 作为这笔引导奖励的一次性领取点，该绑定为【B】。 |
| 【B】第二次召唤 | 固定获得初始二选一中未选择的另一位；原服务端保底池、冷却和概率未恢复。回调 `left_time=0`。 |
| 【B】教学战斗 | 第二场演示失败，其余场演示胜利。失败侧的战斗临时属性设为 1，仍运行现有战斗引擎生成完整动作，不改永久养成属性。不是官方教学战报或官方敌方数值。 |
| 【B】教学结算 | 复用当前旅途体力、经验、银两、首胜装备和升级奖励规则；这些服务端规则本身的证据边界见旅途与升级文档。 |
| 【B】初始资源／名字规则 | 沿用当前离线初始资源和 `profile_rules.json` 的中文姓名长度、屏蔽词规则；初次命名免费。 |
| 【B】指定操作 | 第二位神仙放入阵位 2，教学装备穿到阵位 1；对象必须真实属于当前角色。 |

原包反汇编证据：

阶段 1 完成后 `guide_progress=2`；1～13 全部完成为 `16382（0x3ffe）`。14～20 没有阶段，不填造完成事件。客户端发现第一个未完成位超过 13 后退出强制引导，并独立解析活动引导位。

后续“新手天书”14项目标现已单独接通，教学首奖与天书共用持久化领取位，见[新手天书实现与调试说明](新手天书实现与调试说明.md)。本次也未声称恢复旧版本可能存在的活动专用教学战报。

## 代码与响应顺序

- [new_role_guide.py](../network_redirect/new_role_guide.py)：读取原阶段表，前置验证、名字／头像／对象检查、选将、穿装、教学战斗、奖励及进度属性包。
- [backend.py](../network_redirect/backend.py)：新账号以空伙伴列表、进度 0 创建；接收 `1204`；编码响应后保存；管理会话重放和登录时清理缓存。
- [monument.py](../network_redirect/monument.py)、[activity_rank.py](../network_redirect/activity_rank.py)、[activity_arena.py](../network_redirect/activity_arena.py)：兼容未选将的空阵容。头像展示暂用 4061，不向角色发放该伙伴。

每步先在内存中的独立角色对象结算；伙伴／物品变化、背包、地图、资源和 `1032` 属性更新先于教学回调发送。主角属性 9 为 `guide_progress`，属性 29 为头像。升级通知使用已有升级模块。战斗的事件 44 放在本次业务事件末尾，使原回放开始时数据已经更新。

`1017` 仍负责登录／重连快照，不在每步中重造主界面。断线后的新登录清空会话响应缓存，持久化进度继续保留。

## 防重复和失败回滚

- 未知 stage、缺少前置、已完成 stage 不执行奖励。
- 同一会话内，相同非零 `serial_num` 和完全相同请求直接返回缓存响应。
- 使用新的序号重复已完成阶段也不能再抽将、发奖或结算战斗。
- 过期序号或同序号改写请求被拒绝。缓存最多 256 条，重新登录清空。
- 原版活动入口允许序号 0；这类请求仍受持久化阶段位保护。
- `name` 中传入的伙伴／装备 ID 只查本角色存档，不接受任意伙伴类型、跨账号对象或客户端奖励金额。
- 结算或响应编码失败不会提交本次角色修改。名字错误保留阶段 1，并返回原命名错误码供输入界面重试。

注意：断线恢复依靠阶段快照继续下一步，不会重新播放已经提交的战斗。原版教学并非可重复领取的活动。

## 调试定位

- 不出现引导：确认账号是新注册且未继承旧档；旧账号的 `0x7fffffff` 不会自动重置。
- 命名无响应：检查姓名符合本地规则、头像为 `101～104／201～204`，以及事件 35 是否送达。
- 返回前置错误：比对阶段表和进度位；不要把阶段号当作进度整数直接写入。
- 教学战斗不播放：核查 `1028 → 1027(fight_type=7, guide_stage=当前阶段) → 事件44`，并确认前置伙伴／物品数据已更新。
- “数据无效”：查服务端 `game_guide_rejected` 中的阶段和错误详情。成功处理记录 `game_guide_ok`；命名校验失败也可能完成请求处理，判断实际进度应以存档和事件内容为准。
- 原生验证找不到设备：先启动配置中的模拟器和游戏；测试脚本需要可访问 ADB／Frida，沙箱限制下应使用允许本地设备连接的执行环境。
