# 神石高阶提炼修复说明

更新日期：2026-10-31。

**已修复截图中的12→13级提炼报“灵石升华或提炼等级无效”，同时补齐13→14级提炼。** 三类石头使用已打包1263热更新资源中的真实配方和属性系数，最高14级。

## 3. 具体修改

- [equipment.py](../network_redirect/equipment.py)：改读独立保存的[1263高阶灵石表](../analysis/configs/stone/stone_reborn_cost_worth.csv)，以该表确定上限和下一级配方；配方与属性共用同一份数据。基础3.87表保留不改。
- 所有11级以上的提炼统一校验四重境界；参数错误、未达10级、已到上限和配置缺失分别提示，避免再次把不同原因合并为“等级无效”。
- [equipment_client.lua](../network_redirect/equipment_client.lua)：仅接管13级入口，保留神石权益和四重境界检查，再调用原生 `showTilian()`；其他等级继续走原入口。目标对象不改等级、不换ID。补丁支持重复注入和恢复。
- APK仅更换 `assets/offline/program.zip` 与其校验属性；引擎、Java启动代码、运行时、视频、热更新资源及存档路径均保持各自原版。

没有强改存档等级、补发材料、重建账号或追扣已有物品，不需要数据库迁移。

## 6. 14→15及更高等级专项核查（2026-10-31）

**当前项目所持资源和两个修复APK均以14级为上限，不存在14→15、15→16或更高等级的提炼配方。** 这与之前12→13的故障不同：之前客户端已有配方而服务端漏接；15级及以上连当前客户端的目标配方、属性系数和专用命名分支都不存在。

| 阶段 | 当前资源 | 修复后行为 |
|---|---|---|
| 12→13 | 有三类配方、系数和命名分支 | 已接通 |
| 13→14 | 有三类配方、系数和命名分支 | 已接通，并补齐原入口限制 |
| 14→15 | 无15级目标配方和系数 | 到达上限，不扣材料 |
| 15→16及以后 | 无对应目标配方和系数 | 不支持；不能按上一档自行外推 |

14级最终单孔系数为武器攻击500%、防具防御500%、法宝生命600%。这些是装备基数加成，不能视为角色最终属性直接增加五倍／六倍。

### 资源核查范围

- 分别解开正式版、测试版修复APK内的 `program.zip`，通过实际 `release_w/index.txt` 解析1263覆盖资源，确认高阶表的三种类型都只有11、12、13、14四档，服务端表与之相符。
- 检查 `.runtime/release_w` 与冻结构建快照 `device-release_w`：各57份现存索引（包含与版本索引重复的当前 `index.txt`），涉及1206～1263范围内实际保留的版本，并非该区间每个版本都存在。所有灵石表引用均可解析，没有未找到的表文件。
- 上述两套快照均只引用两种高阶表：基础表最高12级，扩展表最高14级。另核对基础包两份1205索引，其表最高12级。这些快照存在内容重复，不能当成116个独立版本。
- `data.lua` 的高阶命名逻辑在12、13、14级分别使用 `stone_tilianName`、`stone_tilianNameB`、`stone_tilianNameC`；没有15级专用分支。名称函数对未识别等级的回退不能证明该等级可养成。
- 当前客户端上限提示 `stoneCast4` 的原文为“神石已达到最高等级”。修复补丁仅接管13级入口，14级及更高等级仍进入原生上限保护。

这一结论限定于**当前项目、本地保留资源和已生成安装包**；没有取得1263之后的新资源，不能据此断言其他未提供的原服版本永远没有更高等级。

### 边界实测

1. **服务端15个协议场景通过**：三种石头各测试14级背包目标、14级已镶嵌目标，以及人为构造的15、16、20级空闲目标。均返回事件55“灵石已达到提炼上限”，操作前后完整角色保存状态相同。
2. **原生客户端12个场景通过**：三种石头各测试14、15、16、20级的入口，均提示“神石已达到最高等级”，发包次数为0，未打开新的提炼窗口；测试结束恢复临时替换的函数。
3. 15／16／20级是专门用于验证异常边界的临时测试对象，不是游戏当前可获得或可正常镶嵌的等级。本次没有修改玩家存档、游戏逻辑或安装包。
